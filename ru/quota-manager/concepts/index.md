С помощью API {{ quota-manager-name }} можно отслеживать значения и потребление квот и настроить оповещения о достижении пороговых значений. Это поможет вовремя запросить увеличение квот или предотвратить перерасход ресурсов.

## Выделение квот {#quotas-allocation}

При создании облака автоматически устанавливаются значения квот по умолчанию. После изменения квоты сброс к начальному значению не предусмотрен.

Для некоторых ресурсов значение квоты не устанавливается. В консоли для таких ресурсов отображается **{{ ui-key.yacloud.iam.cloud.quotas.label_quota-empty }}**.

Квоты можно увеличить по запросу в пределах лимитов — технических ограничений платформы. Выделенные квоты не гарантируют наличие свободных ресурсов.

Управление квотами через CLI и API выполняется по идентификатору квоты, который имеет вид `<имя_сервиса>.<имя_ресурса>.<единица_измерения>`. Например: `dns.zones.count`, `serverless.networkPackets.rate`, `mdb.memory.size`. 

Идентификаторы квот и их значения по умолчанию для поддерживаемых сервисов {{ yandex-cloud }} приведены в разделе [{#T}](../all-quotas.md).

Потребление квот можно узнать в консоли на странице сервиса [{{ quota-manager-name }}]({{ link-console-quotas }}) или с помощью [запроса API](../operations/list-quotas.md).

## Зачем нужны квоты {#quotas-need}

Квоты помогают контролировать потребление облачных сервисов. Например, они не позволяют новым пользователям занять слишком много ресурсов при тестировании.

## Типы ресурсов {#resources-types}

Квоты в {{ yandex-cloud }} привязаны к ресурсам. При выполнении команды CLI или запроса API укажите тип ресурса:

* `resource-manager.cloud` — [облако](../../resource-manager/concepts/resources-hierarchy.md#cloud);
* `organization-manager.organization` — [организация](../../organization/concepts/organization.md);
* `billing.account` — [платежный аккаунт](../../billing/concepts/billing-account.md).
