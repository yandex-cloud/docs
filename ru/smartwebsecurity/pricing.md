## Из чего складывается стоимость использования {{ sws-name }} {#rules}

Стоимость зависит от способа тарификации:

* [По подписке](#subscription) — подходит для больших объемов входящего трафика.
  
* [По количеству запросов](#requests) — подходит для небольшого объема входящего трафика.

Оба способа учитывают количество запросов по всем [облакам](../resource-manager/concepts/resources-hierarchy.md#cloud), привязанным к одному [платежному аккаунту](../billing/concepts/billing-account.md).

При расчете стоимости обработки запросов учитываются только [легитимные запросы](concepts/rules.md#rule-action). Это запросы, которые были разрешены всеми правилами и пропущены к защищаемому ресурсу.

При этом есть особенности тарификации в режиме Dry run:

* В режиме Dry run правила не блокируют запросы. Если запрос достиг защищаемого ресурса, он учитывается в потреблении, даже если без режима Dry run был бы заблокирован.

* Если режим Dry run был установлен только для одного типа правил (например, правил профиля безопасности), а запрос заблокирован правилом WAF или ARL без режима Dry run, такой запрос не учитывается в потреблении.

Обработка запроса правилами профиля ARL отдельно не тарифицируется. Заблокированные запросы не учитываются при расчете стоимости обработки запросов независимо от того, на каком этапе и каким правилом они были заблокированы.

При использовании прокси-сервера отдельно оплачивается Network Protection. В расчет входит входящий трафик, пропущенный Network Protection, в том числе трафик запросов, которые затем были заблокированы на уровне L7. Правила расчета в разделе [Network Protection](#network-protection).

При использовании [доменов](concepts/domain-protect.md) дополнительно к стоимости обработанных запросов [взимается плата](#proxy-resources) за вычислительные ресурсы прокси-сервера. Защиту доменов можно включить только при тарификации по количеству запросов — в подписку она не включена.

#### Ресурсы прокси-сервера {#proxy-resources}

При использовании доменов вы платите за фактическое использование вычислительных ресурсов каждого активного прокси-сервера.

При активации защиты домена автоматически резервируется минимальный объем ресурсов прокси-сервера — 6 [ресурсных единиц](../application-load-balancer/concepts/application-load-balancer.md#lcu-scaling), по 2 в каждой зоне доступности. Их тарификация начинается сразу, независимо от того, получает ли домен трафик.

Ресурсная единица — это внутренняя виртуальная машина, которая создается для работы прокси-сервера в зоне доступности.

Одна ресурсная единица рассчитана на следующие максимальные показатели (пороговые значения для автоматического масштабирования):

* 1000 запросов в секунду (RPS);
* 4000 одновременно активных соединений;
* 300 новых соединений в секунду;
* 22 МБ (176 Мбит) трафика в секунду (учитывается входящий и исходящий трафик).

Группа ресурсных единиц автоматически масштабируется в зависимости от внешней нагрузки на узлы прокси-сервера. Размер группы вычисляется таким образом, чтобы на каждую единицу приходилась нагрузка, не превышающая пороговых значений.

Минимальное количество ресурсных единиц по умолчанию — 6, его можно увеличить по запросу.

Тарификация за использование прокси-сервера почасовая. Плата берется за минимальное количество ресурсных единиц, работавших в течение часа.

Приложения, подключенные к прокси-серверу, дополнительно защищаются от DDoS-атак на уровнях L3–L4 с помощью [Network Protection](concepts/network-protection.md), которая [оплачивается отдельно](#network-protection).

Стоимость рассчитывается отдельно для каждого прокси-сервера. Цена за 1 Мбит/с одинакова при любом объеме полосы. Минимальной платы, минимальной оплачиваемой полосы и минимального срока использования нет.

Вычислительные ресурсы прокси-сервера, обработка запросов правилами профиля безопасности и Cloud WAF оплачиваются отдельно, даже когда Network Protection не тарифицируется.

##### Какой трафик учитывается {#network-protection-traffic}

В расчет входит очищенный входящий трафик: данные, которые узлы очистки Network Protection пропустили к прокси-серверу по всем портам его адреса. Если этот трафик затем заблокирован на уровне L7, он все равно учитывается в стоимости Network Protection.

Трафик, отброшенный Network Protection, и исходящие ответы ресурса клиентам не учитываются. Если за весь расчетный период учтенного входящего трафика не было, Network Protection не тарифицируется.

##### Как рассчитывается стоимость за месяц {#network-protection-formula}

Для каждого прокси-сервера определяются два показателя за время подключения к защите:

- **p95** — 95-й перцентиль средних скоростей входящего трафика за пятиминутные интервалы, в Мбит/с. Этот показатель снижает влияние коротких пиков нагрузки.
- **Средняя скорость** — общий объем учтенного входящего трафика, разделенный на длительность подключения к защите, с приведением к Мбит/с. В объем входят и короткие пики.

Тарифицируемая полоса равна большему из этих двух значений. Поэтому короткие пики могут увеличить стоимость через среднюю скорость, даже если значение p95 не изменилось.


**Стоимость за месяц = тариф × max(p95, средняя скорость) × T / M**.



Здесь `T` — суммарная длительность всех интервалов подключения прокси-сервера к защите в расчетном месяце, включая интервалы без трафика. `M` — длительность полного календарного месяца. Для отношения `T / M` используются одинаковые единицы времени.

Расчетный месяц начинается 1 числа в 00:00 UTC+3. Если защита подключена на часть месяца, стоимость рассчитывается пропорционально длительности подключения. При отсутствии подключения стоимость равна нулю.

##### Период защиты и остановка прокси-сервера {#network-protection-period}

Network Protection включается автоматически при создании прокси-сервера. Удаление прокси-сервера завершает период защиты.

Остановка прокси-сервера сохраняет защиту его адреса и не завершает период расчета. Пятиминутные интервалы без трафика учитываются с нулевой скоростью. После повторного запуска того же прокси-сервера накопленная статистика месяца сохраняется.

Интервалы с нулевой скоростью учитываются при расчете средней скорости и p95 и входят в длительность подключения к защите. Поэтому остановка ресурса не гарантирует пропорционального уменьшения стоимости, результат зависит от трафика за весь период подключения в месяце.

Новый прокси-сервер учитывается отдельно. Если прежний прокси-сервер остановлен, но не удален, расчет для него продолжается по общей формуле. Итоговая стоимость складывается из начислений по обоим ресурсам.

##### Начисления и просмотр трафика {#network-protection-billing}

В течение месяца в биллинге отображается накопленное начисление за учтенное потребление. При изменении нагрузки сумма может увеличиваться неравномерно. Она не является прогнозом стоимости полного месяца. Итоговая стоимость рассчитывается после окончания месяца по формуле выше.

Начисления можно посмотреть в разделе **Детализация** сервиса {{ billing-name }}. Подробнее — в [инструкции по просмотру детализации](../billing/operations/check-charges.md).

Для самостоятельной проверки итогового расчета используйте данные о пропущенном входящем трафике Network Protection в {{ monium-full-name }} за тот же прокси-сервер и завершенный расчетный месяц. Порядок просмотра описан в [инструкции по мониторингу](operations/monitoring.md).
