# Управление доступом к {{ datalens-platform-full-name }}

## Права доступа {#access-rights}

Доступ в {{ datalens-platform-short-name }} регулируется правами:

* **Права для доступа к сервису** — определяют, кто имеет доступ к интерфейсу {{ datalens-platform-short-name }} и какие операции с метаданными будут доступны пользователям.

   Для доступа к сервису пользователю нужно назначить одно из прав: `Посещение` или `Администрирование`. Выдача прав для работы с метаданными (`Использование метаданных`, `Управление разметкой метаданных` и др.) опциональна.

   Права для доступа к сервису можно [назначать]({{ link-docs }}/organization/operations/add-role) в интерфейсе {{ org-full-name }} (например, для администратора, который настраивает экземпляр), однако рекомендуемый способ — в [интерфейсе {{ datalens-platform-short-name }}](manage-access.md#service-access) (для всех остальных пользователей).

* **Права для доступа к отдельным объектам** — определяют уровень доступа к конкретному объекту, например коллекции, воркбуку или REST-каталогу (`Ограниченный просмотр`, `Просмотр`, `Редактирование`, `Администрирование`, и др.). Такие права [выдаются на конкретный объект](manage-access.md#set-access), и они наследуются вложенными объектами.
   
   Если у пользователя отозвать право доступа к сервису (`Посещение` или `Администрирование`), то настроенные права для доступа к объектам сохранятся, но перестанут действовать, поскольку пользователь не сможет попасть в интерфейс {{ datalens-platform-short-name }}.

Описания всех прав доступа собраны в разделе [{#T}](roles.md).

О том, как выдать доступ к сервису и объектам, а также как обработать запросы доступа, читайте в разделе [{#T}](manage-access.md).

## Организация и экземпляр {#org-tennant}

Для работы {{ datalens-platform-short-name }} требуется [организация]({{ link-docs }}/organization/concepts/organization.md) {{ org-full-name }}. Действует ограничение: в рамках одной организации можно создать только один экземпляр {{ datalens-platform-short-name }}.

Если вы создаете {{ datalens-platform-short-name }} с нуля, то организация будет создана автоматически при [активации платформы](../quickstart.md#activate-service). При настройке прав доступа роли пользователям назначаются на уровне экземпляра.

Если вы мигрируете в {{ datalens-platform-short-name }} из {{ datalens-name }}, то будет использована та же организация, что и в экземпляре {{ datalens-name }}. Экземпляр {{ datalens-name }} будет полностью заменен на экземпляр {{ datalens-platform-short-name }}, это действие необратимо. Поскольку роли в {{ datalens-name }} назначаются на уровне организации, то при миграции это сохранится. Но все новые роли в {{ datalens-platform-short-name }} мы рекомендуем назначать уже на уровне экземпляра, и мигрированные роли также постепено заменять на роли на уровне экземпляра.
