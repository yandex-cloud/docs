# Разграничение зон контроля пользователей {{ maf-full-name }} и {{ yandex-cloud }}

При работе с сервисом {{ maf-full-name }} необходимо учитывать, что контролирует [{{ yandex-cloud }}](#cloud-responsibilities) как облачный провайдер, а что — [клиент {{ yandex-cloud }}](#customer-responsibilities). Понимание этих зон контроля помогает эффективно использовать возможности сервиса и корректно взаимодействовать с технической поддержкой.

Техническая поддержка {{ yandex-cloud }} обрабатывает обращения, связанные с проблемами в зоне контроля {{ yandex-cloud }}. Запросы на отладку проблем в зоне контроля клиента выходят за рамки поддержки, оказываемой {{ yandex-cloud }}.

## Архитектура сервиса {#architecture}

Каждый [кластер {{ AF }}](../../managed-airflow/concepts/index.md#cluster) запускается в отдельной группе узлов {{ managed-k8s-full-name }}, которая изолирована от других кластеров средствами виртуальных сетей и самого {{ k8s }}. Группы узлов управляются общим {{ k8s }}-мастером под управлением {{ yandex-cloud }}.

Для хранения метаданных {{ AF }} используется общий кластер {{ PG }} под управлением {{ yandex-cloud }}. Доступ к нему ограничен.

## Зона контроля {{ yandex-cloud }} {#cloud-responsibilities}

* **Физическая и виртуальная инфраструктура**. Обеспечение работоспособности физических серверов, виртуальных машин, дисков и сетевой связности, на которых функционируют компоненты сервиса.

* **{{ k8s }}-инфраструктура**. Обеспечение работоспособности общего {{ k8s }}-мастера и сетевой инфраструктуры групп узлов: виртуальной сети, группы безопасности и сервисного аккаунта. Изоляция групп узлов между кластерами.

* **Управляемый кластер {{ PG }} для метаданных**. Обеспечение работоспособности, доступности и резервного копирования общего кластера {{ PG }}, который используется для хранения метаданных {{ AF }}.

* **Компоненты {{ AF }} под управлением {{ yandex-cloud }}**. Обеспечение работоспособности основных [компонентов {{ AF }}](../../managed-airflow/concepts/index.md#components):

  * веб-сервера;
  * планировщика;
  * DAG-процессора;
  * воркеров;
  * Triggerer.

* **Резервное копирование и восстановление**. Обеспечение резервного копирования и восстановления базы метаданных кластера {{ AF }}. Восстановление из резервной копии не гарантируется, если проблема связана с ошибкой на стороне поставщика компонента или архитектурными особенностями данных. Техническая поддержка {{ yandex-cloud }} объяснит причину проблемы и возможные способы ее предотвращения в будущем.

* **Кластерные операции**. Обеспечение выполнения операций с кластером через доступные облачные интерфейсы: создание, изменение, масштабирование, обновление и удаление кластера, а также изменение конфигурации компонентов.

* **Хранилище DAG-файлов**. Обеспечение работоспособности интеграции между кластером {{ AF }} и {{ objstorage-full-name }} на платформенном уровне.

* **Мониторинг и логирование платформенного уровня**. Предоставление метрик работоспособности компонентов {{ AF }} через {{ monitoring-full-name }}. Предоставление платформенных логов компонентов {{ AF }} через {{ cloud-logging-full-name }}.

* **Обслуживание и обновления**. Применение обновлений безопасности для компонентов платформы и гостевой ОС узлов. Применение оптимальных настроек по умолчанию при создании новых кластеров и обновлении версии {{ AF }}.

* **Интеграция с сервисами {{ yandex-cloud }}**. Обеспечение платформенной интеграции с сервисами {{ yandex-cloud }}:

  * {{ objstorage-full-name }} — хранение DAG-файлов и логов задач;
  * {{ iam-full-name }} — управление доступом к сервису на уровне платформы;
  * {{ vpc-full-name }} — сетевая изоляция кластера;
  * {{ lockbox-full-name }} — хранение секретов, Connections и Variables;
  * {{ cloud-logging-full-name }} и {{ monitoring-full-name }} — сбор платформенных логов и метрик.

* **Пользовательская документация**. Разработка и актуализация документации по эксплуатации {{ maf-full-name }}. Документация самого {{ AF }} является зоной ответственности проекта Apache Software Foundation.

## Зона контроля клиентов {{ yandex-cloud }} {#customer-responsibilities}

* **Написание DAG-файлов**. Разработка, тестирование, отладка и оптимизация DAG-файлов и операторов {{ AF }}.

* **Логика задач**. Обеспечение корректности бизнес-логики внутри операторов, хуков и сенсоров.

* **Зависимости Python**. Управление пользовательскими Python-библиотеками, устанавливаемыми в кластер. Клиент отвечает за совместимость библиотек с версией Python и {{ AF }}, которые предоставляет сервис, а также за совместимость библиотек между собой.

  Версия Python фиксируется версией {{ AF }}, поставляемой {{ yandex-cloud }}, и может измениться при обновлении кластера. Клиент отвечает за проверку совместимости пользовательских библиотек с новой версией Python и {{ AF }} после обновления. {{ yandex-cloud }} не гарантирует работоспособность пользовательских библиотек с какой-либо конкретной версией Python или {{ AF }}.

* **Диагностика Task Instance**. Анализ статусов выполнения задач, изучение логов задач и диагностика причин сбоев на уровне кода задачи.

* **Планирование расписания**. Корректная настройка параметров расписания DAG: `schedule_interval`, `start_date`, `catchup`, `max_active_runs` и других.

* **Производительность DAG**. Оптимизация DAG с точки зрения количества задач, параллелизма и времени выполнения. Предотвращение перегрузки планировщика, DAG-процессора и пула воркеров.

* **Хранилище DAG-файлов в {{ objstorage-full-name }}**. Загрузка, версионирование и управление DAG-файлами в бакете {{ objstorage-full-name }}. Настройка и эксплуатация CI/CD-пайплайнов для доставки DAG-файлов в бакет. Обеспечение корректных прав доступа сервисного аккаунта кластера к бакету.

* **Использование {{ GL }} в качестве хранилища DAG-файлов**. Обеспечение работоспособности {{ GL }}. Платформенные ошибки {{ maf-full-name }} при работе с {{ GL }} относятся к зоне контроля {{ yandex-cloud }}.

* **Ресурсы кластера**. Обеспечение соответствия конфигурации кластера фактической нагрузке: выбор типа ресурсов, количества экземпляров компонентов, минимального и максимального количества воркеров.

* **Параметры {{ AF }}**. Настройка параметров конфигурации {{ AF }}, доступных клиенту. Клиент отвечает за последствия отклонения от рекомендуемых значений по умолчанию.

* **Окно технического обслуживания**. Назначение временного окна для проведения технического обслуживания кластера.

* **Connections и Variables**. Создание, настройка и поддержание актуальности Connections и Variables {{ AF }}. Настройка интеграции с {{ lockbox-full-name }} или другими бэкендами для хранения секретов. Управление жизненным циклом секретов.

* **Управление доступом**. Настройка ролей и сервисных аккаунтов для доступа к {{ AF }}.

* **Мониторинг и реакция на события**. Анализ метрик работоспособности кластера и своевременная реакция на алерты. Настройка дополнительных алертов для метрик пользовательских задач и DAG. Анализ логов задач, доступных через веб-интерфейс {{ AF }} и {{ cloud-logging-full-name }}.

* **Внешние системы**. Обеспечение доступности и корректной работы внешних систем, с которыми взаимодействуют задачи {{ AF }}.

* **Сетевая связность с внешними системами**. Настройка групп безопасности, маршрутизации и NAT для доступа кластера к целевым внешним ресурсам.

* **Стороннее ПО**. Настройка и эксплуатация инструментов CI/CD для развертывания DAG и сторонних систем мониторинга.

* **Обновление версий**. Подготовка к обновлению версии {{ AF }} после получения оповещения или ознакомления с [политикой работы с версиями {{ AF }}](../../managed-airflow/concepts/update-policy.md): анализ истории изменений, проверка совместимости DAG, операторов и зависимостей с целевой версией.

  Клиент отвечает за проверку совместимости пользовательских Python-библиотек с версией Python и {{ AF }}, поставляемыми в новой версии кластера, до и после обновления. Обновление или замена библиотек, несовместимых с новой версией, также является ответственностью клиента.

* **Тестирование перед обновлением production-кластера**. Тестирование DAG на новой версии {{ AF }} до применения обновления в production-кластере.

* **Работа на неактуальной версии {{ AF }}**. Решение проблем эксплуатации, связанных с использованием неактуальной версии {{ AF }} по истечении сроков поддержки, установленных {{ yandex-cloud }}.

## Типичные сценарии {#scenarios}

| Сценарий | Зона контроля |
| --- | --- |
| Веб-сервер {{ AF }} недоступен, веб-интерфейс не открывается | {{ yandex-cloud }} |
| Task Instance завершился с ошибкой в пользовательском коде | Клиент |
| DAG-процессор не обрабатывает DAG из-за платформенной ошибки | {{ yandex-cloud }} |
| DAG-процессор не обрабатывает DAG из-за синтаксической ошибки в DAG-файле | Клиент |
| Планировщик не запускает задачи из-за некорректного `schedule_interval` или `start_date` | Клиент |
| KEDA не масштабирует воркеры из-за платформенной ошибки | {{ yandex-cloud }} |
| Ошибка кластерной операции, например создания или масштабирования через API | {{ yandex-cloud }} |
| Ошибка подключения к внешней БД из задачи {{ AF }} | Клиент |
| DAG-файл не загружен в бакет {{ objstorage-full-name }} | Клиент |
| Некорректная работа встроенной интеграции с {{ lockbox-full-name }} | {{ yandex-cloud }} |
| Несовместимость пользовательских Python-библиотек с текущей версией {{ AF }} или Python | Клиент |
| Пользовательская Python-библиотека перестала работать после обновления версии {{ AF }} или Python в кластере | Клиент |
| Сбой резервного копирования базы метаданных на платформенном уровне | {{ yandex-cloud }} |
| {{ GL }} недоступен | Клиент |
| Ошибка подключения к {{ GL }} связана с платформенной ошибкой {{ maf-full-name }} | {{ yandex-cloud }} |

## Обращение в техническую поддержку {#support}

Техническая поддержка {{ yandex-cloud }} обрабатывает обращения, связанные с проблемами в зоне контроля {{ yandex-cloud }}.

При обращении по вопросам, относящимся к зоне контроля клиента, техническая поддержка не может гарантировать полноценный разбор и устранение проблем. К таким вопросам относятся отладка DAG, оптимизация задач, настройка Connections, анализ пользовательских логов, совместимость Python-библиотек, конфигурация CI/CD-пайплайнов {{ GL }} и другие задачи эксплуатации.

{% note info %}

В случае если у клиента недостаточно экспертизы, чтобы самостоятельно выполнять действия из своей зоны контроля, он может обратиться к своему аккаунт-менеджеру. Аккаунт-менеджер предложит варианты привлечения сертифицированных партнеров или профессиональных сервисов {{ yandex-cloud }}.

{% endnote %}
