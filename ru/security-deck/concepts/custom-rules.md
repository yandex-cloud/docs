# Пользовательские правила

Пользовательские правила позволяют адаптировать стандартные наборы правил безопасности модулей [{{ cspm-name }}](cspm.md) и [{{ kspm-name }}](kspm.md) под внутренние требования вашей компании.

Для работы с пользовательскими правилами необходима [роль](../security/index.md) `security-deck.rules.editor` или выше.

{% include [add-rule-to-set](../../_includes/security-deck/add-rule-to-set.md) %}

## Пользовательские правила модуля {{ cspm-name }} {#cspm-rules}

Пользовательские правила модуля {{ cspm-name }} создаются на основе базового стандартного правила. Базовое правило определяет основную логику проверки, которую можно дополнить или изменить.

Доступны следующие настройки:

* Редактирование названия и описания.
* Изменение критичности.
* Дополнение или изменение рекомендаций по исправлению.
* Редактирование настраиваемых параметров, специфичных для базового правила.

## Пользовательские правила модуля {{ kspm-name }} {#kspm-rules}

Пользовательские правила модуля {{ kspm-name }} создаются с нуля на основе собственных политик безопасности. В отличие от правил {{ cspm-name }}, они не требуют базового стандартного правила.

Доступны следующие настройки:

* Название и описание правила.
* Тип проверки — определяет, когда применяется правило. Сейчас поддерживается только опция Admission — правило применяется при создании или изменении {{ k8s }}-объекта.
* Критичность правила.
* Рекомендации по исправлению нарушений.
* YAML-код правила политики.

По умолчанию правило создается в режиме `Аудит`. После создания правила вы можете [поменять режим](../operations/kspm/manage-rule-modes.md).
