# Репликация в {{ SD }}

Репликация в кластере {{ mmg-name }} включается при наличии не менее трех [нескрытых](../operations/hosts.md#update) хостов. Каждый хост-реплика хранит копию одного и того же набора данных.

Виды реплик в кластере {{ mmg-name }}:
* _Первичная реплика (мастер)_ — автоматически выбирается среди нескрытых хостов и принимает все запросы на запись.
* _Вторичные реплики_ — асинхронно копируют все изменения на мастере.

Запросы на чтение могут обрабатываться как на вторичных репликах, так и на мастере, в зависимости от [параметра подключения `readPreference`](../operations/connect/clients.md).

## Смена мастера {#master-failover}

При выходе из строя или [ручном переключении](../operations/stepdown.md) мастера {{ SD }} автоматически выберет новый мастер из нескрытых хостов.

Повлиять на выбор мастера в кластере {{ SD }} можно с помощью [настройки приоритетов](../operations/hosts.md#update) для хостов кластера. Новым мастером станет хост с наибольшим приоритетом.

Задать приоритет хоста можно с помощью YC CLI, API или {{ TF }}:

* при [создании кластера](../operations/cluster-create.md) или [хоста в кластере](../operations/hosts.md#add-host);
* при [изменении настроек хоста](../operations/hosts.md#update).

Значение приоритета по умолчанию — `1`, соответствует наименьшему приоритету. Минимальное значение — `0`. Хост с таким приоритетом не может стать мастером, даже если в кластере нет других подходящих хостов. Максимальное значение — `1000`. Доступны только целочисленные значения.

## Отстающие реплики {#delayed-replica}

_Отстающая реплика_ — это вторичная реплика с заданным ненулевым временем отставания от мастера. Отстающая реплика хранит на диске копию журнала операций с мастера и применяет их с лагом, равным времени отставания. Такая реплика может располагаться только на скрытом хосте. В случае ошибочных операций вы можете оперативно [восстановить с нее данные на хост-мастер кластера](../operations/delayed-replicas.md#restore-data).

При создании или изменении хоста вы можете сделать его отстающей репликой. Для этого скройте его и задайте время отставания данных на этой реплике от мастера.

{% note warning %}

Чтобы обеспечить работу отстающей реплики, [отслеживайте свободное место в ее хранилище](high-availability.md#storage-settings).

Чем дольше время отставания реплики, тем больше места на диске хоста нужно для хранения изменений. Если место будет исчерпано, реплика перейдет в режим «только чтение» и перестанет выполнять свою функцию.

{% endnote %}

В шардированном кластере использование отстающих реплик не гарантирует полного восстановления данных. Отстающая реплика копирует все изменения, в том числе операции миграции чанков между шардами, с задержкой, равной времени отставания. Если миграция чанка происходит в пределах времени отставания, то в какой-то момент данные на отстающей реплике будут отражать состояние в процессе миграции. Поэтому они могут быть несогласованы с состоянием кластера и метаданными шардирования до миграции. В этом случае отстающая реплика не поможет восстановить кластер к состоянию до этой миграции (например, чтобы отменить ошибочную миграцию или потерю данных).
