# Репликация в {{ SD }}

Репликация в кластере {{ mmg-name }} включается при наличии двух и более [нескрытых](../operations/hosts.md#update) хостов. Каждый хост-реплика хранит копию одного и того же набора данных.

Виды реплик в кластере {{ mmg-name }}:
* _Первичная реплика (мастер)_ — автоматически выбирается среди нескрытых хостов и принимает все запросы на запись.
* _Вторичные реплики_ — асинхронно копируют все изменения на первичной реплике. 

Запросы на чтение могут обрабатываться как на вторичных репликах, так и на первичной реплике, в зависимости от [параметра подключения `readPreference`](../operations/connect/clients.md).

## Смена первичной реплики {#master-failover}

При выходе из строя или [ручном переключении](../operations/stepdown.md) первичной реплики {{ SD }} автоматически выберет новую первичную реплику из нескрытых хостов.

Повлиять на выбор первичной реплики в кластере {{ SD }} можно с помощью [настройки приоритетов](../operations/hosts.md#update) для хостов кластера. Новой первичной репликой станет хост с наибольшим приоритетом.

Задать приоритет хоста можно с помощью YC CLI, API или {{ TF }}:

* при [создании кластера](../operations/cluster-create.md) или [хоста в кластере](../operations/hosts.md#add);
* при [изменении настроек хоста](../operations/hosts.md#update).

Значение приоритета по умолчанию — `1`, соответствует наименьшему приоритету. Минимальное значение — `0`. Хост с таким приоритетом не может стать первичной репликой, даже если в кластере нет других подходящих хостов. Максимальное значение — `1000`. Доступны только целочисленные значения.
