# Как создать многоголосую аудиозапись и аудиодайджест с помощью SpeechKit, Python и n8n

В этом руководстве вы создадите аудиозапись из диалога, где каждому участнику назначен отдельный голос SpeechKit. Python разделит длинный текст на фрагменты, сохранит результаты синтеза в кэше и объединит их в один MP3. Дополнительно разберём, как построить на том же принципе автоматический аудиодайджест в n8n.

Это подход для учебных диалогов, озвучивания статей, небольших рассказов и новостных подборок. Для больших аудиокниг потребуется также редакторская разметка говорящих, контроль ударений, проверка соответствия исходному тексту и прослушивание готового результата.

В примере используется SpeechKit **API v1 REST** и два голоса, но он не пытается синтезировать многоголосую речь одним запросом: каждый фрагмент озвучивается отдельно выбранным голосом. Такой способ позволяет сохранять порядок говорящих, паузы и готовые записи независимо от возможностей отдельного голоса.

{% note info %}

API v1 доступен только в регионе Россия. Для других регионов и расширенных возможностей синтеза используйте API v3. Наличие API-ключа не означает доступ к бесплатному синтезу: учитывайте активный платёжный аккаунт, тарифы и квоты.

{% endnote %}

## Перед началом

Понадобятся:

- Организация, облако и каталог Yandex Cloud с активным платёжным аккаунтом.
- Сервисный аккаунт с ролью `ai.speechkit-tts.user` в нужном каталоге и API-ключ с областью действия, разрешающей синтез SpeechKit.
- Python 3.10 или новее.
- Установленный FFmpeg с командами `ffmpeg` и, при желании, `ffprobe` в `PATH`.
- Файлы из этого руководства: [`speechkit_multivoice.py`](./speechkit_multivoice.py) и [`sample_dialogue.json`](./sample_dialogue.json).

Если вы используете API-ключ сервисного аккаунта, передавайте его в HTTP-заголовке `Authorization: Api-Key ...`. Поле `folderId` в таком запросе не требуется. Для IAM-токена пользовательского аккаунта схема авторизации и требования к `folderId` отличаются.

Официальная документация: [краткое руководство по SpeechKit API v1](https://yandex.cloud/ru/docs/speechkit/quickstart/tts-quickstart-v1), [описание метода API v1](https://yandex.cloud/ru/docs/speechkit/tts/request), [цены на синтез](https://aistudio.yandex.ru/ru/docs/speechkit/pricing).

## Шаг 1. Подготовьте диалог и назначьте голоса

Файл `sample_dialogue.json` содержит короткий монтаж из первой главы романа «Полёт дуплянки»: голос Авроры, предупреждение автоинформатора и размышления героини. Для каждого фрагмента указаны `speaker`, `voice`, `text` и `pause_after` (пауза после реплики в секундах).

Например:

```json
{
  "segments": [
    {
      "speaker": "Аврора",
      "voice": "lera",
      "text": "Навигационная система сообщила о приближении к пограничному сектору.",
      "pause_after": 0.4
    },
    {
      "speaker": "Автоинформатор",
      "voice": "kirill",
      "text": "Внимание! Вы приближаетесь к зоне особого пограничного контроля Аверии.",
      "pause_after": 0.4
    }
  ]
}
```

Имена говорящих нужны программе для проверки порядка реплик. Сервис получает параметр `voice`. Убедитесь, что выбранный голос поддерживает заданный язык и необходимые настройки. Для отдельных голосов могут отличаться допустимые эмоциональные роли и форматы.

Используйте только тексты, на публикацию и обработку которых у вас есть права. В примере нет приватных пользовательских данных. Полная рукопись не передаётся.

## Шаг 2. Проверьте план бесплатно, без API-вызовов

Сохраните `speechkit_multivoice.py` и `sample_dialogue.json` в одну папку. Выполните:

```bash
python speechkit_multivoice.py --input sample_dialogue.json --dry-run
```

Результат содержит метку `DRY_RUN_NO_API_CALLS`, количество текстовых фрагментов, суммарную длину и список голосов. В этом режиме API-ключ и FFmpeg не нужны, тарифицируемых запросов нет.

Учебный скрипт делит большие реплики по предложениям и, при необходимости, по словам. Максимальная длина фрагмента по умолчанию равна 180 символам. Это консервативная настройка для коротких запросов и кэширования, а не официальный лимит SpeechKit. Для API v1 действует ограничение размера тела POST 15 КБ и длины поля `text` 5 000 символов; для больших произведений понадобится отдельная стратегия нарезки, учитывающая естественные паузы и стоимость блока.

**Важно:** автоматическое деление помогает не разрывать слова, но не гарантирует хорошую интонацию в длинных сценах. Перед большой генерацией проверьте места разбиения и распределение ролей.

## Шаг 3. Выполните синтез с помощью API-ключа

Сохраните ключ только в защищённом хранилище или краткоживущей переменной окружения процесса. Не вставляйте его в исходники, JSON диалога, командную историю общего компьютера или общедоступные скриншоты.

Пример для bash, если ключ уже доступен в переменной `YANDEX_API_KEY`:

```bash
python speechkit_multivoice.py --input sample_dialogue.json --output speech-output
```

Для Windows PowerShell вызов Python такой же. Переменную `YANDEX_API_KEY` задайте безопасным способом, принятым в вашей среде. Не добавляйте ключ в публичные команды и файлы репозитория.

Программа вызывает `https://tts.api.cloud.yandex.net/speech/v1/tts:synthesize` с параметрами `text`, `lang=ru-RU`, `voice`, `format=mp3`, `speed=1.0`, `emotion=neutral`. При успехе API v1 возвращает бинарные данные MP3. В отличие от REST API v3, этот метод не возвращает JSON с аудио в base64.

Скрипт сохраняет каждый уникальный фрагмент в `speech-output/.cache`, используя SHA-256 от текста, голоса, API и настроек. Повторный запуск с теми же параметрами не отправит повторный запрос для уже сохранённого аудио. При изменении текста или голоса будет создан новый кэш-ключ.

Для учёта затрат значение `new_api_requests` в результате показывает количество новых запросов, а `cache_hits` количество повторно использованных фрагментов. Реальный счёт определяется тарифами SpeechKit, а не только этим счётчиком.

{% note warning %}

Зависший сетевой запрос может быть уже обработан провайдером и оплачен, даже если клиент не получил файл. Поэтому этот пример **не делает автоматических повторных запросов после тайм-аута**. Для большого конвейера ведите отдельный журнал отправок и проверяйте спорные обращения вручную либо используйте согласованную стратегию восстановления.

{% endnote %}

## Шаг 4. Соберите MP3 и проверьте результат

Для каждого сохранённого MP3 программа создаёт временный одноканальный WAV с частотой 48 кГц. Затем последовательно добавляет аудиокадры и заданные паузы, после чего FFmpeg создаёт итоговый файл `speech-output/multivoice.mp3` с битрейтом 128 кбит/с.

Проверить параметры можно командой:

```bash
ffprobe -v error -show_entries format=duration,bit_rate -of json speech-output/multivoice.mp3
```

Прослушайте результат и убедитесь, что все фразы произнесены правильными голосами, окончания слов не потеряны, вопросы не превратились в утверждения и паузы не нарушают смысл. Автоматическая проверка длительности и кодека не заменяет слуховую приёмку.

Для большой книги дополнительно полезны сверка оригинала с распознанной речью, журнал отдельных фрагментов, контроль стабильности тембра и выборочное прослушивание каждого персонажа.

### Сколько стоил синтез

Для API v1 стоимость рассчитывается по числу текстовых символов: 1 342 ₽ за миллион символов. Для API v3 general расчёт по блокам до 250 символов за отдельный запрос составляет 0,1626 ₽, а для LiveTTS 0,25 ₽ за блок. Это не модель тарификации по входным и выходным токенам.

При указанном разделении реплик **расчётная стоимость шести итоговых образцов составляет 3.82 ₽ до скидок**. В ходе подготовки потребовалось несколько вариантов сокращения пограничной сцены: **суммарная расчётная стоимость всех новых запросов тестовой сессии около 4,63 ₽**. Реальное списание по платёжному аккаунту не сверено, поэтому обе цифры не являются квитанцией провайдера.

Аудиофайлы проверены инструментально: MP3, моно, положительная длительность, контрольные SHA-256. Слуховую проверку ударений, пауз и художественного результата необходимо выполнить отдельно.

## Шаг 5. Примените подход в n8n для аудиодайджестов

Похожую схему можно использовать, когда новые тексты регулярно приходят из RSS или другой системы.

1. Узел **Schedule Trigger** запускает сценарий с допустимой частотой; для разового теста используйте **Manual Trigger**.
2. **RSS Read** или HTTP Request получает записи, а узел редактирования полей оставляет только разрешённые к обработке текст, заголовок, URL и уникальный ID.
3. **Code** или аналогичный узел разбивает длинные тексты на фрагменты и формирует массив элементов с голосом и порядковым номером. Не передавайте в SpeechKit HTML, конфиденциальные тексты и чужие материалы без разрешения.
4. **HTTP Request** отправляет POST на `https://tts.api.cloud.yandex.net/speech/v1/tts:synthesize`, тип тела `Form URL-Encoded`, поля `text`, `lang=ru-RU`, `voice`, `format=mp3`. В настройках ответа выберите **File / Binary** и укажите binary property для аудио. **Authorization** настройте через подходящий credential-хранилище, а не строкой с настоящим ключом в экспортируемом workflow.
5. Для надёжного кэша и сборки больших файлов передавайте идентификаторы фрагментов и бинарное аудио в отдельный безопасный процесс сборки. Не объединяйте MP3 простым склеиванием байтов: нужен аудиодекодер или FFmpeg.
6. Проверьте сформированный файл, размер, длительность и счёт за синтез. Только затем доставляйте MP3 в Telegram, объектное хранилище или другую систему, к которой есть разрешённый доступ.

Для импортируемого JSON n8n требуются проверка конкретной версии платформы и credential-узлов. Поэтому в этом руководстве показана **логическая конфигурация**, а не непроверенный готовый workflow. Если API отвечает `401`, сначала выполните минимальный независимый тест cURL с тем же сервисным аккаунтом, затем проверяйте, отправляет ли HTTP Request заголовок авторизации; не публикуйте секрет ради диагностики.

## Что показали реальные внедрения: произношение, доступ и кодировки

Проверка текста и голосов в коротком демонстрационном диалоге не отменяет эксплуатационных проблем. В проектах художественного озвучивания «Полёт дуплянки» и кратких аудиосводок «Пегрегатора» мы столкнулись с несколькими типами ошибок. Здесь приведены только обобщённые способы их устранения, без API-ключей, параметров закрытой инфраструктуры и кода производственного конвейера.

### 1. Текст для чтения вслух отличается от текста для экрана

В новостных сводках название `Claude Code` при автоматической озвучке иногда звучало неправильно. Поэтому информационное содержание оставляли в исходном виде для читателя, а отдельное поле `summary_tts` (либо `summary_tts_ru` в схеме хранения) готовили для синтезатора. В нём можно задавать согласованное русское произношение иностранных названий и аббревиатур, например «Оупен Эй-Ай». Такой способ не меняет цитируемое написание на экране.

Особую проверку проводили для чисел. Дробь, записанная цифрами, может произноситься как два отдельных числа. Для TTS числа приводили к словам и нужному падежу. В кратком аудиодайджесте разумно округлять второстепенные значения до 2-3 значащих цифр, **если это не меняет существенный факт**. Если точность курса, процента или суммы важна, округление следует объяснить либо сохранить нужную точность. Вариант для речи должен проходить отдельную фактическую сверку с оригиналом.

То же касается времени: вместо «в 7» для вступления готовили произносимое выражение «в семь утра» или «в семь вечера», а не рассчитывали, что TTS корректно восстановит контекст по цифрам.

### 2. SSML должен передаваться именно как SSML

У SpeechKit API v1 поля `text` и `ssml` взаимоисключающие. Если отправить строку `<break time="1200ms"/>` в поле `text`, служебная разметка может быть произнесена буквально. Для пауз и TTS-разметки используйте поле `ssml`, а для обычного текста только `text`.

Учебный Python-пример этого руководства передаёт обычный текст и добавляет межрепликовые паузы **локально при монтаже WAV**. Он не реализует SSML-паузы внутри синтезируемой фразы. В n8n-контуре отдельная подготовка SSML полезна для пауз внутри одной новости, но итоговую структуру запроса необходимо проверять отдельно.

### 3. `PermissionDenied` не всегда означает неправильную IAM-роль

При первоначальном подключении одного из новостных сценариев SpeechKit отвечал `PermissionDenied`. Исправление заголовка авторизации, выдача ролей сервисному аккаунту и проверка scope сами по себе проблему не устранили. Прямой тест того же обращения вне n8n также завершился ошибкой. По материалам проекта, синтез заработал после подключения активного платёжного аккаунта.

Эта история не означает, что любой `PermissionDenied` вызван биллингом. Проверяйте **вместе** корректный каталог, права сервисного аккаунта, scope API-ключа, формат HTTP-запроса и активность платёжного аккаунта. Отдельный идентификатор API-ключа не является секретным значением ключа.

### 4. HTTP 400 может быть вызван локальным чтением секрета, а не самим API

В другом проекте первые три минимальных обращения к SpeechKit API v1 возвращали HTTP 400 `Bad Request`. Причина была установлена офлайн: секрет, введённый через графический интерфейс Windows Credential Manager, хранился в UTF-16LE, а загрузчик пытался интерпретировать его как UTF-8. После исправления декодирования повторный минимальный запрос вернул HTTP 200 и корректный MP3. Это проверено локальными тестами кодировок и декодированием аудио через FFmpeg.

Для подобных случаев проверяйте, что приложение извлекает секрет из хранилища в корректной кодировке, без нулевых байтов и случайных префиксов, а HTTP-заголовок строится в требуемом формате. **Не выводите секрет, его фрагменты или заголовок авторизации в консоль и логи.** Сам HTTP 400 без диагностики не доказывает причину сбоя.

### 5. Считайте стоимость по правилам конкретной версии API

Для SpeechKit API v1 тарификация основана на количестве отправленных символов, в том числе пробелов и служебных символов. Для API v3 действуют отдельные единицы тарификации на основе блоков текста и выбранной модели. Это не схема входных/выходных LLM-токенов. Не путайте плановую стоимость и реально выставленный счёт; кэшированный фрагмент, повторно собранный локально, не требует нового синтеза.

В нашем примере новостная подача намеренно нейтральная: задача не в том, чтобы вызвать у слушателя тревогу или ажиотаж, а в том, чтобы передать проверенные факты с минимальным эмоциональным шумом. Для художественного диалога, напротив, различаются голоса, паузы, реплики и речевой подтекст. Полный метод художественной режиссуры в рамках этого вводного руководства не рассматривается.

**Границы опыта:** проверенная демонстрация API-ключа не доказывает успешный синтез целой главы, а документированная схема n8n не равна опубликованному и протестированному импортируемому workflow. Мы не применяли библиотеку заранее записанных слов со склейкой новостей; такой способ обсуждался, но его реализация не подтверждена.

## Шаг 6. Контролируйте ошибки, квоты и цену

| Признак | Что проверить |
| --- | --- |
| `400 Bad Request` | URL-кодирование тела, поддерживаемые настройки голоса, `text` против `ssml`, ограничения API |
| `401 Unauthorized` | Формат `Authorization`, корректный тип ключа, фактическую передачу заголовка клиентом |
| `403 Forbidden` | Роль сервисного аккаунта, scope API-ключа и доступ к каталогу |
| `429 Too Many Requests` | Квоты и интенсивность запросов; уменьшите параллелизм и придерживайтесь рекомендаций по повторам |
| Повторные траты | Изменения текста/параметров, отсутствие кэша, повторный синтез после сетевых тайм-аутов |
| Неверный голос | Сопоставление роли и `voice`, порядок сегментов, совместимость голоса с настройками |

Для длинных проектов полезны предварительный dry-run, минимальный платный smoke test и хранение технических квитанций без ключей. Не запускайте сотни синтезов только для проверки одной ошибки авторизации.

## Что получилось

У вас есть воспроизводимый учебный пример многоголосой MP3-записи, который можно адаптировать к аудиодайджестам или большим литературным текстам. Он показывает архитектурные основы: отдельный запрос для каждого голоса, корректную нарезку, кэш, безопасную авторизацию, паузы и проверяемый монтаж.

**Границы примера:** здесь нет художественного голосового кастинга, обработки заранее записанной музыки, автоматической проверки дословности и восстановимого планировщика на десятки тысяч запросов. Для полноценной аудиокниги эти возможности следует добавить и протестировать отдельно.
