# Кластеризация поисковых запросов по выдаче

При планировании статей нужно решить, какие поисковые фразы объединить на одной странице. Для предварительной группировки можно сравнить адреса в выдаче. В этом руководстве вы получите выдачу через Yandex Search API и соберете кластеры, то есть группы фраз с общими результатами поиска.

В примере используется настраиваемое правило: фраза входит в кластер, если у нее есть хотя бы три общих адреса с главной фразой кластера среди первых десяти результатов. Это эвристика для отбора тем. Перед подготовкой страниц проверьте, совпадает ли намерение читателей у фраз внутри каждой группы.

## Подготовьте окружение {#before-you-begin}

1. [Создайте платежный аккаунт](https://yandex.cloud/ru/docs/billing/quickstart/) и [каталог](https://yandex.cloud/ru/docs/resource-manager/operations/folder/create), если их еще нет. Убедитесь, что облако привязано к активному платежному аккаунту.
1. [Создайте сервисный аккаунт](https://yandex.cloud/ru/docs/iam/operations/sa/create) для этого примера.
1. [Назначьте ему роль](https://yandex.cloud/ru/docs/iam/operations/sa/assign-role-for-sa) `search-api.webSearch.user` на каталог. Она позволяет работать с веб-поиском и [Wordstat](https://aistudio.yandex.ru/ru/docs/search-api/operations/wordstat-gettop).
1. [Создайте API-ключ](https://yandex.cloud/ru/docs/iam/operations/authentication/manage-api-keys#create-api-key) с областью действия `yc.search-api.execute` и ограниченным сроком действия.
1. Сохраните значение ключа в файл `api_key`, а идентификатор каталога в файл `folder_id`. По умолчанию пример читает их из каталога `~/.config/search-api/`. Другой путь можно передать параметром `--config-dir`.

Не добавляйте эти файлы в репозиторий. Ограничьте доступ к ним средствами вашей операционной системы. Например, в Linux и macOS:

```bash
chmod 600 ~/.config/search-api/api_key ~/.config/search-api/folder_id
```

Понадобится Python 3.9 или новее. Сторонние библиотеки не нужны. Сохраните рядом [скрипт `cluster_queries.py`](query-clustering/cluster_queries.py) и [пример `phrases.csv`](query-clustering/phrases.csv). Далее команды выполняются из каталога с этими файлами. Если в вашей системе Python запускается командой `python3`, используйте ее вместо `python`.

### Платные ресурсы {#paid-resources}

Оплачиваются запросы к API Wordstat и веб-поиску. Перед запуском сверьтесь с [правилами тарификации](https://aistudio.yandex.ru/ru/docs/search-api/pricing). Для пробного запуска в скрипте задано ограничение: не более пяти поисковых фраз. Без параметра `--run` скрипт только показывает план и не обращается к API.

## Подготовьте список фраз {#phrases}

Выберите один из двух источников: API Wordstat или собственный CSV.

### Расширьте исходную фразу через Wordstat {#wordstat}

{% note warning %}

По состоянию на 12 ноября 2026 года в [документации Wordstat](https://aistudio.yandex.ru/ru/docs/search-api/concepts/wordstat) указано: статистика за даты после 7 октября 2026 года недоступна, хотя методы API продолжают отвечать. Не принимайте возвращенные частоты за текущий спрос. Для работы с актуальным списком используйте CSV из своего источника и укажите дату сбора данных.

{% endnote %}

Метод [Wordstat.GetTop](https://aistudio.yandex.ru/ru/docs/search-api/api-ref/Wordstat/getTop) вызывается по адресу `POST https://searchapi.api.cloud.yandex.net/v2/wordstat/topRequests`. В теле запроса передаются исходная фраза, число фраз, регион и каталог:

```json
{
  "phrase": "как выбрать велосипед",
  "numPhrases": "50",
  "regions": ["225"],
  "devices": ["DEVICE_ALL"],
  "folderId": "<идентификатор_каталога>"
}
```

Ключ передается в заголовке `Authorization: Api-Key <API-ключ>`. В ответе список фраз находится в поле `results`. Поле `count` приходит строкой: перед сортировкой преобразуйте его в целое число. Скрипт делает это в функции `parse_wordstat`.

В примере для обоих API задан регион `225`, Россия. Для другого региона выберите код из [списка регионов поиска](https://aistudio.yandex.ru/ru/docs/search-api/reference/regions) и передайте `--region`.

### Загрузите собственный CSV {#csv}

Создайте файл в кодировке UTF-8 с заголовком `phrase,count`. В нем должна быть одна фраза на строку. Фразы с запятыми заключайте в двойные кавычки по правилам CSV.

В приложенном `phrases.csv` пять фраз о выборе велосипеда. Их частоты условные и служат только для демонстрации порядка обработки. Для рабочего запуска замените их данными своего источника. Скрипт не обращается к Wordstat, если указан `--input`.

## Получите выдачу {#serp}

Скрипт отправляет [синхронный запрос веб-поиска](https://aistudio.yandex.ru/ru/docs/search-api/api-ref/WebSearch/search) для каждой выбранной фразы. Он явно задает первую страницу, плоскую группировку и не более десяти документов:

```json
{
  "query": {
    "searchType": "SEARCH_TYPE_RU",
    "queryText": "как выбрать велосипед",
    "page": "0",
    "fixTypoMode": "FIX_TYPO_MODE_OFF"
  },
  "groupSpec": {
    "groupMode": "GROUP_MODE_FLAT",
    "groupsOnPage": "10",
    "docsInGroup": "1"
  },
  "region": "225",
  "responseFormat": "FORMAT_XML",
  "folderId": "<идентификатор_каталога>"
}
```

Поле `rawData` содержит XML в кодировке Base64. Функция `parse_serp` декодирует его и разбирает модулем `xml.etree.ElementTree`. Она извлекает только адреса документов из `response/results/grouping/group/doc/url`.

При сравнении адресов скрипт убирает фрагмент после `#` и приводит сетевую часть адреса (`netloc`) к нижнему регистру. Регистр пути, параметры запроса, схему и префикс `www` он сохраняет. Без проверки перенаправлений нельзя считать разные варианты адреса одной страницей. Повторяющиеся адреса не увеличивают число пересечений.

### Обработайте ошибки и сохраните ответы {#errors}

HTTP 429 означает ограничение частоты или квоты, а не отсутствие спроса. Скрипт повторяет такой запрос с растущей паузой и учитывает числовой заголовок `Retry-After`, если сервер его прислал. После исчерпания попыток он останавливается. Другие HTTP-ошибки и ошибки формата ответа также останавливают запуск.

Ошибка может находиться и внутри XML. Скрипт проверяет элемент `error`: [код `15`](https://aistudio.yandex.ru/ru/docs/search-api/reference/error-codes) обрабатывается как отсутствие результатов, остальные коды вызывают остановку. Фразы без результатов попадают в отдельный список `without_results` и не участвуют в кластеризации. Их нужно проверить отдельно.

Проверенные ответы сохраняются в каталог `cache`. Ключ кэша учитывает метод, тело запроса, регион и каталог Yandex Cloud. Срок хранения в примере составляет сутки. При повторном запуске с теми же параметрами скрипт берет свежие ответы из кэша. Ответ XML с кодом `15` также сохраняется как отсутствие результатов. Остальные ошибки в кэш не записываются.

Между сетевыми запросами скрипт выдерживает паузу. Перед большим запуском проверьте [квоты](https://aistudio.yandex.ru/ru/docs/search-api/concepts/limits): ограничения на запросы в секунду и в час действуют одновременно. Повторные попытки также учитывайте при оценке расхода.

## Сгруппируйте фразы {#cluster}

Функция `clusters` обрабатывает фразы по убыванию частоты. При равных частотах она использует алфавитный порядок, чтобы результат не зависел от порядка строк в CSV.

1. Первая фраза становится главной фразой нового кластера.
1. Каждая следующая фраза сравнивается с главными фразами уже созданных кластеров.
1. Если общих адресов не меньше порога, фраза входит в первый подходящий кластер.
1. Если подходящего кластера нет, фраза открывает новый.

Порог по умолчанию равен `3`. Его можно изменить параметром `--threshold`. Это настройка метода, а не гарантированная граница между темами.

Сравнивайте фразу с главной фразой кластера, а не с любым участником. Допустим, A имеет три общих адреса с B, B имеет три с C, а A и C имеют только один общий адрес. Если A стала главной, B присоединится к ней, а C откроет новый кластер. Склейка по цепочке объединила бы все три фразы.

При этом участники одного кластера не обязаны иметь три общих адреса друг с другом: правило проверяет их связь только с главной фразой. В результате получится предварительная группировка для ручной проверки.

Поле `head_count` в результате содержит частоту главной фразы. Не трактуйте его как суммарный спрос кластера. Частоты Wordstat по содержащимся фразам могут пересекаться, поэтому скрипт их не складывает.

## Запустите пример {#run}

Сначала посмотрите план без сетевых запросов:

```bash
python cluster_queries.py --seed "как выбрать велосипед" --num-phrases 50 --max-queries 5
```

Программа покажет один запрос Wordstat и не более пяти запросов веб-поиска, без учета кэша и повторов. Чтобы выполнить план:

```bash
python cluster_queries.py --seed "как выбрать велосипед" --num-phrases 50 --max-queries 5 --output clusters-wordstat.json --run
```

Для запуска по CSV вместо Wordstat:

```bash
python cluster_queries.py --input phrases.csv --max-queries 5 --output clusters-csv.json --run
```

Чтобы обработать больше фраз, увеличьте `--max-queries`. Скрипт выбирает наиболее частотные фразы в пределах этого ограничения. Увеличение `--num-phrases` расширяет ответ Wordstat, но само по себе не повышает число запросов веб-поиска.

Результат сохраняется в JSON. В нем находятся исходные частоты, адреса выдачи, кластеры, фразы без результатов и счетчики сетевых попыток и попаданий в кэш. Число кластеров зависит от полученной выдачи и выбранного порога.

Проверьте повторный запуск с тем же источником и теми же параметрами, но с другим именем результата:

```bash
python cluster_queries.py --seed "как выбрать велосипед" --num-phrases 50 --max-queries 5 --output clusters-repeat.json --run
```

Если кэш свежий и полон, счетчик `http_attempts` будет равен `0`. Для повторного запуска файлы `api_key` и `folder_id` по-прежнему должны быть на месте: скрипт читает конфигурацию до проверки кэша. Существующий файл результата скрипт не перезаписывает. После прерывания уже проверенные ответы остаются в кэше, поэтому запуск можно повторить с новым именем результата.

## Проверьте расходы и удалите ненужные ресурсы {#clear-out}

Оцените стоимость до запуска: умножьте число запросов каждого метода на его текущую цену из [тарифов](https://aistudio.yandex.ru/ru/docs/search-api/pricing). Учитывайте время отправки запросов и повторные попытки. План скрипта показывает количество запросов без кэша и повторов, а не сумму списания.

Фактическое потребление проверьте в [детализации расходов](https://yandex.cloud/ru/docs/billing/operations/check-charges). Счетчик `http_attempts` показывает сетевые попытки, он не заменяет биллинг.

Если ресурсы больше не нужны:

1. [Удалите API-ключ](https://yandex.cloud/ru/docs/iam/operations/authentication/manage-api-keys#delete-api-key), созданный для примера.
1. [Удалите сервисный аккаунт](https://yandex.cloud/ru/docs/iam/operations/sa/delete), если он создавался только для примера и не используется другими приложениями.
1. Удалите локальную копию ключа. Кэш и результаты сохраните, если хотите повторить анализ без новых запросов.
