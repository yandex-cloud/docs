# Кластеризация поисковых запросов по выдаче

Когда вы планируете страницы сайта под поисковый спрос, похожие по смыслу запросы часто требуют одной страницы, а не нескольких. Разнести их по разным страницам — значит конкурировать с самим собой. Надежный способ понять, какие запросы поисковая система считает одной темой, — сравнить их выдачу: если в топ-10 у двух запросов совпадает три и более адреса, под них подходит одна страница.

В этом руководстве вы соберете такие группы (кластеры) целиком на {{ yandex-cloud }}:

1. [Подготовьте облако к работе](#before-you-begin).
1. [Создайте сервисный аккаунт и API-ключ](#create-sa).
1. [Расширьте исходные фразы через API Wordstat](#wordstat).
1. [Снимите топ-10 выдачи через API веб-поиска](#serp).
1. [Сгруппируйте запросы в кластеры](#cluster).
1. [Оцените стоимость прогона](#cost).

Если созданные ресурсы вам больше не нужны, [удалите их](#clear-out).

## Перед началом работы {#before-you-begin}

[Создайте платежный аккаунт](../../billing/quickstart/index.md) и каталог, в котором будете работать, если их еще нет.

Понадобится Python 3.9 или новее. Сторонние библиотеки не нужны: запросы отправляются модулем `urllib` из стандартной библиотеки.

### Необходимые платные ресурсы {#paid-resources}

В стоимость входит плата за запросы к {{ search-api-name }}: отдельно за запросы к API Wordstat и за синхронные запросы к API веб-поиска (см. [тарифы](../../search-api/pricing.md)).

Для некоторых типов запросов к веб-поиску с 00:00 до 07:59 по московскому времени действует льготный тариф, поэтому дневные и ночные запросы в детализации идут отдельными строками.

## Создайте сервисный аккаунт и API-ключ {#create-sa}

1. [Создайте сервисный аккаунт](../../iam/operations/sa/create.md) в каталоге, где будете работать.
1. [Назначьте](../../iam/operations/sa/assign-role-for-sa.md) ему роль `search-api.webSearch.user`. Этой роли достаточно и для веб-поиска, и для API Wordstat.
1. [Создайте](../../iam/operations/authentication/manage-api-keys.md) для сервисного аккаунта API-ключ с областью действия `yc.search-api.execute` и сохраните его в файл `api_key`.
1. Сохраните идентификатор каталога в файл `folder_id`.

Храните ключ вне репозитория с кодом и ограничьте права на файл: `chmod 600 api_key`.

## Расширьте исходные фразы через API Wordstat {#wordstat}

Начните с нескольких фраз, которыми люди описывают свою задачу. Метод `topRequests` вернет популярные запросы, содержащие фразу, с числом показов:

```python
import json, os, urllib.request

KEY = open("api_key", encoding="utf-8").read().strip()
FOLDER = open("folder_id", encoding="utf-8").read().strip()
HOST = "https://searchapi.api.cloud.yandex.net"

def post(path, body):
    req = urllib.request.Request(
        HOST + path,
        data=json.dumps(body).encode(),
        headers={"Authorization": "Api-Key " + KEY,
                 "Content-Type": "application/json"})
    return json.loads(urllib.request.urlopen(req, timeout=60).read())

def top_requests(phrase, n=50):
    answer = post("/v2/wordstat/topRequests",
                  {"folderId": FOLDER, "phrase": phrase, "numPhrases": n})
    return [(r["phrase"], int(r["count"])) for r in answer.get("results", [])]
```

Обратите внимание: поле `count` приходит строкой, его нужно привести к числу.

{% note warning %}

Пустой список и ошибка — разные вещи. Если превышена квота, API вернет HTTP 429. Не перехватывайте все исключения одной веткой: иначе исчерпанная квота будет выглядеть как «спроса нет».

{% endnote %}

## Снимите топ-10 выдачи через API веб-поиска {#serp}

Синхронный запрос возвращает ответ в поле `rawData` в кодировке Base64. Внутри — XML, из которого достаточно взять адреса документов:

```python
import base64, re, time
from urllib.parse import urlsplit

def normalize(url):
    s = urlsplit(url.strip())
    return (s.netloc.lower().removeprefix("www.") + s.path.rstrip("/")).lower()

def top10(phrase):
    answer = post("/v2/web/search", {
        "query": {"searchType": "SEARCH_TYPE_RU", "queryText": phrase},
        "responseFormat": "FORMAT_XML",
        "folderId": FOLDER})
    xml = base64.b64decode(answer.get("rawData", "")).decode("utf-8", "replace")
    return [normalize(u) for u in re.findall(r"<url>(.*?)</url>", xml, re.S)[:10]]
```

Нормализация адреса нужна, чтобы `https://www.site.ru/page/` и `https://site.ru/page` считались одним адресом.

Каждый запрос к выдаче платный, поэтому:

* **Кэшируйте ответы.** Сохраняйте выдачу в файл и при повторном запуске берите ее оттуда. Для кластеризации выдача недельной давности обычно годится.
* **Делайте паузу между запросами** и при ответе 429 ждите, а не переходите к следующей фразе.

Узким местом обычно оказывается Wordstat: по умолчанию к нему можно отправить 100 запросов в час, а к синхронному веб-поиску 10 000 (см. [квоты и лимиты](../../search-api/concepts/limits.md)). Если для вашего объема этого мало, запросите увеличение квоты через техническую поддержку.

```python
import urllib.error

def top10_with_retry(phrase, attempts=4, pause=300):
    for _ in range(attempts):
        try:
            return top10(phrase)
        except urllib.error.HTTPError as e:
            if e.code == 429:
                time.sleep(pause)
                continue
            raise
    raise RuntimeError(f"квота не освободилась: {phrase}")
```

## Сгруппируйте запросы в кластеры {#cluster}

Идите по фразам в порядке убывания частоты. Каждая фраза либо присоединяется к существующему кластеру, либо открывает новый:

```python
THRESHOLD = 3  # сколько общих адресов в топ-10 делает запросы одной темой

def clusters(serp, freq):
    """serp: {фраза: [адреса]}, freq: {фраза: частота}"""
    groups = []  # (главная фраза, ее адреса, члены кластера)
    for phrase in sorted(serp, key=lambda p: -freq.get(p, 0)):
        urls = set(serp[phrase])
        for head, head_urls, members in groups:
            if len(urls & head_urls) >= THRESHOLD:
                members.append(phrase)
                break
        else:
            groups.append((phrase, urls, [phrase]))
    return [members for _, _, members in groups]
```

Фраза сравнивается только с **главной** фразой кластера — самой частотной, — а не с любым его участником. Если склеивать «цепочкой» (A похож на B, B похож на C), в один кластер попадают фразы с разными намерениями. На реальных данных так слились запросы «приставы списали больничные» и «могут ли приставы списать кредитные деньги»: выдачи у соседних фраз пересекались, но под эти запросы нужны разные страницы.

Спрос кластера удобно считать по главной фразе. Не складывайте частоты всех фраз: частота из Wordstat уже включает запросы, содержащие фразу, и сумма даст завышенное значение.

## Оцените стоимость прогона {#cost}

До запуска посчитайте число запросов: одна фраза — один запрос к выдаче, плюс запросы к Wordstat на расширение. Фактический расход смотрите в [детализации расходов](../../billing/operations/check-charges.md) с группировкой по продуктам: запросы к Wordstat и дневные и ночные запросы к выдаче идут отдельными строками.

Если у вас есть грант, помните, что он ограничен по сроку: после его окончания запросы тарифицируются полностью.

## Как удалить созданные ресурсы {#clear-out}

Плата за {{ search-api-name }} списывается только за выполненные запросы. Чтобы исключить случайные расходы, удалите API-ключ и сервисный аккаунт, если они больше не нужны.
