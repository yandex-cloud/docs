# Изменить настройки кластера {{ mtr-name }}

Если у вас есть кластер [{{ TR }}](../../concepts/components/trino.md) в [проекте](../projects/create-project.md), вы можете изменить его настройки.

{% note info %}

При изменении части параметров {{ mtr-name }} пересоздает кластер. На время применения новой конфигурации кластер переходит в состояние `Updating`, активные запросы прерываются. Подробнее см. в разделе [Обновление кластера](../../concepts/components/trino.md#cluster-update).

{% endnote %}

{% list tabs group=instructions %}

- CLI {#cli}

  1. Откройте файл ресурса `TrinoCluster`. Например, с помощью команды `open trinocluster.yaml`.
  1. Отредактируйте параметры:

      * `spec.version` — версия {{ TR }}. Значение должно быть указано в `TrinoImageCatalog`.
      * `spec.deletionProtection` — защита от удаления. Допустимые значения: `true`, `false`.
      * `spec.coordinator.resources.requests.cpu` — гарантированное количество CPU для пода координатора.
      * `spec.coordinator.resources.requests.memory` — гарантированный объем памяти для пода координатора.
      * `spec.coordinator.resources.limits.cpu` — максимальное количество CPU для пода координатора.
      * `spec.coordinator.resources.limits.memory` — максимальный объем памяти для пода координатора.
      * `spec.worker.replicas` — количество воркеров. Минимум `1`.
      * `spec.worker.resources.requests.cpu` — гарантированное количество CPU для пода воркера.
      * `spec.worker.resources.requests.memory` — гарантированный объем памяти для пода воркера.
      * `spec.worker.resources.limits.cpu` — максимальное количество CPU для пода воркера.
      * `spec.worker.resources.limits.memory` — максимальный объем памяти для пода воркера.
      * `spec.config` — дополнительные настройки {{ TR }}. Набор допустимых ключей и значений задаётся валидационной схемой версии {{ TR }} (оператор публикует её в ConfigMap `trino-omdb-operator-<версия>` в своём пространстве имён). Например, ключ `io.trino` задаёт уровень логирования (значения `DEBUG`, `INFO`, `WARN`, `ERROR`).
      * `spec.accessControl` — правила доступа к каталогам, схемам, таблицам, функциям, процедурам и запросам. См. раздел [Управление доступом](../../concepts/components/trino.md#access-control).

  1. Примените манифест: `kubectl apply -f trinocluster.yaml -n <пространство_имен>`. При необходимости можно прописать пространство имен в параметр ресурса `metadata.namespace` и не использовать его в команде.


- Консоль управления {#console}

  1. Если вы еще не открыли проект, выберите проект.
  1. Выберите пространство имен, в котором создан кластер.
  1. В левом меню выберите **Trino** → **Кластеры**.
  1. Выберите кластер.
  1. Нажмите **Редактировать**.
  1. Измените поля:

      **Основные параметры**

      * **Версия Trino** — версия {{ TR }} из `TrinoImageCatalog`.
      * **Защита от удаления** — переключатель защиты от случайного удаления.

      Поле **Имя** доступно только для чтения.

      **Конфигурация координатора**

      * **Запрошенный CPU**, **Запрошенная память** — запросы ресурсов для пода координатора.
      * **Лимит CPU**, **Лимит памяти** — максимальные ресурсы для пода координатора.

      **Конфигурация воркеров**

      * **Количество воркеров** — число подов воркеров.
      * **Запрошенный CPU**, **Запрошенная память** — запросы ресурсов для пода воркера.
      * **Лимит CPU**, **Лимит памяти** — максимальные ресурсы для пода воркера.

      **Дополнительные настройки**

      Раздел для добавления, изменения и удаления настроек {{ TR }}. У существующих строк ключ доступен только для чтения; меняется только значение.

      **Настройки доступа**

      Раздел для правил доступа в подсекциях «Правила каталогов», «Правила схем», «Правила таблиц», «Правила функций», «Правила процедур», «Правила запросов». Список полей и привилегий совпадает с формой создания кластера.

  1. Нажмите **Сохранить**.

{% endlist %}

Готово, настройки кластера изменены.
