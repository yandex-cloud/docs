#### Описание

**Риски при невыполнении правила:** без управления доступом по IP-адресам утечка токена сервисного аккаунта позволяет злоумышленнику из любой точки скачать образы (раскрыв состав инфраструктуры) или загрузить подменённые образы в реестр, что может скомпрометировать все нагрузки, использующие эти образы.

Реестр в [Yandex Container Registry](https://yandex.cloud/ru/docs/container-registry/) по умолчанию доступен с любого IP-адреса. Таким образом, любой, у кого есть действительные учётные данные, может скачивать или загружать образы откуда угодно из интернета.

[Управление доступом по IP](https://yandex.cloud/ru/docs/container-registry/operations/registry/registry-access) позволяет ограничить операции pull и push в реестре конкретным списком IP-адресов или CIDR-диапазонов. Это добавляет сетевую границу поверх защиты, которую предоставляет [сервис Identity and Access Management](https://yandex.cloud/ru/docs/iam/): даже если токен сервисного аккаунта утечёт, злоумышленник вне разрешённых IP-адресов не сможет ни скачать образы (и узнать, что запущено у вас в инфраструктуре), ни загрузить подменённые.

#### Инструкции и решения по выполнению

Ограничьте доступ к реестру известными диапазонами IP-адресов:

1. Определите политику доступа для скачивания и загрузки образов — обычно это исходящие IP кластера (NAT-шлюз), пулы раннеров CI/CD и небольшой круг адресов администраторов.
2. [Назначьте IP-разрешения на реестре](https://yandex.cloud/ru/docs/container-registry/operations/registry/registry-access) для действий `PULL` и `PUSH`, перечислив только эти диапазоны.
3. После сохранения убедитесь, что с не разрешённого IP операции pull и push не проходят, а с разрешённого — работают.

Подробнее в [документации Container Registry](https://yandex.cloud/ru/docs/container-registry/concepts/).
