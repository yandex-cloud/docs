#### Описание

[Yandex Audit Trails](https://yandex.cloud/ru/docs/audit-trails/) — основной инструмент сбора аудитных логов Yandex Cloud. Сервис записывает, что происходит с ресурсами облака, и выгружает логи в бакет Object Storage или лог-группу Cloud Logging для дальнейшего анализа или экспорта.

Audit Trails различает два типа событий:

* [События уровня конфигурации](https://yandex.cloud/ru/docs/audit-trails/concepts/events) — действия с конфигурацией облака: создание, изменение, удаление компонентов инфраструктуры, пользователей, политик. Пишутся по умолчанию, как только создан трейл.
* [События уровня сервисов](https://yandex.cloud/ru/docs/audit-trails/concepts/events-data-plane) — действия с данными и ресурсами внутри сервисов (например, обращения к объектам в бакете). По умолчанию не пишутся; включаются отдельно для каждого сервиса.

Audit Trails можно включить на уровне каталога, облака или организации. Рекомендуется включать его на уровне всей организации: это даёт единый централизованный поток логов по всей организации — как правило, в отдельное облако безопасности, — на что рассчитаны большинство схем мониторинга и compliance.

**Риски при невыполнении правила:** Без Audit Trails на уровне организации нет централизованной записи о том, кто и что делал во всех облаках и каталогах. Инциденты безопасности невозможно расследовать, несанкционированные изменения остаются незамеченными, а требования к аудитному логированию не могут быть выполнены. Злоумышленники, скомпрометировавшие облачные аккаунты, могут действовать, не оставляя отслеживаемых следов.

#### Инструкции и решения по выполнению

Включите Audit Trails на уровне организации:

1. Создайте [трейл](https://yandex.cloud/ru/docs/audit-trails/quickstart) на уровне организации и выберите приёмник — бакет Object Storage, лог-группу Cloud Logging или поток Yandex Data Streams.
2. Для сервисов, где важны события уровня сервисов (IAM, KMS, Lockbox, Object Storage, Managed Service for Kubernetes, управляемые БД), [включите сбор data-событий](https://yandex.cloud/ru/docs/audit-trails/quickstart#the-trail-creation) на трейле.
3. Перенаправьте приёмник в вашу SIEM или другую систему мониторинга — см. правило «События Yandex Audit Trails экспортируются в SIEM-систему».
4. Настройте мониторинг состояния самого трейла (статус `Error`, разрывы в событиях) — см. правило «Сервис Yandex Audit Trails работает в штатном режиме».

Список важных событий безопасности, которые стоит искать в аудитных логах, — в [библиотеке решений на GitHub](https://github.com/yandex-cloud/yc-solution-library-for-security/tree/master/auditlogs/_use_cases_and_searches).
