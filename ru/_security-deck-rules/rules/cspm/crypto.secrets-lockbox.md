#### Описание

Критичные данные и секреты доступа — токены аутентификации, API-ключи, ключи шифрования, пароли к БД — нельзя хранить в открытом виде в коде, в названиях и описаниях ресурсов, в метаданных ВМ и в подобных местах. Любой, у кого есть доступ к исходному коду, консоли управления или метаданным ВМ, получает доступ и к этим секретам.

[Yandex Lockbox](https://yandex.cloud/ru/docs/lockbox/) — управляемое хранилище секретов. Он хранит секреты в зашифрованном виде ключом из сервиса [Key Management Service](https://yandex.cloud/ru/docs/kms/), отдаёт их только авторизованным учётным записям и записывает каждое обращение в Audit Trails.

**Риски при невыполнении правила:** Учётные данные, хранящиеся в открытом виде в коде, конфигурации или метаданных, может извлечь любой, у кого есть доступ на чтение к этим местам — разработчики, CI/CD-пайплайны или злоумышленник, получивший доступ к репозиторию или ВМ. Утёкший секрет можно использовать для доступа к облачным ресурсам, базам данных или внешним сервисам, зачастую не оставляя следов в аудитных логах.

#### Инструкции и решения по выполнению

Уберите секреты из кода, конфигурации и метаданных в Lockbox:

1. [Создайте в Lockbox секрет](https://yandex.cloud/ru/docs/lockbox/operations/secret-create) для каждого учётного данных или чувствительного значения, которое используют ваши нагрузки.
2. Выдайте доступ к секрету только тому сервисному аккаунту нагрузки, которому он действительно нужен — используйте роль [`lockbox.payloadViewer`](https://yandex.cloud/ru/docs/lockbox/security/).
3. Читайте секреты в нагрузке напрямую из Lockbox — например, на ВМ через [SDK или CLI](https://yandex.cloud/ru/docs/lockbox/quickstart), а в Managed Service for Kubernetes — через [External Secrets Operator с поддержкой Yandex Lockbox](https://yandex.cloud/ru/docs/lockbox/tutorials/kubernetes-lockbox-secrets).
4. Удалите секрет из исходного места (код, конфиг, метаданные) и ротируйте его — старое значение нужно считать утёкшим.

Подробнее: [документация Lockbox](https://yandex.cloud/ru/docs/lockbox/).

{% note alert "**Примечание**" %}

При работе в Terraform заполняйте содержимое секрета Lockbox [скриптом](https://terraform-provider.yandexcloud.net/Resources/lockbox_secret_version), а не значением прямо в манифесте. Иначе значение секрета попадёт ещё и в файл `.tfstate`.

{% endnote %}

Для инвентаризации секретов в ваших хранилищах данных воспользуйтесь сервисом [DSPM](https://yandex.cloud/ru/docs/security-deck/concepts/dspm).
