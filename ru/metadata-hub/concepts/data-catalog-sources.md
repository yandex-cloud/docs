# Источники данных

Источник данных — это то подключение к базе данных или сервису, через которое в [каталог](data-catalog.md) загружаются метаданные. Пользовательские данные при этом не загружаются. При включенном профилировании дополнительно выполняются запросы на чтение к данным или выборкам, чтобы рассчитать статистику по колонкам и таблицам.

В каталог загружаются метаданные, которые содержат следующую информацию об источнике:

| Информация об источнике | Описание  |
| ----------------------- | --------- |
| Объекты хранения | Базы данных, схемы, таблицы, представления, индексы |
| Структура данных | Имена колонок/полей, их типы данных и возможность хранения значения `NULL` (nullable), вложенные колонки/поля |
| Комментарии | Описания к таблицам и колонкам |
| Происхождение данных | Связи между таблицами и представлениями |
| Профилирование данных | Статистика по таблицам и колонкам |
| Удаленные объекты | Объекты, которые были удалены из источника после предыдущей выгрузки |

### {{ PG }} {#source-pg}

В каталог из {{ PG }} загружаются метаданные, которые содержат следующую информацию об источнике:

| Информация об источнике | Описание  |
| ----------------------- | --------- |
| Базы данных и схемы | Базы данных и схемы, доступные в источнике |
| Таблицы | Таблицы, их технические имена и принадлежность к схеме |
| Представления | Представления и их SQL-определения |
| Хранимые процедуры | Хранимые процедуры и их SQL-определения |
| Колонки | Имена, типы данных и принадлежность к схеме |
| Комментарии | Описания таблиц и колонок, заданные через `COMMENT ON` |
| Происхождение данных | Связи между таблицами и представлениями, а также между представлениями |
| Происхождение данных на уровне колонок | Связи между колонками в представлениях |
| Профилирование данных | Статистика по таблицам, строкам и колонкам |
| Удаленные объекты | Объекты, которые были удалены из источника после предыдущей выгрузки |

В каталоге метаданные представлены в виде структуры: база данных → схема → таблица/представление → колонка.

Происхождение данных может определяться:

* На основе разбора SQL-определений представлений.
* На основе анализа SQL-запросов.
  
  Для анализа SQL-запросов требуется {{ PG }} версии не ниже `13` и расширение `pg_stat_statements`.

Для профилирования данных пользователю необходимы права `SELECT` на таблицы.

### {{ SD }}/{{ MG }} {#source-mg}

В каталог из [{{ SD }}](../../storedoc/index.yaml) и {{ MG }} загружаются метаданные, которые содержат следующую информацию об источнике:

| Информация об источнике | Описание  |
| ----------------------- | --------- |
| Базы данных | Базы данных, доступные в источнике |
| Коллекции | Имена, принадлежность к базе данных, список полей и их типы, структура документов, технические атрибуты |
| Поля | Имена, вложенные поля, типы, возможность хранения значения `NULL`, смешанные типы |
| Удаленные объекты | Коллекции, которые были удалены из источника после предыдущей выгрузки |

В каталоге метаданные представлены в виде структуры: база данных → коллекция → поле.

В {{ SD }} и {{ MG }} нет единой схемы коллекции, так как документы могут иметь разную структуру. Если включен вывод схемы, в каталоге формируется объединенная схема коллекции на основе выборки документов. Для построения схемы необходимы права на чтение баз данных, из которых загружаются метаданные.


### {{ data-transfer-full-name }} {#source-dt}

В каталог из [{{ data-transfer-name }}](../../data-transfer/index.yaml) загружаются метаданные о [трансферах](../../data-transfer/concepts/index.md#transfer), которые выполняются в выбранных [каталогах {{ yandex-cloud }}](../../resource-manager/concepts/resources-hierarchy.md#folder).

Метаданные содержат следующую информацию о трансфере:

* связи между хранилищами, таблицами и колонками;
* [трансформации данных](../../data-transfer/concepts/data-transformation.md).

Для каждого участника трансфера, для которого в каталоге не [создан источник](../operations/data-catalog/create-source.md), создается хранилище без активного источника. В этом случае в каталоге будут доступны только метаданные, полученные в рамках трансфера. В дальнейшем для каждого хранилища можно создать источник и настроить загрузку метаданных.


### {{ websql-full-name }} {#source-websql}

В каталог из [{{ websql-name }}](../../websql/index.yaml) загружаются метаданные об SQL-запросах и объектах базы данных, которые используются в запросах. Результаты выполнения запросов не загружаются. При этом запросы загружаются только для баз данных, для которых в каталоге создан источник.

В каталоге пользователю отображаются только его запросы или запросы, на просмотр которых у него есть права.


### {{ datalens-full-name }} {#source-datalens}

В каталог из [{{ datalens-name }}](../../datalens/index.yaml) загружаются метаданные о следующих объектах:

* [датасеты](../../datalens/dataset/index.md);
* [чарты](../../datalens/concepts/chart/index.md);
* [дашборды](../../datalens/concepts/dashboard.md);
* [отчеты](../../datalens/reports/index.md);
* [воркбуки и коллекции](../../datalens/workbooks-collections/index.md).

Метаданные загружаются для выбранных [подключений](../../datalens/concepts/connection/index.md). Если подключения не выбраны, метаданные загружаются для всех доступных подключений.

Для загрузки метаданных [сервисному аккаунту](../../iam/concepts/users/service-accounts.md) необходимы роли `datalens.visitor` и `datalens.admin` на организацию. Вместо роли `datalens.admin` можно выдать роли на доступ к отдельным ресурсам сервиса {{ datalens-name }} (например, `datalens.workbooks.viewer`). В таком случае загружаются только метаданные тех ресурсов, к которым у сервисного аккаунта есть доступ.

[Подробнее о ролях в {{ datalens-name }}](../../datalens/security/roles.md).
