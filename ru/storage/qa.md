#### Что такое {{ objstorage-full-name }}? {#qa-what-is}

{{ objstorage-full-name }} — это универсальное масштабируемое решение для хранения данных. Оно подходит как для высоконагруженных сервисов, которым требуется надежный и быстрый доступ к данным, так и для проектов с невысокими требованиями к инфраструктуре хранения.

#### Что я могу делать с {{ objstorage-full-name }}? {#qa-usecases}

С {{ objstorage-name }} вы можете:
* Разместить в {{ objstorage-name }} файлы своего проекта (сайта или серверного приложения) для публичного или закрытого доступа. Файлы могут быть любого формата.
* Хранить архивные данные большого объема (до 5 ТБ на один файл), которые будут доступны только тем, кому вы разрешите.
* Обеспечить совместную работу с данными внутри распределенной организации.
* Обеспечить доступ к своим данным из любого места Земли, где есть интернет.

#### Как начать пользоваться {{ objstorage-full-name }}? {#qa-quickstart}

Чтобы начать работать с {{ objstorage-name }}:
1. Зарегистрируйтесь в {{ yandex-cloud }}.
1. Создайте каталог.
   На этом шаге уже можно пользоваться {{ objstorage-name }} с помощью консоли управления {{ yandex-cloud }}. Можно создавать и удалять бакеты, загружать объекты в бакеты и скачивать их оттуда.
1. Получите статические ключи, чтобы использовать HTTP API {{ objstorage-name }} или готовые SDK и приложения.

Более подробные инструкции вы найдете в разделах [{#T}](quickstart.md) и [{#T}](s3/index.md).

#### Почему объекты не загружаются, хотя максимальный размер бакета еще не достигнут? {#qa-upload-storage-quota}

Возможно, в вашем облаке исчерпана [квота](concepts/limits.md#storage-quotas) **{{ ui-key.yacloud_quotas.quotas.storage.volume.size-key-value }}** (`storage.volume.size`). В консоли управления при этом может появляться ошибка `We encountered an internal error, please try again.`.

[Максимальный размер бакета](operations/buckets/limit-max-volume.md) ограничивает объем данных в отдельном бакете, а квота `storage.volume.size` — суммарный объем данных во всех бакетах облака. Увеличение максимального размера бакета не изменяет квоту облака.

Например, если максимальный размер бакета — 500 ГБ, а квота облака — 100 ГБ, загрузка новых объектов может завершаться ошибкой при достижении суммарного объема 100 ГБ во всех бакетах облака.

1. [Посмотрите значение и потребление квоты](../quota-manager/operations/read-quotas.md) `storage.volume.size` для облака, в котором находится бакет.
1. Если квота исчерпана или оставшегося объема недостаточно для загрузки, [создайте запрос на ее увеличение](../quota-manager/operations/set-quotas.md).
1. После увеличения квоты повторите загрузку объектов.

#### Как удалить несколько объектов за один раз? {#qa-delete-multiple-objects}

Вы можете удалить несколько объектов через консоль управления {{ yandex-cloud }} или через [API](../glossary/rest-api.md) с помощью метода [deleteMultipleObjects](s3/api-ref/object/deletemultipleobjects.md).

#### Почему сервисный аккаунт не может получить доступ в бакет? {#sa-bucket-access}


Проверьте, что сервисному аккаунту назначена [роль](./security/#roles-list) для доступа в бакет.


Если у бакета включено [шифрование](./concepts/encryption.md), назначьте сервисному аккаунту [роль](../kms/security/#service) `kms.keys.encrypterDecrypter` на [ключ {{ kms-short-name }}](../kms/concepts/key.md), которым зашифрован бакет. Это можно сделать, например, с помощью команды CLI:

```bash
yc kms symmetric-key add-access-binding \
  --id <идентификатор_ключа> \
  --service-account-id <идентификатор_сервисного_аккаунта> \
  --role kms.keys.encrypterDecrypter
```

Где:
* `--id` — идентификатор ключа {{ kms-short-name }}.
* `--service-account-id` — идентификатор сервисного аккаунта.

#### Где хранятся мои данные? {#qa-where}


Данные хранятся в нескольких географически распределенных дата-центрах на территории России. Подробнее в разделе [{#T}](../overview/concepts/geo-scope.md).




#### Как защищены мои данные в {{ objstorage-full-name }}? {#qa-data-security}

Физические носители расположены в дата-центрах {{ yandex-cloud }}, которые являются режимными объектами.

Данные хранятся в зашифрованном виде, и никто из тех, кто имеет доступ к физическому носителю, не сможет прочитать данные.

По умолчанию доступ к хранилищу осуществляется по протоколу HTTPS.

#### От чего зависит скорость загрузки и скачивания данных в {{ objstorage-full-name }}? {#qa-timings}

Время ответа {{ objstorage-name }} зависит от многих факторов:
* Производительности клиентской стороны (скорости сети, загрузки CPU или дисковой подсистемы).
* Скорости магистральных соединений, соединений между дата-центрами или соединения между клиентом и сервером.
* Производительности самого сервиса {{ objstorage-name }}.

Из-за этого мы не можем указать конкретное значение времени ответа. При этом мы не считаем нормой резкое увеличение времени ответа или заметное снижение скорости отправки данных и постоянно работаем над улучшением технических характеристик {{ objstorage-name }}.

#### Почему после создания/изменения политики доступа пропал доступ к бакету? {#qa-lost-access}

Если после настройки политики доступа возникает ошибка `Access Denied` или не отображается список объектов, проверьте правила политики.

Возможно несколько причин:

* Для [политики доступа](concepts/policy.md) объекты в бакете и сам бакет — это разные ресурсы. Чтобы правило в политике доступа относилось и к бакету, и к объектам в нем, укажите их как отдельные ресурсы. Например, `samplebucket` и `samplebucket/*`.

* Если к бакету применена политика доступа без правил, то доступ будет запрещен всем пользователям. Чтобы отключить проверки запросов по политике доступа, [удалите](operations/buckets/policy.md#delete-policy) ее.


* Если с бакетом взаимодействует кластер [{{ metastore-full-name }}](../metadata-hub/concepts/metastore.md) или [{{ maf-full-name }}](../managed-airflow/concepts/index.md) и для бакета настроена политика доступа, кластер не сможет записывать данные в бакет или читать данные из бакета без сервисного аккаунта с соответствующей ролью. Подробнее в инструкциях для [{{ metastore-name }}](../metadata-hub/operations/metastore/s3-policy-connect.md) и [{{ maf-name }}](../managed-airflow/operations/s3-policy-connect.md).

Для ресурсов, которые размещены в облачной сети {{ vpc-short-name }} и не имеют публичных IP-адресов или выхода в интернет, можно [организовать подключение](../tutorials/routing/storage-vpc-access.md) к {{ objstorage-name }} через [API Endpoint](../api-design-guide/concepts/endpoints.md). [FQDN](../glossary/fqdn.md) эндпоинта с помощью службы DNS будет преобразован в публичный IP-адрес.


#### Проверяются ли объекты, загружаемые в бакет, на наличие чувствительных данных и вредоносного кода? {#anti-malware}

В {{ objstorage-name }} объекты, загружаемые в бакет, не проверяются на наличие чувствительных данных или вредоносного кода.

Реализуйте проверку на наличие вредоносного кода самостоятельно перед загрузкой объектов в бакет.

Для выявления чувствительных данных в бакете воспользуйтесь [модулем контроля данных ({{ dspm-name }}) {{ sd-full-name }}](../security-deck/concepts/dspm.md).


#### Как исправить некорректный MIME-тип объектов при их загрузке в бакет? {#qa-mime-type}

Если бакет используется для [хостинга сайта](./concepts/hosting.md), некорректный [MIME-тип](https://ru.wikipedia.org/wiki/Список_MIME-типов) объектов может приводить к возникновению ошибок на сайте, например могут не открываться изображения или не работать скрипты.

В таком случае в браузере в консоли разработчика отображаются ошибки о некорректных MIME-типах объектов, загружаемых из бакета.

В зависимости от способа загрузки объектов в бакет заголовок [Content-Type](./s3/api-ref/common-request-headers.md) может подбираться автоматически, при этом не всегда корректно, например `text/plain` вместо `text/css`, либо выставляться по умолчанию — `binary/octet-stream`.

Чтобы избежать ошибок, явно укажите заголовок `Content-Type` при загрузке объектов в бакет:

{% list tabs %}

- CLI

  {% include [cli-install](../_includes/cli-install.md) %}

  {% include [default-catalogue](../_includes/default-catalogue.md) %}

  1. Посмотрите описание команды для загрузки объекта:

     ```bash
     yc storage s3api put-object --help
     ```

  1. Загрузите файл с явно заданным MIME-типом:

     ```bash
     yc storage s3api put-object \
       --bucket <имя_бакета> \
       --key <ключ_объекта> \
       --body <путь_к_локальному_файлу> \
       --content-type "application/javascript"
     ```

     Где `--bucket` и `--key` — обязательные параметры: имя бакета и ключ объекта. Параметр `--body` задает путь к загружаемому файлу. Необязательный параметр `--content-type` явно задает MIME-тип; в примере указан тип для JavaScript.

- AWS CLI

  ```bash
  aws s3 cp \
    <путь_к_локальному_файлу> \
    s3://<имя_бакета>/ \
    --no-guess-mime-type \
    --content-type "application/javascript" \
    --endpoint-url=https://{{ s3-storage-host }}
  ```

- s3cmd

  ```bash
  s3cmd put \
    --no-guess-mime-type \
    --no-mime-magic \
    --mime-type="application/javascript" \
    <путь_к_локальному_файлу> \
    s3://<имя_бакета>/
  ```

{% endlist %}

Также вы можете изменить заголовок `Content-Type` для уже загруженных объектов, например:

{% list tabs %}

- AWS CLI

  ```bash
  aws s3 cp \
    s3://<имя_бакета>/ \
    s3://<имя_бакета>/ \
    --exclude '*' \
    --include '*.js' \
    --no-guess-mime-type \
    --content-type="application/javascript" \
    --metadata-directive="REPLACE" \
    --recursive \
    --endpoint-url=https://{{ s3-storage-host }}
    ```

- s3cmd

  ```bash
  s3cmd modify \
    --recursive \
    --exclude '*' \
    --include '*.js' \
    --no-guess-mime-type \
    --no-mime-magic \
    --mime-type="application/javascript" \
    s3://<имя_бакета>/
  ```

{% endlist %}

#### Как настроить заголовок Cache-Control для объектов в бакете? {#cache-control}

Заголовок `Cache-Control` относится к [системным метаданным объекта](concepts/object.md#metadata). Его можно задать при загрузке объекта или изменить для уже загруженного объекта.

С помощью [**s3cmd**](tools/s3cmd.md) заголовок добавляется при загрузке файла:

```bash
s3cmd --add-header 'Cache-Control:max-age=3600' \
  put <путь_к_локальному_файлу> s3://<имя_бакета>/<ключ_объекта>
```

Для уже загруженного объекта:

```bash
s3cmd --add-header 'Cache-Control:max-age=3600' \
  modify s3://<имя_бакета>/<ключ_объекта>
```

Пример загрузки с помощью [**AWS CLI**](tools/aws-cli.md):

```bash
aws --endpoint-url=https://{{ s3-storage-host }} s3 cp \
  <путь_к_локальному_файлу> s3://<имя_бакета>/<ключ_объекта> \
  --cache-control 'max-age=3600'
```

В примерах время кэширования — 3600 секунд.

#### Как скопировать содержимое бакета в другой бакет? {#copy-bucket}

Содержимое бакета можно скопировать в бакет того же каталога, другого каталога, облака или организации. Для этого нужны права на чтение объектов в бакете-источнике и на запись в бакете-приемнике. При копировании всех объектов также нужен доступ к списку объектов источника.

Пример для [**AWS CLI**](tools/aws-cli.md):

```bash
aws --endpoint-url=https://{{ s3-storage-host }} s3 cp \
  s3://<бакет_источник>/ s3://<бакет_приемник>/ \
  --recursive
```

Для копирования между организациями доступны следующие варианты:

* С помощью {{ yandex-cloud }} CLI — от имени [аккаунта в Яндексе](../iam/concepts/users/accounts.md#passport), у которого есть нужные права в обеих организациях:

  ```bash
  yc storage s3 cp \
    s3://<бакет_источник>/ s3://<бакет_приемник>/ \
    --recursive
  ```

  Перед выполнением команды [установите и настройте CLI](../cli/quickstart.md).

* С помощью AWS CLI — от имени сервисного аккаунта с правами на бакет-приемник, если в бакете-источнике разрешено [публичное чтение объектов и их списка](operations/buckets/bucket-availability.md). Этот вариант подходит только для данных, которые можно сделать общедоступными.

Если объекты не зашифрованы, копирование происходит на стороне сервера, в том числе между организациями. Для зашифрованных объектов действуют особенности, описанные в инструкции [{#T}](operations/objects/copy.md).

Команды копируют объекты и сохраняют их в исходном бакете. При переносе данных удаление исходных объектов выполняется отдельно после проверки копии.

#### Как восстановить удаленные объекты? {#recover-deleted-objects}

Если при загрузке объекта было включено [версионирование](concepts/versioning.md) и нужная версия сохранилась, ее можно [восстановить](operations/objects/restore-object-version.md).

Если восстановить объект не удалось, создайте запрос в [техническую поддержку]({{ link-console-support }}). Укажите имя бакета, примерные дату и время удаления, имена объектов или ссылки на них.

{% note warning %}

Техническая поддержка не гарантирует восстановление данных, удаленных пользователем. Пока инженеры работают над запросом, не записывайте новые данные в затронутый бакет.

{% endnote %}

#### Как изменить класс хранения объектов? {#change-storage-class}

[Класс хранения](concepts/storage-class.md), заданный в свойствах бакета, применяется к новым объектам, только если инструмент загрузки явно не указывает другой класс. Например, в бакет с ледяным классом по умолчанию можно загрузить объект стандартного класса.

Для уже загруженных объектов изменение настройки бакета не меняет класс хранения. Чтобы изменить его, можно:

* Настроить [правила жизненного цикла](operations/buckets/lifecycles.md) для перехода в более холодный класс хранения.
* Повторно загрузить объект с нужным классом или скопировать его по тому же ключу с указанием нового класса с помощью [S3-клиента](tools/index.md).

#### Как исправить ошибку `SignatureDoesNotMatch`? {#signature-does-not-match}

Ошибка `The request signature we calculated does not match the signature you provided` при работе через S3-клиент или SDK может возникать из-за неверно указанного [статического ключа доступа](../iam/concepts/authorization/access-key.md). Проверьте идентификатор и секретную часть ключа, а также их формат в настройках клиента.

Для диагностики повторите операцию с помощью [AWS CLI](tools/aws-cli.md) с параметром `--debug`. В выводе будут промежуточные результаты расчета подписи, которые помогут найти причину ошибки.

Если ошибка сохраняется, создайте запрос в [техническую поддержку]({{ link-console-support }}) и приложите отладочный вывод. Перед отправкой удалите из него секретные ключи и другие конфиденциальные данные.

#### Почему при удалении бакета возникает ошибка `Bucket is not empty`? {#bucket-not-empty}

Удалить можно только пустой бакет. Ошибка `Bucket is not empty` возникает, если в нем остались объекты, их версии, маркеры удаления или незавершенные составные загрузки.

Чтобы очистить бакет:

* [Удалите все объекты, их версии и маркеры удаления](operations/objects/delete-all.md). В инструкции есть примеры для CLI, AWS CLI и Python (boto3).
* [Удалите незавершенные составные загрузки](operations/objects/deleting-multipart.md).

Также очистку можно настроить с помощью [правил жизненного цикла](operations/buckets/lifecycles.md). Они обрабатываются асинхронно, поэтому бакет может освободиться не сразу.

#### Почему запрос OPTIONS возвращает ошибку 403 без заголовка `Access-Control-Allow-Origin`? {#cors-error}

Проверьте [конфигурацию CORS](operations/buckets/cors.md) в бакете и заголовки [запроса OPTIONS](s3/api-ref/object/options.md):

* Заголовок `Origin` должен содержать источник запроса, например `https://example.com`, разрешенный в `AllowedOrigin`.
* Заголовок `Access-Control-Request-Method` должен содержать метод последующего запроса, разрешенный в `AllowedMethod`.
* Если запрос передает `Access-Control-Request-Headers`, перечисленные заголовки должны быть разрешены в `AllowedHeader`. Чтобы разрешить все заголовки, используется `*`.

Если источник или метод не разрешены, {{ objstorage-name }} возвращает ошибку 403 без заголовков `Access-Control-*`.


Подробнее о механизме — в разделе [{#T}](../glossary/cors.md).


#### Как исправить ошибку сертификата при использовании собственного домена? {#wrong-certificate}

Ошибки `err_cert_common_name_invalid` и `ssl_error_bad_cert_domain` могут возникать, когда CNAME-запись для домена сайта указывает на `<имя_бакета>.{{ s3-storage-host }}`. Для [хостинга сайта](operations/hosting/own-domain.md) она должна указывать на `<имя_бакета>.{{ s3-web-host }}`.

Проверьте CNAME-запись и [настройку HTTPS](operations/hosting/certificate.md): сертификат должен соответствовать домену сайта.

#### Почему при создании бакета возникает ошибка `BucketAlreadyExists`? {#bucket-already-exists}

Ошибка `409 BucketAlreadyExists` означает, что имя бакета уже занято. Имена бакетов уникальны в пределах региона и его эндпоинта, в том числе между каталогами, облаками и организациями.

Выберите другое имя и повторите создание. Требования к имени приведены в разделе [Правила именования бакетов](concepts/bucket.md#naming).
