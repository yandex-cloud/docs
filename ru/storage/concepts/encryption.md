# Шифрование в {{ objstorage-name }}

При использовании сервиса [{{ objstorage-full-name }}](../../storage/) критичные данные должны быть зашифрованы.

Шифрование бакета {{ objstorage-name }} с помощью ключей [{{ kms-full-name }}](../../kms/) (server-side encryption) — рекомендуемый подход. Такое шифрование защищает от случайной или намеренной публикации содержимого бакета в интернете.

{% note alert %}

Данные в {{ objstorage-short-name }} шифруются по схеме [envelope encryption](../../kms/concepts/envelope.md). Удаление ключа равносильно потере зашифрованных им данных.

{% endnote %}

Шифрование выполняется на стороне сервера (server-side encryption) с помощью ключей, хранящихся в {{ kms-name }}. Созданный {{ kms-short-name }}-ключ указывается в настройках бакета. Этот ключ будет использоваться для шифрования всех новых объектов или при [загрузке объекта через API](../../storage/s3/api-ref/object/upload.md).

Объекты шифруются перед сохранением в бакет и расшифровываются при скачивании из него. Шифрование по умолчанию применяется ко всем новым объектам, при этом загруженные ранее — остаются без изменений.

## Шифрование бакета и шифрование объекта {#bucket-and-object}

Ключ, указанный в настройках бакета, задает шифрование **по умолчанию**. Оно применяется к объекту, если в запросе на загрузку не переданы другие параметры шифрования.

Чтобы зашифровать отдельный объект другим ключом, укажите его при [загрузке объекта](../s3/api-ref/object/upload.md) в заголовках:

* `X-Amz-Server-Side-Encryption` — алгоритм шифрования, доступное значение: `aws:kms`;
* `X-Amz-Server-Side-Encryption-Aws-Kms-Key-Id` — идентификатор [ключа {{ kms-short-name }}](../../kms/concepts/key.md).

Такой объект будет зашифрован указанным ключом независимо от настроек бакета.

## Как узнать, зашифрован ли объект {#check}

Запросы [GetObject](../s3/api-ref/object/get.md) и [GetObjectMeta](../s3/api-ref/object/getobjectmeta.md) возвращают заголовки `X-Amz-Server-Side-Encryption` и `X-Amz-Server-Side-Encryption-Aws-Kms-Key-Id`, только если объект зашифрован. Если объект не зашифрован, этих заголовков в ответе не будет.

По второму заголовку можно определить, каким именно ключом зашифрован объект. Это важно, если в бакете лежат объекты, загруженные до включения шифрования или зашифрованные разными ключами.

## Отключение шифрования и удаление ключа {#disable-and-delete}

Это две разные операции с разными последствиями — не путайте их.

* [Убрать шифрование бакета](../operations/buckets/encrypt.md#del) — из настроек бакета удаляется ключ по умолчанию. Новые объекты перестают шифроваться, а уже загруженные остаются зашифрованными прежним ключом. Чтобы их скачать, ключ по-прежнему нужен, как и роль `kms.keys.decrypter` на него.
* [Удалить ключ {{ kms-short-name }}](../../kms/operations/key.md) — данные, зашифрованные этим ключом, восстановить нельзя. Убедитесь, что в бакете не осталось объектов, зашифрованных удаляемым ключом.

Ротация ключа безопасна: она создает [новую версию](../../kms/concepts/version.md), а прежние версии сохраняются, поэтому объекты, зашифрованные до ротации, продолжают расшифровываться.
