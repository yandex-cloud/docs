# Хранение ML-артефактов в {{ objstorage-name }} с помощью lifecycle-политик

В процессе обучения моделей машинного обучения (ML) генерируется большое количество промежуточных артефактов: чекпоинты модели, логи, метрики. Если их не контролировать, они быстро накапливаются и начинают занимать значительную часть бюджета на облачное хранение. В этом руководстве мы рассмотрим, как с помощью жизненных циклов (lifecycle) в {{ objstorage-name }} автоматизировать управление такими артефактами, чтобы не переплачивать за хранение устаревших данных.

## Сценарий использования

Вы обучаете модель компьютерного зрения в {{ datasphere-name }}, и ваши чекпоинты сохраняются в бакет {{ objstorage-name }}. Вы хотите, чтобы:

- Свежие чекпоинты (например, за последние 30 дней) оставались в стандартном классе хранения для быстрого доступа.
- Чекпоинты старше 30 дней, которые могут понадобиться для анализа, автоматически переносились в более дешевый класс хранения (например, `ICE`).
- Чекпоинты, которые устарели окончательно (например, старше 180 дней), автоматически удалялись.

## 1. Создайте бакет и структуру префиксов

Для удобства управления рекомендуется использовать разные префиксы (логические папки) для разных типов артефактов. Например:

- `checkpoints/` — для чекпоинтов модели.
- `metrics/` — для логов и метрик обучения.
- `raw-data/` — для исходных данных (если они хранятся в этом же бакете).

Такое разделение позволяет применять разные правила жизненного цикла к разным типам данных. В нашем примере мы настроим правило только для префикса `checkpoints/`.

## 2. Настройте lifecycle-политику

Жизненные циклы объектов в {{ objstorage-name }} позволяют автоматически изменять класс хранения или удалять объекты по истечении заданного срока. Изменения применяются к конфигурации раз в сутки в 00:00 UTC.

Создайте файл `lifecycle.json` со следующим содержимым:

```json
{
  "lifecycleRules": [
    {
      "id": "ArchiveAndDeleteOldCheckpoints",
      "enabled": true,
      "filter": {
        "prefix": "checkpoints/"
      },
      "transitions": [
        {
          "days": 30,
          "storage_class": "ICE"
        }
      ],
      "expiration": {
        "days": 180
      }
    }
  ]
}
