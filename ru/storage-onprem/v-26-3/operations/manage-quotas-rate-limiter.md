# Управление квотами для запросов и трафика

С помощью управления квотами можно ограничивать количество запросов к {{ objstorage-onprem-name }}, а также трафик — скорость чтения и записи данных. Эти ограничения защищают хранилище от перегрузки и помогают избежать ситуаций, когда всплеск активности одного пользователя ухудшает работу остальных.

Отслеживать потребление квот в {{ objstorage-onprem-name }} можно в разделе [Мониторинг](../monitoring/index.md).

## Лимиты, нижний и верхний пороги переполнения квоты {#quota-limits}

Для каждой квоты задаются *лимит* и два порога переполнения квоты — *нижний* и *верхний*. Лимит определяет среднюю нагрузку, которую ресурс — например, тенант или бакет — сможет поддерживать постоянно. Так лимит в 1000 запросов позволяет обрабатывать 1000 запросов каждую секунду в среднем, допуская кратковременные превышения.

Пороги определяют, как обрабатываются всплески нагрузки. При нагрузке между порогами запросы начинают отклоняться с ошибкой `429 Too Many Requests`. Чем выше нагрузка и чем дольше она превышает нижний порог, тем больше запросов отклоняется.

До нижнего порога запросы не отклоняются — он должен соответствовать нагрузке, при которой ресурс работает стабильно. По умолчанию нижний порог равен лимиту. Верхний порог определяет предел нагрузки, по достижении которого все новые запросы отклоняются.

Это упрощенное описание того, как лимит и пороги влияют на обработку запросов. Механизм ограничений основан на Yandex Rate Limiter и использует логику [Leaky Bucket](https://www.wikiwand.com/en/Leaky_bucket). Подробнее — в статье [YARL: как Яндекс построил распределенный Rate Limiter](https://habr.com/ru/companies/yandex/articles/579778/).

## Создать квоту {#create-quota}

При создании имя квоты формируется автоматически из выбранных параметров. Количество запросов можно ограничить для тенанта, бакета, отдельной операции или шарда, а трафик — для тенанта, бакета, серверного копирования или капла бакета.

{% note info %}

Для работы с квотами пользователю нужна глобальная роль `ADMIN` или `BUCKET_MANAGER`. Назначьте роль [по инструкции](../quickstart.md#assign-global-role).

{% endnote %}

### Ограничить количество запросов и трафик для тенанта или бакета {#limit-tenant-bucket}

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. На левой панели перейдите в раздел ![image](../_assets/console-icons/tachometer.svg) **Квоты**.
  1. Нажмите ![image](../_assets/console-icons/plus.svg) **Создать квоту**.
  1. В поле **Тип квоты** выберите тип ограничения:

      * **Квота RPS** — количество запросов в секунду к тенанту или бакету.
      * **Квота трафика** — скорость чтения или записи данных в КиБ/с.

  1. В поле **Область** выберите **Тенант** или **Бакет**.
  1. В поле **Действие** выберите **Чтение** или **Запись**.
  1. Выберите ресурс, к которому применяется квота:

      * Если выбрана область **Тенант**, в поле **Сущность** выберите нужный тенант.
      * Если выбрана область **Бакет**, выберите **Тенант**, затем в поле **Сущность** — нужный бакет.

  1. В поле **Лимит** укажите количество запросов в секунду для квоты RPS или объем трафика в КиБ/с для квоты трафика.
  1. Проверьте значения в полях **Нижний burst** и **Верхний burst**. По умолчанию нижний порог равен лимиту, а верхний — лимиту, умноженному на 100. При необходимости измените их.
  1. Нажмите **Создать**.

- CLI {#cli}

  {% include [cli-setup](../_includes/cli-setup.md) %}

  Создайте квоту:

  ```bash
  cli yarl set common <сущность> \
    --action <действие> \
    --limit <лимит> \
    --unit <единица_измерения> \
    --scope <область> \
    --low-burst <нижний_порог> \
    --high-burst <верхний_порог>
  ```

  Где:

  * `common` — тип квоты для ограничения количества запросов или трафика тенанта либо бакета.
  * `<сущность>` — идентификатор тенанта или имя бакета.
  * `--action` — действие, `read` для чтения или `write` для записи.
  * `--limit` — лимит, допустимая средняя нагрузка на выбранный ресурс. Укажите количество запросов в секунду для квоты RPS или объем трафика в КиБ/с для квоты трафика.
  * `--unit` (необязательный) — единица измерения, `rps` для количества запросов в секунду или `kbytes` для трафика в КиБ/с. По умолчанию `rps`.
  * `--scope` (необязательный) — область действия, `tenant` для тенанта или `bucket` для бакета. По умолчанию `bucket`.
  * `--low-burst` (необязательный) — нижний порог переполнения квоты, до достижения которого все запросы пропускаются. По умолчанию `limit`.
  * `--high-burst` (необязательный) — верхний порог переполнения квоты, при достижении которого все запросы отклоняются. По умолчанию `limit × 100`.

{% endlist %}

### Ограничить количество вызовов отдельной операции {#limit-operation}

Квота ограничивает выбранные действия в тенанте или бакете — например, загрузки или получения объектов. Ограничение действует независимо от того, из какого интерфейса вызвана операция — с помощью API, CLI или консоли управления.

  1. В поле **Тип квоты** выберите **Квота RPS обработчика**.
  1. В поле **Область** выберите **Тенант** или **Бакет**.
  1. В поле **Операция** выберите операцию, количество вызовов которой нужно ограничить, например **Получение объекта**.
  1. Выберите ресурс, к которому применяется квота:

      * Если выбрана область **Тенант**, в поле **Сущность** выберите нужный тенант.
      * Если выбрана область **Бакет**, выберите **Тенант**, затем в поле **Сущность** — нужный бакет.

  1. В поле **Лимит** укажите количество вызовов в секунду.
  1. Проверьте значения в полях **Нижний burst** и **Верхний burst**. По умолчанию нижний порог равен лимиту, а верхний — лимиту, умноженному на 100. При необходимости измените их.

  ```bash
    --high-burst <верхний_порог>
  ```

  Где:

  * `handler` — тип квоты для ограничения количества вызовов отдельной операции.
  * `<сущность>` — идентификатор тенанта или имя бакета.
  * `--operation` — идентификатор операции, например `get_object`, `put_object` или `list_multipart_uploads`.
  * `--limit` — лимит, допустимая средняя нагрузка на выбранный ресурс. Укажите количество вызовов в секунду.
  * `--scope` (необязательный) — область действия, `tenant` для тенанта или `bucket` для бакета. По умолчанию `bucket`.
  * `--low-burst` (необязательный) — нижний порог переполнения квоты, до достижения которого все запросы пропускаются. По умолчанию `limit`.
  * `--high-burst` (необязательный) — верхний порог переполнения квоты, при достижении которого все запросы отклоняются. По умолчанию `limit × 100`.

{% endlist %}

### Ограничить трафик серверного копирования {#limit-server-copy}

Квота на трафик серверного копирования ограничивает операции чтения и записи внутри хранилища. Например, при копировании или перемещении объектов из бакета в бакет.

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. На левой панели перейдите в раздел ![image](../_assets/console-icons/tachometer.svg) **Квоты**.
  1. Нажмите ![image](../_assets/console-icons/plus.svg) **Создать квоту**.
  1. В поле **Тип квоты** выберите **Квота трафика серверного копирования**.
  1. В поле **Область** выберите **Бакет**.
  1. В поле **Действие** выберите **Серверное чтение** или **Серверная запись**.
  1. Выберите **Тенант**, в котором находится бакет.
  1. В поле **Сущность** выберите бакет.
  1. В поле **Лимит** укажите объем трафика в Мбит/с.
  1. Проверьте значения в полях **Нижний burst** и **Верхний burst**. По умолчанию нижний порог равен лимиту, а верхний — лимиту, умноженному на 100. При необходимости измените их.
  1. Нажмите **Создать**.

- CLI {#cli}

  {% include [cli-setup](../_includes/cli-setup.md) %}

  Создайте квоту:

  ```bash
  cli yarl set common <имя_бакета> \
    --action <действие> \
    --unit mbits \
    --limit <лимит> \
    --scope bucket \
    --low-burst <нижний_порог> \
    --high-burst <верхний_порог>
  ```

  * `<имя_бакета>` — имя бакета, для которого создается квота.
  * `--action` — действие, `server_read` для серверного чтения или `server_write` для серверной записи.
  * `--unit mbits` — единица измерения трафика, Мбит/с.
  * `--limit` — лимит, допустимая средняя нагрузка на выбранный ресурс. Укажите объем трафика в Мбит/с.
  * `--scope bucket` (необязательный) — область действия квоты, бакет. По умолчанию `bucket`.
  * `--low-burst` (необязательный) — нижний порог переполнения квоты, до достижения которого все запросы пропускаются. По умолчанию `limit`.
  * `--high-burst` (необязательный) — верхний порог переполнения квоты, при достижении которого все запросы отклоняются. По умолчанию `limit × 100`.

{% endlist %}

### Ограничить количество запросов бакета к шарду {#limit-shard}

Сведения об объектах бакета распределены между шардами — частями базы данных. Если нагрузка распределяется неравномерно, отдельный шард может оказаться перегружен. Чтобы снизить нагрузку на него, можно ограничить количество запросов к этому шарду при работе с определенным бакетом.

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. На левой панели перейдите в раздел ![image](../_assets/console-icons/tachometer.svg) **Квоты**.
  1. Нажмите ![image](../_assets/console-icons/plus.svg) **Создать квоту**.
  1. В поле **Тип квоты** выберите **Квота RPS шарда бакета**.
  1. В поле **Операция** выберите **Чтение**, **Получение списков**, **Изменение метаданных**, **Чтение данных** или **Запись данных**.
  1. В поле **Бакет** укажите имя бакета.
  1. Укажите **Идентификатор шарда**. Идентификатор можно найти в поле `x_s3_shard_id` в [журнале аудита](../monitoring/index.md#audit-logs).
  1. В поле **Лимит** укажите количество запросов в секунду.
  1. Проверьте значения в полях **Нижний burst** и **Верхний burst**. По умолчанию нижний порог равен лимиту, а верхний — лимиту, умноженному на 100. При необходимости измените их.
  1. Нажмите **Создать**.

- CLI {#cli}

  {% include [cli-setup](../_includes/cli-setup.md) %}

  Создайте квоту:

  ```bash
  cli yarl set shard <имя_бакета> \
    --shard-id <идентификатор_шарда> \
    --operation <операция> \
    --limit <лимит> \
    --shard <тип_шарда> \
    --low-burst <нижний_порог> \
    --high-burst <верхний_порог>
  ```

  Где:

  * `shard` — тип квоты для ограничения количества запросов бакета к шарду.
  * `<имя_бакета>` — имя бакета, запросы которого к шарду нужно ограничить.
  * `--shard-id` — идентификатор шарда. Идентификатор можно найти в поле `x_s3_shard_id` в [журнале аудита](../monitoring/index.md#audit-logs).
  * `--operation` — тип операции, `read`, `list`, `modify`, `dread` или `dwrite`.
  * `--limit` — лимит, допустимая средняя нагрузка на выбранный ресурс. Укажите количество запросов в секунду.
  * `--shard` (необязательный) — тип шарда, `db` или `meta`. По умолчанию `db`.
  * `--low-burst` (необязательный) — нижний порог переполнения квоты, до достижения которого все запросы пропускаются. По умолчанию `limit`.
  * `--high-burst` (необязательный) — верхний порог переполнения квоты, при достижении которого все запросы отклоняются. По умолчанию `limit × 100`.

{% endlist %}

### Ограничить трафик капла бакета {#limit-couple}

Квота ограничивает трафик выбранного бакета для отдельного капла. [Капл](../concepts/architecture/elliptics.md) — это ячейка для записи и чтения бинарных данных.

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. На левой панели перейдите в раздел ![image](../_assets/console-icons/tachometer.svg) **Квоты**.
  1. Нажмите ![image](../_assets/console-icons/plus.svg) **Создать квоту**.
  1. В поле **Тип квоты** выберите **Квота трафика couple бакета**.
  1. В поле **Бакет** укажите имя бакета.
  1. Укажите **Пространство имен** MDS.
  1. Укажите **Идентификатор couple**.
  1. В поле **Лимит** укажите объем трафика в МиБ/с.
  1. Проверьте значения в полях **Нижний burst** и **Верхний burst**. По умолчанию нижний порог равен лимиту, а верхний — лимиту, умноженному на 100. При необходимости измените их.
  1. Нажмите **Создать**.

- CLI {#cli}

  {% include [cli-setup](../_includes/cli-setup.md) %}

  Создайте квоту:

  ```bash
  cli yarl set couple <имя_бакета> \
    --namespace <пространство_имен> \
    --couple <идентификатор_couple> \
    --limit <лимит> \
    --unit mbytes \
    --low-burst <нижний_порог> \
    --high-burst <верхний_порог>
  ```

  Где:

  * `couple` — тип квоты для ограничения трафика капла бакета.
  * `<имя_бакета>` — имя бакета, для капла которого создается квота.
  * `--namespace` — пространство имен MDS.
  * `--couple` — идентификатор капла.
  * `--limit` — лимит, допустимая средняя нагрузка на выбранный ресурс. Укажите объем трафика в МиБ/с.
  * `--unit mbytes` (необязательный) — единица измерения трафика, МиБ/с. По умолчанию `mbytes`.
  * `--low-burst` (необязательный) — нижний порог переполнения квоты, до достижения которого все запросы пропускаются. По умолчанию `limit`.
  * `--high-burst` (необязательный) — верхний порог переполнения квоты, при достижении которого все запросы отклоняются. По умолчанию `limit × 100`.

{% endlist %}

Команда `set` также изменяет существующую квоту с тем же типом, сущностью и параметрами, определяющими область действия квоты.

## Посмотреть квоты {#view-quotas}

{% note info %}

Для работы с квотами пользователю нужна глобальная роль `ADMIN` или `BUCKET_MANAGER`. Назначьте роль [по инструкции](../quickstart.md#assign-global-role).

{% endnote %}

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. На левой панели перейдите в раздел ![image](../_assets/console-icons/tachometer.svg) **Квоты**.
  1. Если у вас есть роли в нескольких тенантах и нет глобальной роли, выберите нужный **Тенант**.
  1. При необходимости найдите квоту с помощью поля **Поиск квот**.

  В таблице отображаются тип квоты, сущность, параметры, лимит и пороги **Нижний burst** и **Верхний burst**. Для квот по умолчанию в столбце **Сущность** указано **Все сущности**.

- CLI {#cli}

  {% include [cli-setup](../_includes/cli-setup.md) %}

  1. Получите список квот бакета:

      ```bash
      cli yarl list <имя_бакета> --scope bucket
      ```

      Чтобы получить список квот тенанта, выполните команду:

      ```bash
      cli yarl list <идентификатор_тенанта> --scope tenant
      ```

      Для просмотра квот шарда или капла бакета используйте соответственно `--scope bucket_db` или `--scope bucket_couple`.

  1. Скопируйте полное имя нужной квоты из столбца `Name` в результате команды.
  1. Получите информацию о квоте:

      ```bash
      cli yarl get --name '<полное_имя_квоты>'
      ```

      Кавычки позволяют передать имя квоты как один аргумент.

{% endlist %}

## Изменить квоту {#update-quota}

{% note info %}

Для работы с квотами пользователю нужна глобальная роль `ADMIN` или `BUCKET_MANAGER`. Назначьте роль [по инструкции](../quickstart.md#assign-global-role).

{% endnote %}

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. На левой панели перейдите в раздел ![image](../_assets/console-icons/tachometer.svg) **Квоты**.
  1. В строке нужной квоты нажмите значок ![image](../_assets/console-icons/ellipsis.svg) и выберите ![image](../_assets/console-icons/pencil.svg) **Редактировать**.
  1. Измените значения в полях **Лимит**, **Нижний burst** и **Верхний burst**. При редактировании пороги не пересчитываются автоматически вслед за лимитом.
  1. Нажмите **Сохранить**.

  Чтобы изменить тип квоты, ресурс или операцию, [создайте новую квоту](#create-quota). В окне редактирования доступны только лимит и пороги.

- CLI {#cli}

  {% include [cli-setup](../_includes/cli-setup.md) %}

  Повторите команду `cli yarl set` для [создания](#create-quota) квоты с прежними параметрами и новыми значениями лимита и порогов.

  Например, чтобы увеличить лимит чтения бакета до 800 запросов в секунду, выполните команду:

  ```bash
  cli yarl set common <имя_бакета> \
    --action read \
    --limit 800 \
    --unit rps \
    --scope bucket \
    --low-burst 800 \
    --high-burst 80000
  ```

  Чтобы сохранить текущие значения порогов, укажите их в команде. Если параметры порогов не указаны, CLI использует значения по умолчанию.

{% endlist %}

После изменения [просмотрите квоту](#view-quotas) и проверьте ее параметры.

## Удалить квоту {#delete-quota}

{% note info %}

Для работы с квотами пользователю нужна глобальная роль `ADMIN` или `BUCKET_MANAGER`. Назначьте роль [по инструкции](../quickstart.md#assign-global-role).

{% endnote %}

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. На левой панели перейдите в раздел ![image](../_assets/console-icons/tachometer.svg) **Квоты**.
  1. В строке нужной квоты нажмите значок ![image](../_assets/console-icons/ellipsis.svg) и выберите ![image](../_assets/console-icons/trash-bin.svg) **Удалить**.
  1. В открывшемся окне подтвердите удаление.

- CLI {#cli}

  {% include [cli-setup](../_includes/cli-setup.md) %}

  1. Получите список квот бакета:

      ```bash
      cli yarl list <имя_бакета>
      ```

      Чтобы получить список квот тенанта, шарда или капла, используйте соответствующую команду из раздела [Посмотреть квоты](#view-quotas).

  1. Скопируйте полное имя нужной квоты из столбца `Name` в результате команды.
  1. Удалите квоту:

      ```bash
      cli yarl delete --name '<полное_имя_квоты>'
      ```

  Чтобы удалить квоту по ее параметрам, укажите тип квоты, ресурс и параметры операции. Например, для квоты чтения бакета выполните команду:

  ```bash
  cli yarl delete common <имя_бакета> \
    --action read \
    --scope bucket \
    --unit rps
  ```

  Чтобы удалить квоту другого типа, используйте команду `cli yarl delete handler`, `cli yarl delete shard` или `cli yarl delete couple`. Укажите те же параметры ресурса и операции, что и при создании квоты. Лимит и пороги указывать не нужно.

{% endlist %}

После удаления снова получите список квот. Удаление отдельной квоты не отменяет другие ограничения, применимые к запросам, в том числе квоты по умолчанию.
