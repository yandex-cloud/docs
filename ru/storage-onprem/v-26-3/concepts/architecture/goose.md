# Goose

Goose — это сервис, реализующий S3-совместимый API поверх слоя хранения MDS2.

Goose развертывается по одному поду на каждом узле кластера {{ k8s }}. Это необходимо для эффективного использования ресурсов CPU, RAM и [сети](goose-mds2.md). Такое размещение также обеспечивает доступность и отказоустойчивость S3 API.

Для хранения метаданных S3 используются три вида кластеров {{ PG }}:

- *s3meta* — данные о бакетах, правах и ключах доступа (последние синхронизируются из Console API + Zitadel);
- *s3background* — служебная база для фоновых задач;
- *s3db* — данные об объектах (ключах) в бакетах S3.

{% note info %}

Кластеры s3meta и s3background не шардированы. По умолчанию количество шардов s3db равно количеству хостов. Нагрузка на s3db многократно выше, чем на остальные БД. Ключ шардирования — хеш от имени объекта в бакете, что позволяет равномерно распределять нагрузку по шардам.

{% endnote %}

Для чтения и записи Goose использует MDS2:

- неймспейсы MDS2 соответствуют классам хранения S3 согласно параметрам установки: например, неймспейс с репликацией x3 может соответствовать классу `STANDARD`, а неймспейс с EC 4+2 — классу `COLD`;
- для новой записи Goose получает у Visor подходящий капл и адреса Angel;
- встроенный клиент Imhotep передает данные в Angel, а Angel реализует репликацию, EC и согласование метаданных через Raft.

## Запись объекта {#write-object}

Упрощенно процесс записи выглядит так:

1. Goose выполняет авторизацию и читает информацию о бакете из s3meta.
1. Выбирает шард s3db по хешу имени объекта.
1. Выбирает капл и адреса Angel через Visor.
1. Записывает данные в Angel.
1. Записывает в s3db метаданные объекта, включая ID капла и ключ объекта в MDS2.

## Чтение объекта {#read-object}

Упрощенно процесс чтения выглядит так:

1. Goose выполняет авторизацию и читает информацию о бакете из s3meta.
1. Выбирает шард s3db по хешу имени объекта.
1. Читает из s3db ID капла и ключ объекта в MDS2.
1. Получает актуальные адреса Angel через Visor и читает данные из Angel.

При чтении Goose использует кеширование. Для обеспечения консистентности кеш используется *после* чтения из s3db. Для эффективного кеширования не рекомендуется использовать больше одного пода Goose на хост {{ k8s }}.
