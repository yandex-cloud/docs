* Используйте существующие сервисные подключения повторно: они действуют для всех ресурсов в выбранной облачной сети.
* Резервируйте статические внутренние IP-адреса для сервисных подключений и документируйте каждый случай такого резервирования.
* Выдавайте рабочим нагрузкам только минимально необходимые [роли](../../../cloud-registry/security/index.md#service-roles):

    * `cloud-registry.artifacts.puller` для скачивания артефактов.
    * `cloud-registry.artifacts.pusher` для загрузки артефактов. Выдавайте эту роль только тем субъектам, которым действительно нужна возможность загружать артефакты.
* Получайте короткоживущие IAM-токены для субъекта рабочей нагрузки. Не размещайте статические ключи в образах ВМ и контейнеров.
* При использовании корпоративного или пользовательского DNS заранее убедитесь, что в нем корректно разрешаются оба стандартных FQDN и wildcard-имена {{ objstorage-name }} и {{ cloud-registry-name }}.
* Помните, что у {{ cloud-registry-name }} есть публичный эндпоинт. Использование сервисного подключения не запрещает доступ к реестру из других сетей и не отменяет необходимости управлять доступом к реестрам при помощи ресурсов {{ iam-name }}.
* Для [удаленных](../../../cloud-registry/concepts/registry.md#remote-registry) и [виртуальных](../../../cloud-registry/concepts/registry.md#virtual-registry) реестров отдельно оценивайте зависимость от внешних репозиториев: сервисные подключения обеспечивают путь от рабочей нагрузки до сервиса {{ cloud-registry-name }}, но не гарантируют доступность сторонних репозиториев.
* Вместо группы безопасности по умолчанию вы можете [создать](../../../vpc/operations/security-group-create.md) и привязать к ВМ собственную группу безопасности, которая разрешает только минимально необходимый трафик ВМ:

    * Исходящий TCP-трафик на порт `443` к IP-адресам обоих сервисных подключений.
    * Исходящие DNS-запросы к DNS-серверу в подсети. Под DNS-сервер в подсети выделяется второй по счету IP-адрес диапазона. Подробнее читайте в разделе [{#T}](../../../vpc/concepts/network.md#subnet).
    * Входящий трафик, который обеспечивает административный доступ только из вашей доверенной сети, если такой доступ нужен.
