# Внешние таблицы

{{ mgp-name }} позволяет работать с данными в источниках, внешних по отношению к кластеру {{ mgp-name }}. Для этого используются _внешние таблицы_ — специальные объекты в базе данных, которые ссылаются на таблицы, бакеты или файлы внешних источников. Для доступа к данным во внешних СУБД используется протокол [{{ GP }} Platform Extension Framework](../operations/external-tables.md) (PXF), а к файлам на внешних файловых серверах — утилита [{{ GP }} Parallel File Server](../operations/gpfdist/connect.md) (`gpfdist`). Для СУБД {{ GP }} и {{ CB }} используются разные утилиты `gpfdist`. Подробнее об утилитах в [документации {{ GP }}]({{ gp.docs.broadcom }}/6/greenplum-database/utility_guide-ref-gpfdist.html) и [{{ CB }}]({{ gp.docs.cloudberry }}/sys-utilities/gpfdist).

С помощью внешних таблиц вы можете:

* выполнять запросы к внешним источникам данных;
* загружать наборы данных из внешних источников в БД в кластере {{ mgp-name }};
* объединять локальные и внешние таблицы в запросах;
* записывать данные во внешние таблицы или файлы.

{% note info %}

Для обеспечения безопасности в {{ mgp-name }} недоступно создание внешних веб-таблиц, использующих shell-скрипты.

{% endnote %}

## Внешние источники данных для работы по протоколу PXF {#pxf-data-sources}

В сервисе {{ mgp-name }} используются _внешние источники данных_ для создания внешних таблиц. Каждый источник является аналогом конфигурации на веб-сервере, которая используется для доступа к данным во внешних СУБД. Поэтому источники используются только для работы с PXF.

Источники позволяют:

* Указать в конфигурации параметры, которые нельзя передать в [SQL-запросе на создание внешней таблицы](../operations/pxf/create-table.md), работающей по протоколу PXF.
* Не указывать явно пароль пользователя в SQL-запросе на создание внешней таблицы.
* Упростить SQL-запрос на создание таблицы, так как с выделенным и настроенным источником не нужно перечислять параметры конфигурации в запросе.
* Упростить изменение конфигурации — параметры достаточно переопределить один раз на источнике, не изменяя их отдельно для каждой таблицы.

## Работа с файлами на внешних источниках с помощью утилиты gpfdist {#gpfdist}

Утилита `gpfdist` — это файловый сервер, который предоставляет хостам кластера {{ mgp-name }} параллельный доступ к файлам на удаленном сервере по протоколу HTTP.

Утилита установлена на всех хостах-сегментах кластера {{ mgp-name }}, но для работы с внешними файлами ее нужно [установить и запустить](../operations/gpfdist/connect.md#run-gpfdist) на сервере, который хранит эти файлы.

Для работы с файлами через утилиту `gpfdist` выполните следующие шаги:

1. На удаленном сервере запустите утилиту `gpfdist`, которая открывает доступ к указанной директории на указанном порту.
1. В кластере {{ mgp-name }} [создайте внешнюю таблицу](../operations/gpfdist/connect.md#create-gpfdist-table). В параметре `LOCATION` укажите протокол `gpfdist`, адрес сервера, порт и путь к файлу или маску для группы файлов.

При обращении к такой таблице хосты-сегменты кластера параллельно подключаются к `gpfdist`, и каждый сегмент читает или записывает свою часть данных. Данные передаются между сегментами и удаленным сервером напрямую, минуя хост-мастер. При загрузке данные распределяются между сегментами равномерно или согласно заданному [ключу дистрибуции](sharding.md#distribution-key). Это повышает производительность при работе с большими объемами внешних данных.

Утилита `gpfdist` позволяет:

* Использовать текстовые файлы с разделителями (форматы `TEXT`, `CSV` и `CUSTOM`), а также сжатые файлы gzip и bzip2.
* Использовать внешние таблицы для чтения данных из файлов и записи данных в файлы. Для этого создайте таблицу с опцией `READABLE` или `WRITABLE`.
* Указывать в одной внешней таблице несколько файлов и несколько серверов с запущенной утилитой `gpfdist`.
* Распределять нагрузку на сеть с помощью запуска на одном сервере нескольких экземпляров утилиты с разными директориями и портами.

Сервер с запущенной утилитой `gpfdist` должен быть доступен из сети, к которой подключен кластер {{ mgp-name }}, по указанному порту. Для этого [настройте группы безопасности](../operations/connect/index.md#configuring-security-groups). Если сервер с `gpfdist` находится за пределами {{ yandex-cloud }} и доступен через интернет, [настройте NAT-шлюз](../../vpc/operations/create-nat-gateway.md) в сети кластера.

[Внешние источники данных](#pxf-data-sources) для `gpfdist` не используются: все параметры подключения указываются в SQL-запросе на создание внешней таблицы.
