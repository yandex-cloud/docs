# Подключение CLI к эндпоинтам {{ yandex-cloud }}

_Эндпоинт_ — адрес, по которому CLI обращается к API соответствующего сервиса {{ yandex-cloud }}. Набор используемых эндпоинтов зависит от выполняемой команды.

При запуске `yc init` CLI подключается к региональному эндпоинту `https://{{ api-host }}` и получает актуальный список эндпоинтов сервисов. Затем CLI обращается к эндпоинтам, которые используются для аутентификации и настройки профиля. После инициализации CLI выбирает эндпоинт в соответствии с сервисом, к которому относится выполняемая команда.

Чтобы получить полный список доступных эндпоинтов {{ yandex-cloud }} и портов, выполните запрос:

```bash
curl https://{{ api-host }}/endpoints
```

Ответ содержит идентификаторы сервисов и адреса их эндпоинтов:

```json
{
  "endpoints": [
    {
      "id": "<идентификатор_сервиса>",
      "address": "<адрес_эндпоинта>:<порт>"
    }
  ]
}
```

{% note tip %}

Не используйте статическую копию списка: при появлении новых сервисов и эндпоинтов данные могут измениться. Подробнее о формате ответа читайте в разделе [{#T}](../../api-design-guide/concepts/endpoints.md).

{% endnote %}

## Доступ через файрвол или прокси-сервер {#network-access}

Если исходящие соединения ограничены файрволом, разрешите доступ к `{{ api-host }}` и эндпоинтам сервисов, с которыми планируете работать. Используйте порты, указанные в ответе на запрос `https://{{ api-host }}/endpoints`.

При аутентификации пользователя через браузер также потребуется доступ к `https://{{ auth-main-host }}` и доменам поставщика удостоверений.

Если доступ к {{ yandex-cloud }} организован через прокси-сервер, [настройте переменную окружения HTTPS_PROXY](index.md#cli-via-proxy).

## Проверка подключений {#check-connections}

Чтобы проверить, к каким эндпоинтам подключается `yc init`, включите подробный журнал gRPC:


```bash
yc init --debug-grpc
```



В журнале адреса подключений отображаются в строках `original dial target` и `Dialing`. Если подключение установлено, в журнале появляется строка `successfully connected`.

Параметр `--debug-grpc` выводит подробную информацию о gRPC-соединениях. Для просмотра общего журнала выполнения команды используйте параметр `--debug`. Подробнее об этих параметрах читайте в разделе [{#T}](./core-properties.md).

{% note warning %}

Журнал отладки может содержать данные запросов. Передавайте его другим пользователям только после удаления токенов и другой конфиденциальной информации.

{% endnote %}
