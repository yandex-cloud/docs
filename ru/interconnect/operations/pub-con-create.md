# Создать публичное соединение

Сейчас вы можете создать публичное соединение только через обращение в техническую поддержку.

Перед созданием соединения [получите информацию](trunk-get-info.md) о транковом подключении, сохраните его идентификатор и убедитесь, что физический порт находится в рабочем состоянии.

Создайте [обращение в поддержку]({{ link-console-support }}) со следующим содержанием:

```text
Тема: [CIC] Создание публичного соединения.

Прошу создать публичное соединение в транковом подключении.

trunk_id: euus5dfgchu2********
folder_id: b1g28j9359gi********
vlan_id: 101
ipv4_peering:
  peer_bgp_asn: 65001
allowed-public-services:
  - {{ s3-storage-host }}
  - transcribe.{{ api-host }}
is_nat_extra_ip_required: false
```

Где:

* `trunk_id` — идентификатор транкового подключения;
* `vlan_id` — идентификатор VLAN для публичного соединения, уникальный в пределах транкового подключения;
* `peer_bgp_asn` — номер BGP ASN на вашем сетевом оборудовании в формате ASPlain;
* `allowed-public-services` — список [эндпоинтов сервисов](../concepts/pub-con.md#svc-list), к которым вам нужен доступ;
* `is_nat_extra_ip_required` — укажите, нужен ли вам дополнительный префикс `/32` для [NAT](../concepts/pub-con.md#pub-nat);
* `folder_id` — идентификатор каталога для записи метрик. Необязательный параметр. Если вы не укажете его, будет использоваться каталог транкового подключения.

После создания соединения поддержка сообщит вам его идентификатор и параметры BGP-пиринга. Настройте BGP на вашем оборудовании, [проверьте состояние BGP-сессии](../concepts/monitoring.md#private-mon) и доступность выбранных сервисов.
