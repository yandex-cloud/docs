# Стоп-листы

В {{ postbox-name }} есть два стоп-листа: пользовательский и глобальный. Перед отправкой письма каждому получателю сервис проверяет оба стоп-листа независимо.

Когда адрес получателя находится:
* в глобальном стоп-листе, письмо этому получателю не отправляется.
* в пользовательском стоп-листе, письмо не отправляется, если причина, по которой адрес добавили в стоп-лист, [блокирует отправку](#reasons).

Перед тем, как добавить адрес в стоп-лист или проверить, находится ли он в стоп-листе, {{ postbox-name }} приводит его к каноническому виду: переводит домен в нижний регистр, а все, что идет после знака `+` до `@`, отбрасывает. Например, адрес `user+promo@Example.COM` хранится и ищется как `user@example.com`.

При попытке отправить письмо на заблокированный адрес запрос на отправку принимается, сервис возвращает идентификатор письма, но на почтовый сервер получателя оно не передается. Такое письмо отображается как [недоставленное](#blocked).

Стоп-листы проверяются отдельно для каждого получателя письма. Если адрес заблокирован, письмо не отправляется только этому получателю. Остальные получатели обрабатываются как обычно.

## Пользовательский стоп-лист {#user}

_Пользовательский стоп-лист_ — это список адресов получателей, которым {{ postbox-name }} не отправляет письма, если причина, по которой адрес добавили в стоп-лист, [блокирует отправку](#reasons). Можно создать только один пользовательский стоп-лист для облака и использовать его для всех каталогов, [адресов](glossary.md#address) и [конфигураций](glossary.md#configuration) внутри облака.

Пользовательский стоп-лист позволяет:

* заранее заблокировать нежелательные адреса, не дожидаясь первой ошибки доставки;
* автоматически исключать из рассылок получателей, которые пожаловались на письма;
* перенести стоп-лист из другого сервиса рассылок;
* разобраться, почему конкретное письмо не было отправлено, а после при необходимости разблокировать адрес.

Массового экспорта стоп-листов из сторонних сервисов в {{ postbox-name }} нет. Каждый адрес необходимо переносить отдельно.

### Как адрес попадает в пользовательский стоп-лист {#user-adding}

Адрес попадает в пользовательский стоп-лист одним из двух способов:

* [Вручную](../operations/manage-suppression-list.md#add) — пользователь добавляет адрес и самостоятельно указывает причину добавления.
* Автоматически по жалобе — когда от получателя приходит жалоба на письмо, {{ postbox-name }} добавляет адрес получателя в стоп-лист с причиной `COMPLAINT`. При этом сохраняется идентификатор письма, из-за которого адрес попал в стоп-лист.

Список адресов строится по асинхронному индексу, поэтому только что добавленный или удаленный адрес может добавиться в стоп-лист или удалиться из него с задержкой в несколько секунд. При этом запрос информации об одном адресе возвращает актуальные данные сразу, и блокировка отправки на адрес тоже начинает действовать сразу.

Ограничений на количество адресов в пользовательском стоп-листе нет.

### Причины добавления адреса в пользовательский стоп-лист {#reasons}

У каждого адреса в пользовательском стоп-листе указана причина, по которой он туда попал:

* `COMPLAINT` — получатель пожаловался на письмо.
* `BOUNCE` — на адрес не доставляются письма, например, потому что адреса не существует. Добавить адрес в стоп-лист по причине `BOUNCE` можно только вручную.

У адреса может быть только одна причина, по которой его добавили в стоп-лист. Если адрес добавляется в стоп-лист повторно, причина перезаписывается. Например, если пользователь добавил адрес с причиной `BOUNCE`, а затем от получателя пришла жалоба, причина изменится на `COMPLAINT`.

От настроек стоп-листа в [конфигурации](../operations/create-configuration.md#options), примененной к письму, зависит:
* какие причины блокируют отправку;
* добавляются ли адреса получателей в пользовательский стоп-лист автоматически по причине `COMPLAINT`.

Если конфигурация не применена к письму, по умолчанию отправку блокирует только причина `COMPLAINT` и адреса получателей, которые пожаловались на письма, автоматически добавляются в пользовательский стоп-лист.

## Глобальный стоп-лист {#global}

*Глобальный стоп-лист* (Global Suppression List, GSL) — это системный список адресов, которым управляет {{ postbox-name }}. Он общий для всех [адресов](glossary.md#address) и обновляется автоматически.

Глобальный стоп-лист включен по умолчанию для всех адресов {{ postbox-name }}, отключить его нельзя. Содержимое глобального стоп-листа недоступно через публичный API.

### Как адрес попадает в глобальный стоп-лист {#global-adding}

Если почтовый сервер получателя возвращает ошибку, которую {{ postbox-name }} классифицирует как постоянную и не требующую повторной попытки доставки, сервис фиксирует отказ по этому адресу. Из-за временных ошибок доставки адрес в глобальный стоп-лист не попадает.

Блокировка зависит от количества отказов. Первый отказ фиксируется, но попытки отправки при этом продолжаются. Если отказы повторяются, {{ postbox-name }} блокирует отправку на адрес. Срок блокировки увеличивается с каждым новым отказом и может достигать 14 дней.

### Как адрес удаляется из глобального стоп-листа {#global-removing}

После того как срок блокировки истек, {{ postbox-name }} удалит адрес из глобального стоп-листа при следующей успешной отправке на этот адрес. Если успешной отправки не происходит, адрес находится в стоп-листе около полугода.

Удалить адрес из глобального стоп-листа вручную нельзя — обратитесь в [техническую поддержку]({{ link-console-support }}).

## Как понять, что письмо не отправлено из-за того, что адрес находится в стоп-листе {#blocked}

Посмотрите:

* [Журнал выполнения](../operations/logs-write.md). Если для адреса [настроена запись логов](../operations/logs-write.md) и включена опция **{{ ui-key.yacloud.postbox.label_mail-statuses }}**, в журнале выполнения появится запись уровня `WARN` с сообщением `Message suppressed`. У обычной ошибки доставки будет сообщение `Message bounced`.

    Пример записи:

    ```json
    {
      "level": "WARN",
      "data": {
        "msg": "Message suppressed",
        "identity_id": "...",
        "message": {
          "message_id": "...",
          "reason": "Recipient is on your account suppression list",
          "mail": { "recipient": "user@example.com", "from": "...", "to": "...", "subject": "..." }
        }
      }
    }
    ```

    Поле `reason` указывает на то, какой стоп-лист заблокировал отправку:

    * `Recipient is on your account suppression list` — пользовательский стоп-лист;
    * `Recipient is on the global suppression list` — глобальный стоп-лист.

* [Историю отправленных писем](../operations/messages.md). В причинах недоставки письма будет написано, что отправку заблокировал пользовательский или глобальный стоп-лист.

* [Уведомления об операциях с письмами](notification.md#bounce). Если отправку заблокировал:

    * пользовательский стоп-лист, придет событие `Bounce` с подтипом ошибки `bounceSubType : OnAccountSuppressionList` и `diagnosticCode: Blocked by Account Suppression List`.
    * глобальный стоп-лист, придет событие `Bounce` с подтипом ошибки `bounceSubType : Suppressed` и `diagnosticCode: Blocked by Global Suppression List`.
