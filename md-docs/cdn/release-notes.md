# История изменений в Yandex Cloud CDN

## II квартал 2026 {#q2-2026}

* Сервис Cloud CDN стал доступен в [регионе](../overview/concepts/region.md) Казахстан.
* Изменена модель [тарификации](pricing.md) сервиса.
* Добавлена возможность поресурсной тарификации для [выделенной IP-адресации](concepts/dedicated-ip-addressing.md). 
* Появился [лимит](concepts/limits.md#cdn-limits) на количество выделенных IP-адресов для CDN-ресурсов на один платежный аккаунт.
* Расширен перечень HTTP-методов, которые по умолчанию заблокированы в запросах клиентов: помимо `POST`, теперь заблокированы `PUT`, `PATCH` и `DELETE`. Подробнее о возможности включения методов в подразделе [Запросы с методами POST, PUT, PATCH, DELETE недоступны пользователям](troubleshooting.md#post-responses).
* Расширена сеть [точек присутствия](concepts/points-of-presence.md): для [региона](../overview/concepts/region.md) Россия доступно 65 точек присутствия с суммарной пропускной способностью более 7 Тбит/с.
* Исправлены ошибки в [Terraform-провайдере](../terraform/release-notes.md).
* Улучшения в [консоли управления](https://console.yandex.cloud):
    * Перенесены следующие поля в блок настроек работы с источником:
      * **Протокол для источников**;
      * **Доменное имя источника**;
      * **Заголовок Host**.
    * Перенесены следующие поля в отдельную вкладку **Безопасность**:
      * **Переадресация клиентов**;
      * **Доступ по защищённому токену**;
      * **Ограничение доступа по IP-адресу**;
      * **Доступ по IP-адресам**.
    * Улучшено отображение ошибок в шагах визарда при создании CDN-ресурса и группы источников. Теперь ошибка показывается непосредственно на том шаге, где она возникла.
    * При выборе L7-балансировщика в качестве источника в выпадающем списке теперь отображаются только те балансировщики, к которым привязаны публичные IP-адреса.

## I квартал 2026 {#q1-2026}

* Добавлена возможность в [локационных правилах](concepts/location-rules.md) задать другой [источник](concepts/origins.md) для [CDN-ресурса](concepts/resource.md) без наследования настроек из основной конфигурации.
* Реализованы [профили безопасности TLS](concepts/clients-to-servers-tls.md#tls-profiles) для CDN-ресурса, содержащие определенный набор разрешенных шифров TLS.
* Поддержана [настройка пользовательского имени сервера для SNI](operations/resources/configure-server-name.md).
* Внедрена возможность настроить в [консоли управления](https://console.yandex.cloud) для CDN-ресурса разрешенный HTTP-метод `POST` в запросах от клиентов, а также поддержку протокола [WebSocket](https://ru.wikipedia.org/wiki/WebSocket). Опции становятся доступными после их включения через [техническую поддержку](https://center.yandex.cloud/support). Подробнее читайте в разделах [Запросы с методами POST, PUT, PATCH, DELETE недоступны пользователям](troubleshooting.md#post-responses) и [Как включить поддержку протокола WebSocket?](troubleshooting.md#websocket-support).
* Добавлена опция [настройки HTTP-ответов](operations/resources/configure-response.md), с помощью которой можно задать код перенаправления с CDN-ресурса или статический код ответа с заранее заданным телом ответа.
* Реализовано отображение в консоли управления статуса блокировки CDN-ресурса. Статус отображается, если CDN-ресурс был заблокирован за нарушение правил пользования сервисом.
* Поддержана возможность задать любое время [кеширования контента](concepts/caching.md).
* Внедрена настройка [следования перенаправлениям запросов](concepts/follow-redirects.md) в консоли управления.

## IV квартал 2025 {#q4-2025}

* Реализована функциональность [локационных правил](concepts/location-rules.md) — точечного переопределения настроек CDN-ресурса для запросов, пути которых соответствуют заданному шаблону.
* Добавлена возможность разрешить CDN-ресурсу [следовать перенаправлениям запросов](concepts/follow-redirects.md) от источника. При включенной опции Cloud CDN выполняет запрос по адресу, указанному в ответе источника, и затем возвращает клиенту контент с конечного адреса.
* Поддержан протокол [WebSocket](https://ru.wikipedia.org/wiki/WebSocket). Для включения обратитесь в [техническую поддержку](https://center.yandex.cloud/support).
* Добавлены новые [точки присутствия](concepts/points-of-presence.md).
* Поддержан [калькулятор цен для Cloud CDN](https://yandex.cloud/ru/prices?state=cc0daabb430b#calculator).
* Добавлено [событие Audit Trails](at-ref.md) уровня конфигурации `ResourceDelete` — удаление CDN-ресурса.

## III квартал 2025 {#q3-2025}

* Добавлен провайдер Yandex Cloud CDN на основе собственных технологий Яндекса.

* Добавлена возможность выбора провайдера при создании [ресурса](operations/resources/create-resource.md) и [группы источников](operations/origin-groups/create-group.md).

* Обновлен интерфейс создания CDN-ресурса:

  * упрощена настройка и создание ресурса с помощью визарда;
  * добавлена возможность копирования конфигурации уже существующего CDN-ресурса.

* Добавлена функциональность управления правилами использования ресурсов для провайдера Yandex Cloud CDN. Настройка доступна в [API](api-ref/ResourceRules/index.md).

* Исправлены ошибки в Terraform:

  * некорректное отображение доменного имени ресурса `provider_cname`;
  * невозможность выбора провайдера для ресурса.

## IV квартал 2024 {#q4-2024}

Поддержано [назначение](operations/resources/labeling.md) CDN-ресурсам [меток](concepts/labels.md) Yandex Resource Manager.

## III квартал 2024 {#q3-2024}

* Добавлена функциональность [перенаправления запросов](concepts/http-rewrite.md). Настройка доступна в консоли управления, CLI и API.
* Поддержана возможность задавать [политику доступа по IP-адресам](concepts/ip-address-acl.md) в консоли управления.

## II квартал 2024 {#q2-2024}

Добавлена возможность [настраивать доступ по защищенному токену](operations/resources/enable-secure-token.md) в консоли управления.

## I квартал 2024 {#q1-2024}

* Добавлена поддержка [политик доступа по IP-адресам](concepts/ip-address-acl.md) для CDN-ресурсов.
* Реализована механика ограничения доступа к CDN-ресурсу с помощью [защищенных токенов](concepts/secure-tokens.md).
* Убрана поддержка автоматического выпуска TLS-сертификатов для CDN-ресурсов на стороне CDN-провайдера EdgeЦентр. Теперь TLS-сертификаты должны быть предварительно загружены в Yandex Certificate Manager. Подробнее в разделе [Настройка TLS-сертификатов для HTTPS-соединений между клиентами и CDN](concepts/clients-to-servers-tls.md).
