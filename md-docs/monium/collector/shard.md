# Создание и настройка шарда

[Шард](../concepts/configuration-model.md) хранит телеметрию одной пары «кластер — сервис» внутри проекта. В настройках шарда можно выбрать метку с именем метрики и задать TTL метрик. На странице шарда доступны его данные, использование квот и анализ кардинальности.

Для работы с шардами используются роли:

* [monium.shards.viewer](../security/index.md#monium-shards-viewer) — просмотр шардов и их настроек.
* [monium.shards.editor](../security/index.md#monium-shards-editor) — создание и изменение шардов. Включает разрешения `monium.shards.viewer`.
* [monium.metrics.reader](../security/index.md#monium-metrics-reader) — чтение метрик шарда.

## Работать с шардом {#open}

При поступлении телеметрии по [OTLP](otlp-protocol.md#shard-distribution) Monium выбирает шард по значениям `project`, `cluster` и `service`. Если подходящего шарда нет, он создается автоматически. Просмотр шарда помогает проверить поступление данных, настройки хранения и использование квот.

{% list tabs group=instructions %}

- Интерфейс Monium {#console}

  1. Откройте [Monium](https://monium.yandex.cloud) и выберите проект в верхней панели.
  1. В меню слева выберите **Поставка и хранение** → **Шарды**.
  1. В списке нажмите идентификатор шарда. На странице шарда вы можете:

     * Посмотреть данные: на вкладке **Общая информация** в блоке справа нажмите:

       * **Метрики шарда** — чтобы найти нужные метрики и проверить их метки.
       * **Графики шарда** — чтобы посмотреть изменение значений метрик во времени. Выберите метрики и период, за который поступали данные. Подробнее о настройке графиков — в разделе [Построить графики по метрикам](../metrics/metric-explorer.md#add-graph).
       * **Логи шарда** — чтобы найти записи событий и сообщения об ошибках.
       * **Трейсы шарда** — чтобы проследить обработку запроса и найти медленные операции.

     * Оценить потребление квот: на вкладке **Использование квот** выберите временной интервал. График **Stored Metrics** показывает количество хранимых метрик, а **Metrics Write** — скорость записи точек в метрики.

       Текущие значения квот и технических лимитов также показаны на вкладке **Общая информация**. Порядок изменения квот описан в разделе [Квоты и лимиты в Monium](../concepts/limits.md).

     * Найти метки, с которыми связан рост числа временных рядов: воспользуйтесь [анализом кардинальности](#cardinality).

     * Изменить настройки шарда: нажмите **Редактировать**, внесите изменения и сохраните их.

{% endlist %}

## Создать шард {#create}

Создайте шард вручную, если нужно выбрать метку с именем метрики и задать TTL до начала отправки телеметрии.

{% list tabs group=instructions %}

- Интерфейс Monium {#console}

  1. Откройте [Monium](https://monium.yandex.cloud). В верхней панели нажмите название текущего проекта и выберите проект для нового шарда.
  1. В меню слева выберите **Поставка и хранение** → **Шарды**.
  1. В правом верхнем углу нажмите **Создать**.
  1. Выберите **Кластер** и **Сервис** для нового шарда.
  1. В поле **ID** введите идентификатор шарда.
  1. В поле **Метка, используемая в качестве имени метрики** укажите, из какой метки Monium будет брать название метрики. Выберите способ задания метки:

     * **Из списка** — выберите `name`, `sensor`, `path`, `metric` или `signal`.
     * **Произвольная** — введите другое имя метки.

     Ориентируйтесь на данные, которые отправляет приложение или агент. Например, для `name="cpu_usage"` выберите `name`, а для `sensor="cpu_usage"` — `sensor`. В обоих случаях названием метрики будет `cpu_usage`.

     Если вы только настраиваете отправку метрик, рекомендуем использовать метку `name`.

  1. При необходимости задайте **TTL метрик** в днях. Если новые значения метрики не поступают в течение этого срока, она считается устаревшей и удаляется.
  1. Нажмите **Создать**.

{% endlist %}

## Оценить кардинальность {#cardinality}

Кардинальность метки — количество ее уникальных значений. Вкладка **Анализ кардинальности** помогает определить, какие метки связаны с ростом числа временных рядов и потребления квот.

Чтобы посмотреть результаты анализа:

{% list tabs group=instructions %}

- Интерфейс Monium {#console}

  1. [Откройте шард](#open).
  1. Перейдите на вкладку **Анализ кардинальности**.
  1. В таблице **Топ меток** найдите строки с большим значением в столбце **Метрик** и сравните значения в столбце **Уникальные метки**.

{% endlist %}

Столбцы таблицы содержат следующую информацию:

* **Метка** — пара «имя метки — значение», например `zone = ru-central1-d`.
* **Метрик** — количество временных рядов с этой парой. Один ряд может учитываться в нескольких строках таблицы, поэтому значения столбца нельзя суммировать для подсчета всех рядов в шарде.
* **Уникальные метки** — количество разных значений других меток среди этих рядов. Например, `bin = 29` означает, что метка `bin` принимает 29 разных значений. Индикатор `+3` обозначает еще три метки, скрытые в строке.

Например, для строки `name = load_balancer.requests_latency_milliseconds` значение **Метрик** равно 29, а в столбце **Уникальные метки** указано `bin = 29`. Это означает, что одному имени метрики соответствуют 29 временных рядов с разными бакетами гистограммы. Такое разбиение ожидаемо и само по себе не указывает на проблему.

Обращайте внимание на метки с неожиданно большим числом значений. Например, идентификатор каждого запроса в метке создает новые временные ряды. В пользовательских метриках используйте [метки с ограниченным набором значений](../concepts/data-model.md#label), а подробности отдельных запросов сохраняйте в логах или трейсах.

Для анализа используются не более 1 000 последних метрик. Результаты относятся только к этой выборке. Общее количество хранимых метрик можно посмотреть на вкладке **Использование квот**.
