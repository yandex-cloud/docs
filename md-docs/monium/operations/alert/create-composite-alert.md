# Создание композитного алерта

[Композитный алерт](../../concepts/alerting/alert.md#composite-alerts) вычисляет свой статус на основе статусов других алертов. Он помогает задать общую логику срабатывания для нескольких связанных проверок. Например, можно учитывать проблему только при одновременном переходе нескольких алертов в статус `Alarm`.

{% note info %}

Для просмотра [алертов](../../concepts/alerting/alert.md) необходима роль `viewer` или выше на облако. Подробнее о ролях в разделе [Управление доступом в Monium](../../security/index.md).

{% endnote %}

{% list tabs group=instructions %}

- Интерфейс Monium {#console}

  1. На главной странице [Monium](https://monium.yandex.cloud) слева выберите ![alt](../../../_assets/console-icons/shield-exclamation.svg) **Алерты и SLO** → ![alt](../../../_assets/console-icons/megaphone.svg) **Алерты**.
  1. Вверху справа нажмите **Создать алерт** → **Композит**.
  1. Укажите основные параметры алерта:

      * **Название** — произвольное название алерта.
      * **ID** — уникальный идентификатор алерта с префиксом проекта. По умолчанию совпадает с названием.
      * **Описание** — назначение алерта или комментарий.
      * **Уровень алерта** — [уровень критичности алерта](../../concepts/alerting/alert.md#severity). Выбирайте уровень по влиянию события:
      
          * `Unspecified` — черновик или тест без выбранного уровня.
          * `Disaster` — недоступность сервиса или риск потери данных.
          * `Critical` — деградация сервиса или нехватка ресурсов.
          * `Info` — плановая операция или тестовый алерт.

  1. В блоке **Селектор алертов** укажите метки для поиска исходных алертов.

      Например, `severity = "Critical"` (группирует критичные алерты), `status = "Alarm"` (группирует сработавшие алерты) или `notification_channel.id = "<идентификатор_канала>"` (группирует алерты из определенного канала уведомлений).

  1. В блоке **Условия срабатывания** выберите стратегию композиции (способ вычисления итогового статуса алерта):

      * **По доле** — статус назначится алерту, когда заданный процент выбранных алертов перейдет в указанные статусы. Используйте стратегию для однотипных проверок, например по доле недоступных хостов в кластере.
      * **По количеству** — статус назначится алерту, когда в указанных статусах окажется заданное число выбранных алертов. Используйте стратегию для фиксированного кворума, например когда достаточно трех сработавших алертов по зонам доступности.

  1. Настройте условия для статусов **Warning** и **Alarm**:

     * Задайте порог: процент или количество. Для **Warning** задайте порог раннего предупреждения, например `20`% проблемных инстансов. Для **Alarm** задавайте порог, который требует реакции дежурного.
     * Выберите статусы исходных алертов, которые нужно учитывать. Если статусы не выбраны, считаются алерты в статусах `Warning` и `Alarm`.

     Когда порог достигнут, композитный алерт перейдет в соответствующий статус. Например, для **Alarm** выбраны статусы `Alarm` и `Error` и задан порог `3`. В этом случае композит перейдет в `Alarm`, когда в статусах `Alarm` и `Error` окажутся суммарно не менее трех исходных алертов.

  1. (Опционально) Настройте дополнительные условия:

      * **Форсировать статус композита в No Data** — если хотя бы один исходный алерт находится в статусе `No Data`, композитный алерт перейдет в статус `No Data`. Используйте настройку, если потеря данных по одному критичному источнику важнее остальных условий.
      * **Форсировать статус композита в Error** — если хотя бы один исходный алерт находится в статусе `Error`, композитный алерт перейдет в статус `Error`. Это помогает не скрыть ошибку вычисления исходного алерта.
      * **Приравнивать замьюченные алерты к статусу Ok** — алерты, добавленные в [мьют](../../alerts/mutes.md), будут считаться алертами в статусе `Ok`. Используйте настройку для плановых работ, чтобы мьют одного исходного алерта не повышал статус композита.

  1. (Опционально) Укажите [аннотации](../../concepts/alerting/annotation.md) к алерту.

      Можно добавить новые аннотации или выбрать заданные в исходных алертах.

  1. (Опционально) Для сортировки и поиска алертов добавьте лейблы в формате `ключ=значение`.

      Можно добавить несколько лейблов. Для этого после ввода пары `ключ=значение` нажмите клавишу **Enter**. Чтобы использовать лейблы в другом алерте или в строке поиска, нажмите кнопку **Скопировать все лейблы**.

  1. (Опционально) В блоке **Ссылки** добавьте ссылки на связанные ресурсы.
  1. Настройте [уведомления](../../concepts/alerting/notification-channel.md). Если у вас нет канала уведомлений, [создайте его](create-channel.md).

      Чтобы не получать уведомление при каждой смене статуса, включите **Подавление шума**. Используйте настройку, если исходные алерты часто меняют статус около порога композита. Подробнее о подавлении шума в разделе [Подавление шума](../../concepts/alerting/alert.md#noise-suppression).

  1. Проверьте результат вычисления алерта.

      Вверху справа нажмите **Проверить результат**. Monium пересчитает алерт по текущим настройкам и покажет вычисленный статус, график и значения переменных.
      
      Используйте проверку, чтобы убедиться, что запросы возвращают данные, а пороги и политики отсутствия данных работают, как ожидается.

  1. Нажмите **Создать**. Алерт появится в списке.
