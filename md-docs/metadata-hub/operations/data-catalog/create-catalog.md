# Создание каталога


{% note info %}

Эта функциональность находится на стадии [Preview](../../../overview/concepts/launch-stages.md).

{% endnote %}


{% list tabs group=instructions %}

- Консоль управления {#console}

    1. В [консоли управления](https://console.yandex.cloud) выберите [каталог ресурсов](../../../resource-manager/concepts/resources-hierarchy.md#folder), в котором нужно создать каталог метаданных.
    1. [Перейдите](https://console.yandex.cloud/link/metadata-hub) в сервис **Yandex MetaData Hub**.
    1. В блоке **Управляйте метаданными** выберите **Data Catalog**.
    1. Нажмите кнопку **Создание каталога**.
    1. Задайте параметры каталога:

       * В поле **Имя** задайте уникальное имя каталога.
       * (Опционально) Добавьте описание каталога.
       * (Опционально) Добавьте [метки Yandex Cloud](../../../resource-manager/concepts/labels.md).

    1. Нажмите кнопку **Создать**.

    {% note info %}
    
    При создании каталога метаданных опция **AI-разметка метаданных** включена по умолчанию.
    
    Когда опция включена, AI-ассистент предлагает описания, [домены](*домен), [классификации](*классификация) и [теги](*тег), [глоссарии](*глоссарий) и [термины](*термин), а также размечает с их помощью ваши метаданные. Предложения ассистента можно подтвердить, отредактировать или отклонить. Для этого наведите курсор на значок **AI** рядом с предложением ассистента и выберите нужное действие.
    
    После создания каталога AI-разметкой можно управлять на странице **Обзор** или при [изменении](update-catalog.md) каталога.
    
    {% endnote %}

- Terraform {#tf}

  [Terraform](https://www.terraform.io/) позволяет быстро создать облачную инфраструктуру в Yandex Cloud и управлять ею с помощью файлов конфигураций. В файлах конфигураций хранится описание инфраструктуры на языке HCL (HashiCorp Configuration Language). При изменении файлов конфигураций Terraform автоматически определяет, какая часть вашей конфигурации уже развернута, что следует добавить или удалить.
  
  Terraform распространяется под лицензией [Business Source License](https://github.com/hashicorp/terraform/blob/main/LICENSE), а [провайдер Yandex Cloud для Terraform](https://github.com/yandex-cloud/terraform-provider-yandex) — под лицензией [MPL-2.0](https://www.mozilla.org/en-US/MPL/2.0/).
  
  Подробная информация о ресурсах провайдера в документации на сайте [Terraform](https://www.terraform.io/docs/providers/yandex/index.html) или в [зеркале](../../../terraform/index.md).

  Если у вас еще нет Terraform, [установите его и настройте провайдер Yandex Cloud](../../../tutorials/infrastructure-management/terraform-quickstart.md#install-terraform).
  
  
  Чтобы управлять инфраструктурой с помощью Terraform от имени сервисного аккаунта или пользовательских аккаунтов: аккаунта на Яндексе, федеративного аккаунта и локального пользователя, [аутентифицируйтесь](../../../terraform/authentication.md) соответствующим способом.

  1. Добавьте в конфигурационный файл описание каталога:

     ```hcl
     resource "yandex_datacatalog_catalog" "example" {
       folder_id   = "<идентификатор_каталога_ресурсов>"
       name        = "<имя_каталога_метаданных>"
       description = "<описание>"
       labels = {
         environment = "production"
       }
     }
     ```

     Укажите идентификатор каталога ресурсов Yandex Cloud в `folder_id` и имя создаваемого каталога метаданных в `name`. При необходимости задайте описание в `description` и метки в `labels`.

     Подробная информация о параметрах ресурса `yandex_datacatalog_catalog` приведена в [документации провайдера](../../../terraform/resources/datacatalog_catalog.md).

  1. Проверьте план изменений и примените его:

     1. В терминале перейдите в директорию с конфигурационным файлом.
     1. Проверьте корректность конфигурации с помощью команды:
     
        ```bash
        terraform validate
        ```
     
        Если конфигурация является корректной, появится сообщение:
     
        ```bash
        Success! The configuration is valid.
        ```
     
     1. Выполните команду:
     
        ```bash
        terraform plan
        ```
     
        В терминале будет выведен список планируемых изменений: ресурсы и/или выходные переменные. На этом этапе изменения не будут внесены. Если в конфигурации есть ошибки, Terraform на них укажет.
     1. Примените изменения конфигурации:
     
        ```bash
        terraform apply
        ```
     
     1. Подтвердите изменения: введите в терминале слово `yes` и нажмите **Enter**.

- API {#api}

    [Пройдите аутентификацию](../../api-ref/authentication-datacatalog.md). Воспользуйтесь методом REST API [createCatalog](../../datacatalog/api-ref/Catalog/createCatalog.md) для ресурса [Catalog](../../datacatalog/api-ref/Catalog/index.md) или вызовом gRPC API [CatalogService/CreateCatalog](../../datacatalog/api-ref/grpc/Catalog/createCatalog.md).

    Передайте в объекте `catalog` идентификатор каталога ресурсов в `folderId`, имя каталога метаданных в `name` и при необходимости `description` и `labels`. Пример тела REST-запроса:

    ```json
    {
      "catalog": {
        "folderId": "<идентификатор_каталога_ресурсов>",
        "name": "<имя_каталога_метаданных>",
        "description": "<описание>",
        "labels": {"environment": "production"}
      }
    }
    ```

    В gRPC идентификатор каталога ресурсов передается в `catalog.folder_id`.

[*глоссарий]: #### {#catalog}
              
              Каталог метаданных — основная сущность сервиса Data Catalog. Одновременно является местом сбора и хранения метаданных из различных источников и рабочим пространством для их разметки. Подробнее в разделе [Каталог метаданных](../../concepts/data-catalog.md).
              
              #### {#ingestion}
              
              Загрузка — процесс, который подключается к указанному в источнике хранилищу данных или сервису и загружает его метаданные в каталог. Загрузку можно запускать вручную или по расписанию. Подробнее в разделе [Загрузка метаданных](../../concepts/data-catalog.md#metadata-upload).
              
              #### {#source}
              
              Источник — подключение, через которое загружаются метаданные. В подключении хранится информация о БД или другом сервисе, из которого загружаются метаданные, а также данные для аутентификации. Подробнее в разделе [Загрузка метаданных](../../concepts/data-catalog.md#metadata-upload).
              
              #### {#data-store}
              
              Хранилище данных (data store) — сущность, которая объединяет метаданные источников, относящихся к одному кластеру управляемых баз данных или к одной пользовательской инсталляции базы данных. Подробнее в разделе [Хранилище данных](../../concepts/data-catalog.md#data-store).
              
              #### {#domain}
              
              Домен — группа метаданных для первичного распределения по потребностям рабочего процесса, например по принадлежности к отделу компании или направлению бизнеса. Для каждого домена можно создать поддомен. Подробнее в разделе [Домены и поддомены](../../concepts/data-catalog.md#domains-and-subdomains).
              
              #### {#subdomain}
              
              Поддомен — вложенная группа метаданных внутри домена, которая позволяет более гранулярно распределить метаданные. Подробнее в разделе [Домены и поддомены](../../concepts/data-catalog.md#domains-and-subdomains).
              
              #### {#classification}
              
              Классификация — группа тегов, которые используются для разметки метаданных. Подробнее в разделе [Классификации и теги](../../concepts/data-catalog.md#classifications-and-tags).
              
              #### {#tag}
              
              Тег — метка, которая используется для разметки метаданных по их типам, например чувствительные данные или характеристики таблиц. Подробнее в разделе [Классификации и теги](../../concepts/data-catalog.md#classifications-and-tags).
              
              #### {#glossary}
              
              Глоссарий — словарь узкоспециализированных терминов для определенной отрасли с толкованием этих терминов. Позволяет сформировать в компании единое понимание общей терминологии. Подробнее в разделе [Глоссарии и термины](../../concepts/data-catalog.md#glossaries-and-terms).
              
              #### {#term}
              
              Термин — понятие, которое используется для разметки данных по их семантическому значению в рамках бизнеса, например «выручка» или «расходы». Подробнее в разделе [Глоссарии и термины](../../concepts/data-catalog.md#glossaries-and-terms).

           #### {#domain}
           
           Домен — группа метаданных для первичного распределения по потребностям рабочего процесса, например по принадлежности к отделу компании или направлению бизнеса. Для каждого домена можно создать поддомен. Подробнее в разделе [Домены и поддомены](../../concepts/data-catalog.md#domains-and-subdomains).
           
           #### {#subdomain}
           
           Поддомен — вложенная группа метаданных внутри домена, которая позволяет более гранулярно распределить метаданные. Подробнее в разделе [Домены и поддомены](../../concepts/data-catalog.md#domains-and-subdomains).
           
           #### {#classification}
           
           Классификация — группа тегов, которые используются для разметки метаданных. Подробнее в разделе [Классификации и теги](../../concepts/data-catalog.md#classifications-and-tags).
           
           #### {#tag}
           
           Тег — метка, которая используется для разметки метаданных по их типам, например чувствительные данные или характеристики таблиц. Подробнее в разделе [Классификации и теги](../../concepts/data-catalog.md#classifications-and-tags).
           
           #### {#glossary}
           
           Глоссарий — словарь узкоспециализированных терминов для определенной отрасли с толкованием этих терминов. Позволяет сформировать в компании единое понимание общей терминологии. Подробнее в разделе [Глоссарии и термины](../../concepts/data-catalog.md#glossaries-and-terms).
           
           #### {#term}
           
           Термин — понятие, которое используется для разметки данных по их семантическому значению в рамках бизнеса, например «выручка» или «расходы». Подробнее в разделе [Глоссарии и термины](../../concepts/data-catalog.md#glossaries-and-terms).
