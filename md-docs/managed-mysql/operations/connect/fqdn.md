# FQDN хостов MySQL®

Для подключения к хосту потребуется его [FQDN](../../concepts/network.md#hostname) — доменное имя. Вы можете использовать [FQDN конкретного хоста](#get-fqdn) в кластере или один из особых FQDN, всегда указывающий на [текущий хост-мастер](#fqdn-master) или [наименее отстающую реплику](#fqdn-replica).

Пример FQDN хоста:

```text
rc1a-goh2a9tr********.mdb.yandexcloud.net
```

Помимо обычных FQDN, для подключения к кластеру можно использовать [особые FQDN](#special-fqdns) и [алиасы](#aliases).

## Получить FQDN хоста {#get-fqdn}

FQDN хоста MySQL® можно получить несколькими способами:

* Посмотрите FQDN в консоли управления:

    1. Перейдите на страницу кластера.
    1. Перейдите в раздел **Хосты**.
    1. Скопируйте значение в столбце **FQDN хоста**.

* Скопируйте команду для подключения к кластеру в [консоли управления](https://console.yandex.cloud). Команда содержит заполненный FQDN хоста. Чтобы получить команду, перейдите на страницу кластера и нажмите кнопку **Подключиться**.

* [Запросите список хостов в кластере](../hosts.md#list) с помощью CLI или API.

## Особые FQDN {#special-fqdns}

Managed Service for MySQL® предоставляет следующие особые FQDN:
* [FQDN текущего мастера](#fqdn-master);
* [FQDN наименее отстающей реплики](#fqdn-replica).

В кластерах из нескольких хостов особые FQDN могут некоторое время указывать на старый хост, даже если он сменил роль (например, из мастера стал репликой). Если используется особый FQDN, который указывает на текущий мастер, то часть запросов на запись может завершиться неудачей — они могут быть направлены к реплике. Это связано с тем, что на обновление DNS-записей для особых FQDN требуется время. Если запрос на запись завершился ошибкой, повторите его позднее.

{% note warning %}

Если при [автоматической смене мастера](../../concepts/replication.md#master-failover) новым мастером или наименее отстающей репликой станет хост без публичного доступа, подключиться к такому хосту из интернета будет невозможно. Чтобы этого избежать, [включите публичный доступ](../hosts.md#update) для всех хостов кластера.

{% endnote %}

### Текущий мастер {#fqdn-master}

FQDN вида `c-<идентификатор_кластера>.rw.mdb.yandexcloud.net` всегда указывает на текущий хост-мастер в кластере. Идентификатор кластера можно получить со [списком кластеров в каталоге](../cluster-list.md#list-clusters).

При подключении к этому FQDN разрешено выполнять операции чтения и записи.

{% note tip %}

Чтобы уменьшить задержки и минимизировать потенциальные проблемы при смене первичной реплики, рекомендуем самостоятельно определять первичную реплику, например с помощью [Sentinel](../../../managed-valkey/operations/connect/clients.md#redis-sentinel).

{% endnote %}

### Наименее отстающая реплика {#fqdn-replica}

FQDN вида `c-<идентификатор_кластера>.ro.mdb.yandexcloud.net` указывает на наименее отстающую от мастера [реплику](../../concepts/replication.md). Идентификатор кластера можно запросить со [списком кластеров в каталоге](../cluster-list.md#list-clusters).

**Особенности:**

* При подключении к этому FQDN разрешено выполнять только операции чтения.
* Если в кластере нет активных реплик, то подключиться к этому FQDN невозможно: соответствующая CNAME-запись в [DNS](../../../glossary/dns.md) будет указывать на пустой объект (`null`).

## Алиасы {#aliases}

Алиасы позволяют обращаться к мастеру, наименее отстающей реплике, а также к каждому конкретному хосту кластера Managed Service for MySQL® по стабильному человекочитаемому имени, независимо от внутренних FQDN. Алиасы задаются пользователем и могут использоваться наравне с обычными и [особыми FQDN](#special-fqdns).

### Алиас кластера {#cluster-alias}

Алиас кластера всегда указывает на текущий хост-мастер в кластере Managed Service for MySQL®. Имеет следующий вид:

```
c-<краткое_имя>-my-<идентификатор_каталога>.rw.mdb.yandexcloud.net
```

Где `<краткое_имя>` — условное имя, которое задается пользователем при формировании алиаса.

Алиас кластера должен быть уникальным в рамках каталога. Для каждого кластера можно назначить только один алиас.

Алиасы кластеров позволяют переключить нагрузку с одного кластера на другой, например после восстановления из бэкапа. Для переключения достаточно переместить алиас между кластерами. При этом вносить изменения на стороне приложения не требуется.

{% note warning %}

После [переключения мастера](../../concepts/replication.md#master-failover) может потребоваться до 10 минут на обновление DNS-записей. В течение этого времени алиас кластера может указывать на старый хост, который уже стал репликой. Используйте алиас кластера только для процессов, которые допускают недоступность базы данных на запись продолжительностью до 10 минут.

{% endnote %}


### Алиасы хостов {#hosts-aliases}

Алиас, указывающий на конкретный хост в кластере, имеет следующий вид:

```
h-<краткое_имя_хоста>-my-<идентификатор_каталога>.mdb.yandexcloud.net
```

Где `<краткое_имя_хоста>` — условное имя, которое задается пользователем при формировании алиаса хоста.

Алиас хоста должен быть уникальным в рамках каталога. Для каждого хоста можно назначить только один алиас.
