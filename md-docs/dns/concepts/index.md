# Концепции Cloud DNS

Yandex Cloud DNS — это сервис, который берет на себя обслуживание DNS-запросов и упрощает администрирование [DNS](../../glossary/dns.md) (Domain Name System).

С помощью Cloud DNS вы можете:

* Создавать [зоны DNS](dns-zone.md) в иерархии DNS. Публичные зоны позволяют использовать доменные имена для сайтов и сервисов в интернете. Внутренние зоны помогают организовать пространство имен облачных ресурсов в выбранных сетях, например для рабочей и тестовой сред.

* Управлять [ресурсными записями](resource-record.md) в созданных зонах. Записи связывают доменные имена с IP-адресами ресурсов и задают другие параметры работы домена. Например, вы можете привязать домен к IP-адресу веб-сервера, настроить псевдоним или указать почтовые серверы домена.

* Настраивать [фильтрацию DNS-запросов](dns-filter.md) от облачных ресурсов. С помощью разрешающих и запрещающих списков вы контролируете разрешение доменных имен через облачный DNS-резолвер. Это помогает блокировать DNS-запросы к фишинговым и вредоносным сайтам или ограничивать запросы в изолированном окружении только доверенными доменами.

* Настраивать [DNS-подключения](dns-connection.md) для корпоративной сети и серверов [Yandex BareMetal](../../baremetal/index.md). Это позволяет приложениям обращаться по именам к облачным ресурсам во внутренних зонах DNS, например к виртуальным машинам и кластерам управляемых баз данных. Для этого корпоративная сеть или приватная подсеть BareMetal должна быть связана с облачной сетью через [Yandex Cloud Interconnect](../../interconnect/index.md).

## Как работает Cloud DNS {#how-it-works}

Cloud DNS обрабатывает DNS-запросы двух типов: к [публичным](dns-zone.md#public-zones) и [внутренним](dns-zone.md#private-zones) доменным зонам.

1. Вы создаете публичную или внутреннюю зону DNS. В публичной зоне доменные имена доступны из интернета. Во внутренней зоне имена доступны из привязанных сетей [Yandex Virtual Private Cloud](../../vpc/index.md), а при настроенном [входящем DNS-подключении](dns-connection.md#dns-inbound) — также из корпоративной сети и с серверов BareMetal, связанных с облачной сетью через Cloud Interconnect.
1. В созданной зоне вы добавляете [ресурсные записи](resource-record.md). Записи связывают доменные имена с IP-адресами, псевдонимами или другими ресурсами.
1. Серверы обрабатывают DNS-запрос к доменному имени из вашей зоны:

   1. Для публичных зон запрос обрабатывают серверы имен Yandex Cloud (`ns1.yandexcloud.net.` и `ns2.yandexcloud.net.`). Чтобы серверы стали авторитетными для вашего домена, делегируйте его. Для этого укажите адреса серверов имен Yandex Cloud в [NS-записях](resource-record.md#ns) у вашего регистратора.
   1. Для внутренних зон запросы обрабатывает облачный [DNS-резолвер](dns-resolver.md). За ним зарезервирован второй IP-адрес диапазона [подсети](*subnet) (например, `x.x.x.2`). Этот адрес по умолчанию передается [виртуальной машине](*vm) (ВМ) по протоколу DHCP.

Если в облаке нет пользовательских зон, кроме сервисных, Cloud DNS все равно обрабатывает публичные DNS-запросы от облачных ресурсов, например от ВМ к внешним доменам.

Для снижения количества публичных DNS-запросов и уменьшения расходов используйте [кеширующие резолверы](../tutorials/local-dns-cache.md), например `systemd-resolved`, `dnsmasq` или `unbound`.

## Интеграция с Compute Cloud {#compute-integration}

При создании ВМ в сервисе [Yandex Compute Cloud](../../compute/index.md) вы можете назначать им доменные имена ([FQDN](*hostname)) и автоматически добавлять ВМ в зоны DNS.

Если при создании ВМ указать зону и доменное имя в настройках DNS, в этой зоне появится соответствующая ресурсная запись. Если при заданном FQDN не указать зону явно, она будет [выбрана автоматически](compute-integration.md#zone-selection).

Подробнее в разделе [Интеграция с Compute Cloud](compute-integration.md).

## Основные понятия сервиса {#service-concepts}

В сервисе Cloud DNS используются следующие основные понятия:

* [Зона DNS](dns-zone.md) — логическое пространство, которое объединяет доменные имена ресурсов и содержит ресурсные записи. Зоны бывают публичными, внутренними и обратными.
* [Ресурсная запись](resource-record.md) — главная единица информации в DNS. С помощью ресурсных записей вы определяете, куда направлять запросы, поступающие на определенные доменные имена.
* [Фильтр DNS](dns-filter.md) — инструмент для контроля и фильтрации исходящих DNS-запросов от облачных ресурсов с помощью списков FQDN.
* [DNS-резолвер](dns-resolver.md) — DNS-сервер в инфраструктуре Yandex Cloud, который обрабатывает DNS-запросы от ресурсов в облачных сетях Virtual Private Cloud и разрешает доменные имена во внутренних зонах DNS.
* [DNS-подключение](dns-connection.md) — ресурс для разрешения доменных имен во внутренних зонах DNS Yandex Cloud из корпоративной сети и с серверов BareMetal.
* [Квоты и лимиты](limits.md) — ограничения на использование сервиса.

Ознакомьтесь также с [общей иерархией ресурсов](../../resource-manager/concepts/resources-hierarchy.md) Yandex Cloud.
