# Репликация в Yandex StoreDoc

Репликация в кластере Yandex StoreDoc включается при наличии двух и более [нескрытых](../operations/hosts.md#update) хостов. Каждый хост-реплика хранит копию одного и того же набора данных.

Виды реплик в кластере Yandex StoreDoc:
* _Первичная реплика (мастер)_ — автоматически выбирается среди нескрытых хостов и принимает все запросы на запись.
* _Вторичные реплики_ — асинхронно копируют все изменения на мастере. 

Запросы на чтение могут обрабатываться как на вторичных репликах, так и на мастере, в зависимости от [параметра подключения `readPreference`](../operations/connect/clients.md).

## Смена мастера {#master-failover}

При выходе из строя или [ручном переключении](../operations/stepdown.md) мастера Yandex StoreDoc автоматически выберет новый мастер из нескрытых хостов.

Повлиять на выбор мастера в кластере Yandex StoreDoc можно с помощью [настройки приоритетов](../operations/hosts.md#update) для хостов кластера. Новым мастером станет хост с наибольшим приоритетом.

Задать приоритет хоста можно с помощью YC CLI, API или Terraform:

* при [создании кластера](../operations/cluster-create.md) или [хоста в кластере](../operations/hosts.md#add);
* при [изменении настроек хоста](../operations/hosts.md#update).

Значение приоритета по умолчанию — `1`, соответствует наименьшему приоритету. Минимальное значение — `0`. Хост с таким приоритетом не может стать мастером, даже если в кластере нет других подходящих хостов. Максимальное значение — `1000`. Доступны только целочисленные значения.
