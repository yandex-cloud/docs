# Концепции Cloud Quota Manager

{% note info %}

Для работы с запросами на изменение квот через CLI и API обратитесь в [службу поддержки](https://center.yandex.cloud/support).

{% endnote %}

В Yandex Cloud действуют квоты и лимиты на использование ресурсов. Сервис Cloud Quota Manager позволяет управлять квотами с помощью различных интерфейсов. Некоторые сервисы, например SpeechKit, в Quota Manager недоступны.

**Квоты** — ограничения на использование ресурсов в облаке или организации. Квоты можно изменить по запросу. Они помогают контролировать потребление ресурсов, избегать перерасхода и планировать бюджет.

При работе с квотами используются понятия:

* **Значение квоты** или просто **квота** (quota limit) — текущее ограничение на ресурс для облака или организации.

* **Потребление квоты** (quota usage) — объем фактически используемого ресурса.

Например, при значении квоты 12 в облаке можно использовать не более 12 виртуальных машин (ВМ). Потребление квоты равно количеству ВМ в облаке. Чтобы использовать 25 ВМ, увеличьте значение квоты как минимум до 25.

_Лимиты_ — технические ограничения, обусловленные особенностями архитектуры Yandex Cloud, физическими характеристиками оборудования или внешними ограничениями. Например, лимиты в сервисе Certificate Manager определяются правилами выдачи сертификатов Let's Encrypt.

Взаимосвязь квот и лимитов показана на схеме ниже.

![image](../../_assets/quota-manager/quotas-limits.svg)

В большинстве сервисов квоты действуют на уровне облака. В Resource Manager, Cloud Video и некоторых других сервисах квоты действуют на уровне организации. В IAM есть квоты обоих уровней.

Интерфейсы управления квотами:
* [Cloud Center](https://center.yandex.cloud/quotas) — уровень организации;
* [консоль управления](https://console.yandex.cloud/cloud?section=quotas) — уровень облака;
* [CLI](../cli-ref/index.md) и [API](../api-ref/authentication.md) — уровень организации и облака.

С помощью API Cloud Quota Manager можно отслеживать значения и потребление квот и настроить оповещения о достижении пороговых значений. Это поможет вовремя запросить увеличение квот или предотвратить перерасход ресурсов.

## Выделение квот {#quotas-allocation}

При создании облака автоматически устанавливаются значения квот по умолчанию. После изменения квоты сброс к начальному значению не предусмотрен.

Для некоторых ресурсов значение квоты не устанавливается. В консоли для таких ресурсов отображается **Квота не выделена**.

Квоты можно увеличить по запросу в пределах лимитов — технических ограничений платформы. Выделенные квоты не гарантируют наличие свободных ресурсов.

Управление квотами через CLI и API выполняется по идентификатору квоты, который имеет вид `<имя_сервиса>.<имя_ресурса>.<единица_измерения>`. Например: `dns.zones.count`, `serverless.networkPackets.rate`, `mdb.memory.size`. 

Идентификаторы квот и их значения по умолчанию для поддерживаемых сервисов Yandex Cloud приведены в разделе [Квоты для сервисов Yandex Cloud](../all-quotas.md).

Потребление квот можно узнать в консоли на странице сервиса [Cloud Quota Manager](https://console.yandex.cloud/cloud?section=quotas) или с помощью [запроса API](../operations/list-quotas.md).

## Зачем нужны квоты {#quotas-need}

Квоты помогают контролировать потребление облачных сервисов. Например, они не позволяют новым пользователям занять слишком много ресурсов при тестировании.

## Типы ресурсов {#resources-types}

Квоты в Yandex Cloud привязаны к ресурсам. При выполнении команды CLI или запроса API укажите тип ресурса:

* `resource-manager.cloud` — [облако](../../resource-manager/concepts/resources-hierarchy.md#cloud);
* `organization-manager.organization` — [организация](../../organization/concepts/organization.md);
* `billing.account` — [платежный аккаунт](../../billing/concepts/billing-account.md).
