# Выделенные IP-адреса

{% note info %}

Функциональность находится на стадии [Preview](../../overview/concepts/launch-stages.md).

{% endnote %}

Выделенный IP-адрес — это IP-адрес, который Yandex Cloud Postbox использует для отправки писем в одном пользовательском облаке. В отличие от общих IP-адресов сервиса, репутация выделенного IP-адреса зависит только от трафика пользователя.

Выделенные IP-адреса объединяются в [пулы](#pools), которые можно [привязывать](#binding) к [конфигурациям](configuration.md).

Выделенные IP-адреса выдаются облаку по запросу. Чтобы получить их, обратитесь в [техническую поддержку](https://center.yandex.cloud/support).

## Пулы IP-адресов {#pools}

Пул — это именованная группа выделенных IP-адресов. Один выделенный IP-адрес в каждый момент времени может находиться только в одном пуле.

У пула есть режим масштабирования (`ScalingMode`). В Yandex Cloud Postbox поддерживается только режим масштабирования `STANDARD`.

## Зарезервированные пулы {#reserved-pools}

Следующие пулы зарезервированы сервисом:

#|
|| **Имя** | **Описание** ||
|| `ses-default-dedicated-pool` | Пул по умолчанию. В нем находятся все выданные облаку выделенные IP-адреса, которые не распределены по пользовательским пулам. ||
|| `ses-shared-pool` | Общий пул IP-адресов сервиса. ||
|#

Использовать эти имена для пользовательских пулов нельзя. Получить информацию о зарезервированных пулах методом [GetDedicatedIpPool](../aws-compatible-api/api-ref/get-dedicated-ip-pool.md) тоже нельзя, и в выдаче метода [ListDedicatedIpPools](../aws-compatible-api/api-ref/list-dedicated-ip-pools.md) они не отображаются.

## Привязка пула к конфигурации {#binding}

Пул привязывается к конфигурации через параметр `SendingPoolName` в настройках доставки конфигурации. Задать этот параметр можно с помощью двух методов:

* [CreateConfigurationSet](../aws-compatible-api/api-ref/create-configuration-set.md) — в блоке `DeliveryOptions` при создании конфигурации;
* [PutConfigurationSetDeliveryOptions](../aws-compatible-api/api-ref/put-configuration-set-delivery-options.md) — для уже существующей конфигурации.

{% note warning %}

Метод `PutConfigurationSetDeliveryOptions` полностью обновляет настройки доставки конфигурации. Если при вызове не указать `SendingPoolName`, пул отвяжется от конфигурации, и письма станут отправляться с общих IP-адресов сервиса.

{% endnote %}

{% note info %}

Пул, привязанный к [конфигурации](configuration.md), нельзя удалить. Сначала отвяжите пул от всех конфигураций, к которым он привязан.

Пул можно удалить, даже если в нем есть выделенные IP-адреса: при удалении пула все IP-адреса автоматически перемещаются в пул по умолчанию `ses-default-dedicated-pool`.

{% endnote %}

## Отправка писем через пул {#sending}

Если пул привязан к конфигурации, все письма, к которым она применяется, отправляются с IP-адресов привязанного пула. Это позволяет разделить потоки писем: например, отправлять транзакционные письма с одного пула, а рассылки — с другого.

{% note warning %}

Если к конфигурации привязан пул, в котором нет ни одного выделенного IP-адреса, письма с этой конфигурацией не отправляются: метод [SendEmail](../aws-compatible-api/api-ref/send-email.md) возвращает ошибку `404 NotFoundException`. Автоматического переключения на общий пул IP-адресов сервиса не происходит.

{% endnote %}

Как только в пуле появляется хотя бы один выделенный IP-адрес, письма с этой конфигурацией начинают отправляться автоматически.

## Прогрев IP-адресов {#warmup}

Yandex Cloud Postbox не управляет прогревом выделенных IP-адресов: IP-адреса готовы к отправке сразу после выдачи. Поля `WarmupStatus` и `WarmupPercentage` всегда возвращают значения `DONE` и `100` и присутствуют в ответе для совместимости с AWS SDK.
