# Приостановить или возобновить кластер Apache Airflow™

Приостановка останавливает основные компоненты Apache Airflow™. Конфигурация кластера, база метаданных, бакеты и учетные данные сохраняются.

Если нужно приостановить расписание одного DAG, используйте [переключатель в веб-интерфейсе Apache Airflow™](run-dag.md#pause-dag). Приостановка всего кластера также делает его веб-интерфейс недоступным.

Еженедельная [очистка метаданных старше 90 дней](../../concepts/components/airflow.md#metadata-retention) продолжается и во время приостановки.

{% note warning %}

Приостановка завершает работающие поды основных компонентов. Не используйте ее во время выполнения важных задач.

{% endnote %}

## Приостановка кластера {#pause}

### Через консоль управления {#pause-console}

1. В консоли управления Stackland выберите проект и пространство имен.
1. В левом меню выберите **Кластеры Airflow**. Если пункт скрыт, раскройте **Ещё**. Откройте нужный кластер.
1. Нажмите **Приостановить** и подтвердите действие.
1. Дождитесь состояния `Paused`.

### Через CLI {#pause-cli}

1. Установите `spec.pause: true`:

    ```bash
    kubectl patch airflowcluster <имя_кластера> \
      -n <пространство_имен> \
      --type=merge \
      -p '{"spec":{"pause":true}}'
    ```

1. Дождитесь состояния `Paused`:

    ```bash
    kubectl get airflowcluster <имя_кластера> \
      -n <пространство_имен> \
      -w
    ```

## Возобновление кластера {#resume}

### Через консоль управления {#resume-console}

1. В консоли управления Stackland выберите проект и пространство имен.
1. В левом меню выберите **Кластеры Airflow**. Если пункт скрыт, раскройте **Ещё**. Откройте приостановленный кластер.
1. Нажмите **Возобновить** и подтвердите действие.
1. Дождитесь состояния `Ready`. После этого можно снова [открыть веб-интерфейс Apache Airflow™](connect-ui.md#console).

### Через CLI {#resume-cli}

1. Установите `spec.pause: false`:

    ```bash
    kubectl patch airflowcluster <имя_кластера> \
      -n <пространство_имен> \
      --type=merge \
      -p '{"spec":{"pause":false}}'
    ```

1. Дождитесь состояния `Ready`:

    ```bash
    kubectl get airflowcluster <имя_кластера> \
      -n <пространство_имен> \
      -w
    ```

После возобновления планировщик снова обрабатывает DAG-файлы. Проверьте расписания и состояние задач в веб-интерфейсе.
