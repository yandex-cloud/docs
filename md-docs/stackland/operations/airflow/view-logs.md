# Посмотреть результаты и логи задач Apache Airflow™

Инструкция описывает веб-интерфейс Apache Airflow™ 3.1.8. Перед началом [запустите DAG](run-dag.md).

## Открыть результат запуска {#run-result}

1. [Откройте веб-интерфейс Apache Airflow™](connect-ui.md), перейдите в **Dags** и выберите DAG.
1. На вкладке **Runs** выберите нужный запуск по времени и идентификатору.
1. Проверьте состояние запуска и его задач. Для просмотра зависимостей используйте **Graph**, для сравнения задач в разных запусках — **Grid**.

Проверяйте состояния отдельных задач, даже если запуск завершился с `success`: итоговое состояние зависит от конечных задач и их правил запуска. Подробнее — в [документации Apache Airflow™](https://airflow.apache.org/docs/apache-airflow/3.1.8/core-concepts/dag-run.html#dag-run-status).

## Прочитать логи задачи {#task-logs}

1. В выбранном запуске откройте нужную задачу и вкладку **Logs**.
1. Если задача выполнялась повторно, выберите нужную попытку. У каждой попытки свой лог.
1. Найдите сообщение об ошибке или ожидаемый результат. Для задачи `greet` из [примера](upload-dags.md#prepare-dag) в логе должно быть `Hello from Airflow!`.

Возвращенное значение задачи доступно на вкладке **XCom**. Для `greet` это строка `Hello from Airflow!`.

Описание вкладок приведено в [обзоре интерфейса Apache Airflow™](https://airflow.apache.org/docs/apache-airflow/3.1.8/ui.html#task-instance-tabs), а выбор попыток — в [описании истории задачи](https://airflow.apache.org/docs/apache-airflow/3.1.8/core-concepts/dag-run.html#task-instance-history).

После устранения причины ошибки можно [повторить задачу](run-dag.md#rerun-task). Если она еще не начала выполняться, воспользуйтесь [диагностикой ожидания](troubleshooting.md#task-waiting).

## Если лог недоступен {#missing-logs}

Проверьте выбранные запуск, задачу и попытку. У задачи, которая еще не начала выполняться, лог может отсутствовать.

Затем в консоли управления Stackland откройте карточку кластера Apache Airflow™ и проверьте раздел **Логи задач** на вкладке **Основное**:

* При локальном хранении логи могут быть утрачены после пересоздания или удаления пода. Для последующих запусков [включите удаленное хранение](edit-cluster.md#console).
* При удаленном хранении проверьте бакет, путь и права на запись и чтение логов. Сообщение об ошибке подключения в **Logs** поможет определить причину.

Изменение способа хранения не переносит уже записанные логи. Включайте удаленное хранение до запуска задач, логи которых нужно сохранить. Подробнее — в разделе [Логи задач](../../concepts/components/airflow.md#task-logs).
