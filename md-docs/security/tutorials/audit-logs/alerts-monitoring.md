# Настройка дашбордов и алертов в Yandex Monium

В руководстве описано, как отслеживать состояние [трейлов](../../../audit-trails/concepts/trail.md) с помощью [дашбордов](../../../monium/concepts/visualization/dashboard.md) и [алертов](../../../monium/concepts/alerting/alert.md) [Yandex Monium](../../../monium/index.md).

Руководство предполагает, что у вас уже развернута инфраструктура:

* Есть ресурсы Yandex Cloud, события безопасности которых нужно собирать.
* Создан [трейл](../../../audit-trails/concepts/trail.md) Audit Trails для сбора событий.
* Настроен [объект назначения](../../../audit-trails/concepts/trail.md#target) для хранения аудитных логов: [бакет](../../../storage/concepts/bucket.md), [поток данных](../../../data-streams/concepts/glossary.md#stream-concepts) или [лог-группа](../../../logging/concepts/log-group.md).

Чтобы начать отслеживать статус трейлов:

* [Настройте алерты](#setup-alerts).
* [Настройте дашборд](#setup-dashboard).

Если ресурсы вам больше не нужны, [удалите их](#clear-out).

## Настройте алерты {#setup-alerts}

Выберите [проект Monium](../../../monium/collector/project.md) для каталога, в котором находится трейл: `folder__<идентификатор_каталога>`. В этом проекте доступны метрики трейла и квоты трейлов на облако — `quota.trails_count.usage` и `quota.trails_count.limit`. Канал уведомлений и алерты создавайте в этом же проекте.

### Создайте канал уведомлений {#create-channel}

Чтобы получать уведомления о срабатывании алерта:

{% list tabs group=instructions %}

- Интерфейс Monium {#console}

  1. Перейдите на главную страницу [Monium](https://monium.yandex.cloud).
  1. В верхней панели нажмите название текущего проекта и выберите проект каталога с трейлом.
  1. На панели слева выберите ![alt](../../../_assets/console-icons/shield-exclamation.svg) **Алерты и SLO** → ![alt](../../../_assets/console-icons/bell.svg) **Способы уведомления**.
  1. В правом верхнем углу нажмите кнопку **Создать** и выберите **Канал уведомления**.
  1. Укажите параметры канала:
     * В поле **Имя** укажите `alerts-channel`.
     * В поле **Метод** выберите метод уведомлений и заполните его параметры.
     * В поле **По умолчанию для уровней** оставьте все уровни невыбранными: далее вы подключите канал к конкретным алертам.
  1. Нажмите кнопку **Сохранить**.

{% endlist %}

Канал появится в списке.

### Добавьте алерты {#add-alerts}

Вы можете настроить один или несколько алертов.

Подробнее о [создании алерта](../../../monium/operations/alert/create-alert.md) и его [параметрах](../../../monium/concepts/alerting/alert.md#alert-parameters) в документации Monium.

#### Переход трейла в неактивное состояние {#deactivating-trail}

Алерт отправит уведомление о том, что трейл переходит в неактивный статус.

{% list tabs group=instructions %}

- Интерфейс Monium {#console}

  1. Перейдите на главную страницу [Monium](https://monium.yandex.cloud).
  1. В верхней панели нажмите название текущего проекта и выберите проект каталога с трейлом.
  1. На панели слева выберите ![alt](../../../_assets/console-icons/shield-exclamation.svg) **Алерты и SLO** → ![alt](../../../_assets/console-icons/megaphone.svg) **Алерты**.
  1. В правом верхнем углу нажмите кнопку **Создать** и выберите **Пользовательский**.
  1. В поле **Название** укажите `deactivating-trail-alert`.
  1. В блоке **Настройки алерта** задайте метки запроса `A`:

     * `project = folder__<идентификатор_каталога>` — проект каталога с трейлом.
     * `cluster = default`.
     * `service = __audit-trails__`.
     * `name = trail.status`.
     * `status != ACTIVE`.
     * `trail = <идентификатор_трейла>`.

  1. В блоке **Условия срабатывания** задайте параметры:

     * **Запрос для проверки** — `A`.
     * **Функция агрегации** — **Последнее значение**.
     * **Функция сравнения** — **Не равно**.
     * **Warning** — очистите поле: в примере используется только порог `Alarm`.
     * **Alarm** — `0`.
     * **Окно вычисления** — `5m`.

  1. В блоке **Обработка отсутствия данных** для параметров **Отсутствие точек в окне вычисления** и **Отсутствие метрик по селектору** выберите `No data`. Это позволит отличать отсутствие данных от нулевого значения метрики.

  1. В блоке **Уведомления** нажмите **Редактировать**. Добавьте канал `alerts-channel`, [созданный ранее](#create-channel), и выберите статусы срабатывания: `Alarm`, `No data` и `OK`.
  1. Нажмите **Проверить результат**. Убедитесь, что запрос возвращает нужные метрики и статус алерта соответствует их значениям.
  1. Нажмите кнопку **Создать**.

{% endlist %}

Алерт создан.

#### Прекращение доставки аудитных логов в объект назначения {#stopping-logs}

Алерт перейдет в статус `Alarm`, если все значения частоты доставки событий за окно вычисления равны нулю. Например, доставка может прекратиться из-за нехватки свободного места в бакете.

Нулевая частота доставки также возможна, если новых событий нет. Используйте этот алерт для трейлов с регулярным потоком событий. При срабатывании сравните [частоту обработки и доставки событий](#create-missing-events-chart) и проверьте [лог диагностики](../../../audit-trails/concepts/diagnostics.md).

Для параметра **Окно вычисления** задайте интервал, превышающий обычные паузы между доставками, например `15m`. Выберите его по графику доставки событий: частота зависит от активности ресурсов в области сбора трейла.

## Настройте дашборд {#setup-dashboard}

Готовые графики для наблюдения за состоянием трейлов находятся в [консоли управления](https://console.yandex.cloud) → сервис **Audit Trails** → раздел ![image](../../../_assets/console-icons/display-pulse.svg) **Мониторинг**.

Чтобы отслеживать не только состояние трейлов, но и состояние объектов назначения, куда они доставляют аудитные логи, создайте дашборд в Monium.

### Создайте график для отслеживания доставки событий {#create-missing-events-chart}

* `trail.delivered_events_count` — частота событий, доставленных в объект назначения.

Скопируйте на дашборд готовый график, который сравнивает частоту обработки и доставки событий:

      1. Перейдите на вкладку **Мониторинг** для выбранного трейла.
      1. Справа вверху нажмите **Открыть в Monium**.

          Откроется интерфейс Monium.

    {% endlist %}

1. Скопируйте график:

    {% list tabs group=instructions %}

    - Интерфейс Monium {#console}

      1. Найдите график **Processed versus delivered events**.
      1. Справа от названия графика нажмите ![horizontal-ellipsis](../../../_assets/horizontal-ellipsis.svg) → **Копировать на другой дашборд**.

### Изучите график доставки событий {#investigate-missing-events-chart}

Обратите внимание на отставание **Delivered events** от **Processed events**. На графике могут быть кратковременные провалы, за которыми следуют всплески: трейл может временно накапливать события, а затем доставлять их в объект назначения. Если отставание сохраняется час или дольше, проверьте статус и [лог диагностики](../../../audit-trails/concepts/diagnostics.md) трейла.

### Создайте график для объекта назначения {#create-destination-chart}

Дополнительно к графику сравнения обработки и доставки событий можно добавить график для объекта назначения:

* **Object Storage**

    Прекращение доставки логов может быть связано с достижением заданного максимального размера бакета. Чтобы отслеживать занятый объем и сравнивать его с ограничением, создайте график по [метрике](../../../monitoring/metrics-ref/storage-ref.md) `space_usage` и добавьте метрику `max_size` в качестве порогового значения.

    Метрика `max_size` недоступна, если для бакета не задан максимальный размер. В таком случае контролируйте использование [квоты](../../../storage/concepts/limits.md#storage-quotas) на объем хранилища в облаке.

* **Cloud Logging**

    [Добавьте на дашборд](../../../logging/tutorials/log-group-record-monitoring.md) график по [метрике](../../../monitoring/metrics-ref/logging-ref.md) `group.service.ingested_records_per_second` — она отображает скорость записи логов в лог-группу. Сравнение этой величины с установленной [квотой](../../../logging/concepts/limits.md#logging-quotas) `Максимальная скорость записи` помогает определить, приближается ли поток логов к максимально разрешенной скорости. Дополнительный график по метрике `group.service.ingest_requests_per_second` со статусом `ERROR` позволит вовремя обнаружить ошибки при записи.


* **Data Streams** — подробнее в документации [Yandex Managed Service for YDB](../../../ydb/index.md):
  * [Справочник метрик Yandex Monitoring](../../../ydb/metrics.md)
  * [Квоты и лимиты в Managed Service for YDB](../../../ydb/concepts/limits.md)

  Подробнее о решении проблем с записью данных смотрите в разделе [Диагностика медленной записи в Yandex Data Streams](../../../data-streams/tutorials/slow-writes-debug.md).

  {% note tip %}

  Если скорость записи потока событий в Data Streams более 1 МБ/с, включите сжатие. Это сократит объем передаваемых данных, снизит риск перегрузки ([троттлинга](https://ru.wikipedia.org/wiki/Троттлинг)) отдельных сегментов YDS и повысит эффективность использования пропускной способности потока.
  
  Настройка сжатия доступна при [создании](../../../audit-trails/operations/create-trail.md) или [изменении](../../../audit-trails/operations/manage-trail.md) трейла через интерфейсы CLI, API или Terraform. Можно указать метод сжатия `GZIP` ([GNU Zip](https://wikipedia.org/wiki/Gzip)) или `ZSTD` ([Zstandard](https://wikipedia.org/wiki/Zstandard)). По умолчанию сжатия нет (`RAW`).
  
  Чтобы читать данные через собственный протокол YDS, дополнительно включите сжатие на читателе YDS. Протоколы HTTP Kinesis и Apache Kafka® пока не поддерживаются.

  {% endnote %}
