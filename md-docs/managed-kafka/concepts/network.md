# Сеть в Managed Service for Apache Kafka®



При создании кластера вы можете:

* задать сеть для хостов кластера;


* указать [зоны доступности](../../overview/concepts/geo-scope.md), в которых должны располагаться хосты кластера;
* задать подсети во всех зонах доступности, в которых будут размещены хосты кластера;


* включить публичный доступ к кластеру извне Yandex Cloud.


Зоны доступности для отдельных хостов ZooKeeper или контроллеров метаданных KRaft выбираются независимо от зон хостов-брокеров. Задать их можно только при создании кластера. Для нескольких хостов сервиса координации можно задать одну и ту же зону доступности. Подсеть нужна в каждой зоне, в которой будет размещен хотя бы один хост-брокер или отдельный хост сервиса координации. Подробнее в разделе [Взаимосвязь ресурсов в Managed Service for Apache Kafka®](index.md).

Если два или три хоста сервиса координации размещены в одной зоне доступности, при отказе этой зоны будет потерян кворум. Подробнее о [размещении хостов сервиса координации](ha-cluster.md#coordination-hosts).



## Имя хоста и FQDN {#hostname}

Имя для каждого хоста в кластере Managed Service for Apache Kafka® генерируется при его создании. Это имя будет являться доменным именем хоста ([FQDN](../../glossary/fqdn.md)). Имя хоста и, соответственно, FQDN невозможно изменить.

Подробнее о том, как получить FQDN хоста, в [инструкции](../operations/connect/fqdn.md#get-fqdn).


FQDN можно использовать для доступа к хосту в рамках одной облачной сети. Подробнее в [документации сервиса Yandex Virtual Private Cloud](../../vpc/index.md).


## Эндпоинт кластера {#cluster-endpoint}

Для первоначального подключения к кластеру можно использовать _эндпоинт кластера_ — единое доменное имя вида `c-<идентификатор_кластера>.mdb.yandexcloud.net`. Оно не зависит от состава хостов: при добавлении, удалении или замене брокеров адрес в настройках клиента менять не требуется.

Эндпоинт содержит DNS-записи с IP-адресами всех хостов-брокеров кластера. Для отказоустойчивого подключения клиент должен перебирать полученные IP-адреса, пока не установит соединение с доступным брокером. Если клиент использует только первый адрес из ответа DNS, недоступность этого брокера может привести к ошибке подключения.

Эндпоинт используется только для первоначального обнаружения брокеров (bootstrap) и не является балансировщиком нагрузки. После получения метаданных кластера клиент автоматически использует FQDN отдельных брокеров для чтения и записи сообщений. Поэтому клиенту должны быть доступны не только эндпоинт, но и хосты-брокеры кластера.


Эндпоинт поддерживается для кластеров с публичным доступом и без него. Возможность подключения зависит от сетевой доступности хостов и настроек групп безопасности.


О том, как получить эндпоинт и настроить клиент, читайте в разделе [FQDN хостов и эндпоинт кластера](../operations/connect/fqdn.md).


## Публичный доступ к кластеру {#public-access-to-a-cluster}

Если вы запросили публичный доступ при [создании кластера](../operations/cluster-create.md), все [хосты-брокеры](brokers.md) в кластере будут доступны извне Yandex Cloud. Чтобы подключиться к такому кластеру, используйте [эндпоинт кластера](#cluster-endpoint) или FQDN одного или нескольких хостов-брокеров этого кластера.

Запросить публичный доступ после создания кластера невозможно.

При удалении кластера с включенным публичным доступом все публичные IP-адреса, назначенные этому кластеру, отзываются.

## Группы безопасности {#security-groups}

Для [групп безопасности](../../vpc/concepts/security-groups.md) действует принцип «весь трафик, который не разрешен, запрещен». Для подключения к кластеру задайте правила в группе безопасности. Они разрешают трафик с определенных портов, IP-адресов или из других групп безопасности. Например, ВМ не сможет подключиться к кластеру, если:

* ВМ находится в подсети 10.128.0.0/16, а в правилах на входящий трафик указана только подсеть 10.133.0.0/24.
* ВМ находится в подсети 10.133.0.0/24, но обращается к порту, не указанному в правилах группы безопасности.

Подробнее о том, как настроить группы безопасности, читайте в разделе [Предварительная настройка для подключения к кластеру Apache Kafka®](../operations/connect/index.md).

{% note tip %}

При подключении к кластеру из той же облачной сети, в которой он находится, настройте группы безопасности не только для кластера, но и для ВМ, с которой выполняется подключение.

{% endnote %}

Особенности работы с группами безопасности:

* Настройки групп безопасности влияют только на возможность подключения к кластеру. Они не влияют на функционирование кластеров: репликации разделов топиков по хостам-брокерам, связь между брокерами и хостами ZooKeeper и другие возможности.

* Даже если кластер и ВМ, с которой выполняется подключение, находятся в одной группе безопасности, подключение будет невозможно, если в этой группе не заданы правила, разрешающие прохождение трафика между этой ВМ и кластером.

  Однако такие правила по умолчанию содержатся в группе безопасности, которая добавляется автоматически при создании облачной сети. Это правила `Self`, разрешающие неограниченное прохождение трафика внутри группы.
