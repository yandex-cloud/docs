# Централизованная публикация в интернете и защита от DDoS-атак приложений из разных каталогов


В этом руководстве описан сценарий, в котором с облачными ресурсами Yandex Cloud работают несколько независимых команд. Команды разрабатывают сервисы и приложения, которые нужно публиковать в интернете. Ресурсы разделены по каталогам Yandex Cloud: каждая команда имеет доступ только к своему каталогу. По требованию службы информационной безопасности (СИБ) команды не должны публиковать ресурсы из своих каталогов напрямую в интернете.

Частный сценарий этого руководства с развертыванием инфраструктуры с нуля смотрите в разделе [Создание распределенной инфраструктуры с защищенным доступом](distributed-secured-infrastructure.md).

С реализацией такой схемы помогут сервисы Yandex Cloud — [Yandex Application Load Balancer](../../application-load-balancer/index.md) (ALB) и [Yandex Smart Web Security](../concepts/index.md) (SWS).

Сервис Application Load Balancer позволяет создавать балансировщики уровня L7 модели [OSI](https://ru.wikipedia.org/wiki/Сетевая_модель_OSI). Балансировщик распределяет трафик между сервисами и приложениями и публикует их в интернете.

Сервис Smart Web Security защищает ресурсы от [DDoS-атак](../../glossary/ddos.md) и ботов на уровне L7. Дополнительно можно подключить [WAF](../concepts/waf.md) и ограничить нагрузку с помощью модуля [Advanced Rate Limiter](../concepts/arl.md) (ARL). Параметры защиты задаются в профиле безопасности Smart Web Security, который подключается к L7-балансировщику.

Чтобы настроить такую схему работы, надо решить несколько задач:

* Централизованная публикация сервисов в интернете через L7-балансировщик.
* Проверка входящего трафика на наличие информационных угроз с помощью Smart Web Security.
* Ограничение доступа команд к L7-балансировщикам и профилю безопасности: разместите балансировщики в отдельном каталоге, доступ к которому есть только у сотрудников СИБ.
* Сетевое взаимодействие балансировщиков с целевыми ресурсами в каталогах команд с помощью [Multi-folder VPC](../../vpc/tutorials/multi-folder-vpc.md). Балансировщики и ресурсы команд должны находиться в разных подсетях одной сети VPC.

## Схема размещения ресурсов в Yandex Cloud {#resource-allocation-scheme}

![image](../../_assets/smartwebsecurity/different-folders-scheme.svg)

На схеме обозначены следующие ресурсы:

* **ALB** — L7-балансировщики Application Load Balancer, через которые сервисы публикуются в интернете.
* **SWS** — сервис Smart Web Security для защиты на уровне приложений (L7).
* **Каталог СИБ** — каталог L7-балансировщиков ALB, доступ к которому имеют только сотрудники службы информационной безопасности.
* **VPC** — облачная сеть с подсетями:
  * **alb-subnet-a**, **alb-subnet-b**, **alb-subnet-d** — подсети с узлами ALB.
  * **subnet-team-1**, **subnet-team-2** — подсети с ресурсами команд.
* **Каталоги команд** — каталоги, в которых размещены целевые ресурсы команд. Например, виртуальные машины (ВМ), базы данных, балансировщики L3-L4 [Network Load Balancer](../../network-load-balancer/index.md) (NLB) и другие.

Предполагается, что целевые ресурсы сервисов уже созданы и размещены в разных каталогах. В руководстве рассмотрены:

* [Требования и рекомендации по дополнительной настройке ресурсов](#requirements-recommendations).
* [Настройка защиты и публикация сервисов в интернете](#publish-services).

## Требования и рекомендации по настройке ресурсов {#requirements-recommendations}

### Сеть {#network-requirements}

* Для сетевого взаимодействия L7-балансировщиков с ресурсами команд используйте Multi-folder VPC. Эта функция позволяет использовать одну сеть VPC в нескольких каталогах.
* Для разграничения сетевого доступа между ресурсами разных команд используйте [группы безопасности](../../vpc/concepts/security-groups.md):

    * Группы безопасности целевых ресурсов должны разрешать входящий трафик из подсетей L7-балансировщика.
    * Группы безопасности L7-балансировщика должны разрешать входящий трафик от клиентов на порты обработчиков и исходящий трафик к целевым ресурсам.

      Рекомендации по настройке групп безопасности смотрите в разделе [Группы безопасности](../../application-load-balancer/concepts/application-load-balancer.md#security-groups).

### L7-балансировщики {#l7-balancer-requirements}

* Разместите все L7-балансировщики в одном каталоге, доступ к которому имеют только сотрудники СИБ.
* (Опционально) [Подключите защиту](../../vpc/ddos-protection/index.md) от DDoS-атак на уровнях L3-L4. Для этого:
    * [Зарезервируйте](../../vpc/operations/get-static-ip.md) статический публичный IP-адрес с защитой от DDoS-атак и назначьте его обработчику L7-балансировщика.
    * [Настройте порог](https://center.yandex.cloud/support) срабатывания механизмов защиты L3-L4 в соответствии с объемом легитимного трафика к сервисам.
    * На целевых ресурсах [задайте MTU](../../vpc/operations/adjust-mtu-ddos-protection.md) `1450`.
* Для [обработчиков](../../application-load-balancer/concepts/application-load-balancer.md#listener) одного L7-балансировщика нельзя использовать разные публичные IP-адреса.
* Для обработчиков одного L7-балансировщика используйте разные порты.

    Для HTTPS-протокола можно использовать [обработчики SNI](../../application-load-balancer/concepts/application-load-balancer.md#listener) с одинаковым портом. Допустимое количество обработчиков SNI смотрите в [лимитах](../../application-load-balancer/concepts/limits.md).

* (Опционально) Для повышения отказоустойчивости разместите L7-балансировщики в разных зонах доступности.
* Для узлов L7-балансировщика учитывайте [размеры подсетей](../../application-load-balancer/concepts/application-load-balancer.md#lcu-scaling-subnet-sizes).
* Настройте для L7-балансировщика минимальное количество [ресурсных единиц](../../application-load-balancer/concepts/application-load-balancer.md#lcu-scaling-settings) в каждой зоне согласно правилам [автомасштабирования](../../application-load-balancer/concepts/application-load-balancer.md#lcu-scaling). Количество ресурсных единиц определяется ожидаемой нагрузкой на ваши сервисы по следующим параметрам:
  * количество запросов в секунду (RPS);
  * количество одновременных активных соединений;
  * количество новых соединений в секунду;
  * объем трафика в секунду.
* При высокой нагрузке учитывайте [лимиты](../../application-load-balancer/concepts/limits.md) L7-балансировщика. Если ресурсов одного балансировщика недостаточно, распределите нагрузку между несколькими балансировщиками.
* Для высоконагруженных сервисов выделите для каждого сервиса свой L7-балансировщик.
* При публикации нескольких сервисов через один L7-балансировщик ALB учитывайте [SLA](https://yandex.ru/legal/cloud_sla_apploadbalancer).
* Учитывайте, что внешние запросы к веб-серверам будут приходить от IP-адресов из диапазона внутренних IP-адресов подсетей L7-балансировщика. IP-адреса источников запросов (пользователей) будут сохраняться в HTTP-заголовке [X-Forwarded-For](https://en.wikipedia.org/wiki/X-Forwarded-For) (XFF). Поэтому для логирования IP-адреса пользователей из XFF на веб-серверах целевых ресурсов может потребоваться [изменение конфигурации](../../application-load-balancer/qa.md#client-ip).

### Целевые ресурсы {#target-resources-requirements}

* В целевую группу L7-балансировщика добавьте IP-адреса сервисов из каталогов команд, которые нужно публиковать в интернете.
* IP-адреса целевых ресурсов должны входить в [частные диапазоны по RFC 1918](https://datatracker.ietf.org/doc/html/rfc1918#section-3).
* Если внутренний IP-адрес целевого ресурса изменится, обновите настройки целевой группы L7-балансировщика.

## Настройка безопасной публикации сервисов в интернете {#publish-services}

Чтобы безопасно опубликовать сервисы в интернете:

1. Создайте [каталог](../../resource-manager/concepts/resources-hierarchy.md#folder) СИБ.
1. [Предоставьте доступ](../../iam/concepts/access-control/index.md#how-do-i-perform-access-management) к каталогу только сотрудникам СИБ.
1. [Настройте сетевое взаимодействие](../../vpc/tutorials/multi-folder-vpc.md) ресурсов из разных каталогов.
1. [Настройте группы безопасности](../../vpc/operations/security-group-create.md) согласно [рекомендациям](#network-requirements).
1. [Зарезервируйте публичный IP-адрес](../../vpc/operations/get-static-ip.md) со включенной опцией защиты от DDoS-атак на уровнях L3-L4.
1. [Создайте профиль безопасности](#create-sws-profile).
1. При использовании HTTPS [добавьте TLS-сертификат](../../certificate-manager/quickstart/index.md) в Certificate Manager.
1. [Создайте L7-балансировщик](#create-alb).
1. [Проверьте работу L7-балансировщика](#check-alb).

На схеме показаны ресурсы L7-балансировщика, которые будут созданы и настроены в этом сценарии.

### Создание профиля безопасности {#create-sws-profile}

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. В [консоли управления](https://console.yandex.cloud) выберите [каталог СИБ](../../resource-manager/concepts/resources-hierarchy.md#folder).
  1. [Перейдите](https://console.yandex.cloud/link/smartwebsecurity) в сервис **Smart Web Security**.
  1. На панели слева выберите ![shield-check](../../_assets/console-icons/shield-check.svg) **Профили безопасности**.
  1. Нажмите **Создать профиль**.
  1. Выберите `По преднастроенному шаблону`.
  1. Введите имя профиля — `sws-ddos`.
  1. В поле **Действие для базового правила по умолчанию** выберите `Разрешить`.
  1. В блоке **Правила безопасности** напротив правила `sp-rule-1` нажмите ![image](../../_assets/console-icons/ellipsis.svg) → ![pencil](../../_assets/console-icons/pencil.svg) **Редактировать**.
  1. Включите опцию **Только логирование (dry run)**.

      Эта опция используется для тестирования работы профиля. В режиме логирования трафик не блокируется и пользователи не будут отключены от вашего сервиса из-за неправильно настроенного профиля. Проанализируйте работу профиля и настройте [правила](../concepts/rules.md) в соответствии с потребностями вашего сервиса.

  1. Нажмите **Сохранить изменения**.
  1. Нажмите **Создать**.

{% endlist %}

Другие способы создания профиля безопасности смотрите в разделе [Создать профиль безопасности](../operations/profile-create.md).

### Создание L7-балансировщика {#create-alb}

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. В [консоли управления](https://console.yandex.cloud) выберите каталог СИБ.
  1. [Перейдите](https://console.yandex.cloud/link/application-load-balancer) в сервис **Application Load Balancer**.
  1. Нажмите кнопку **Создать L7-балансировщик** и выберите **Визард**.

#### Настройка целевой группы {#settings-target-group}

В [целевую группу](../../application-load-balancer/concepts/target-group.md) входят ресурсы, на которые L7-балансировщик будет направлять запросы. Это могут быть ВМ или внутренний балансировщик NLB.

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. Введите имя целевой группы: `test-target-group`.
  1. Укажите внутренний IP-адрес вашего целевого ресурса: адрес обработчика внутреннего NLB вашего сервиса или адрес ВМ.
  1. Выберите подсеть, в которой размещены ресурсы вашего сервиса.

     Для выбора подсети пользователь должен иметь роль `vpc.user` на каталог, в котором находится подсеть.

  1. Задайте настройки других целевых ресурсов: нажмите кнопку **Добавить целевой ресурс** и укажите адреса и подсети.
  1. Нажмите кнопку **Создать и продолжить**.

{% endlist %}

#### Настройка группы бэкендов {#settings-backend-group}

[Группа бэкендов](../../application-load-balancer/concepts/backend-group.md) содержит настройки балансировки трафика и проверки состояния целевых ресурсов. Визард автоматически создает один бэкенд и одну группу проверок состояния. В качестве целевой группы будет выбрана группа, созданная на предыдущем шаге.

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. Включите **Расширенные настройки**.
  1. Введите имя группы бэкендов: `test-backend-group`.
  1. Тип группы оставьте `HTTP`.
  1. Чтобы запросы одной пользовательской сессии обрабатывал один и тот же ресурс бэкенда, включите **Привязка сессий** (session affinity). Если в качестве целевого ресурса используется внутренний балансировщик NLB, привязку сессий можно не включать.

  1. В блоке **Бэкенды**:

     * Введите имя бэкенда: `backend-1`.
     * Оставьте тип бэкенда — `Целевая группа`.
     * Оставьте созданную ранее целевую группу: `test-target-group`.
     * Укажите TCP-порт сервиса. Обычно это `80` для HTTP и `443` для HTTPS.
     * Если в качестве целевого ресурса используется ВМ, настройте [проверку состояния](../../application-load-balancer/concepts/best-practices.md).
     * Если в качестве целевого ресурса используется внутренний балансировщик NLB, удалите проверку состояния.

  1. Нажмите кнопку **Создать и продолжить**.

{% endlist %}

#### Настройка HTTP-роутера {#settings-http-router}

[HTTP-роутеры](../../application-load-balancer/concepts/http-router.md) задают правила маршрутизации запросов к бэкендам и позволяют изменять запросы на балансировщике. Визард автоматически создает виртуальный хост и правило маршрутизации, а также выбирает группу бэкендов, которая была создана на предыдущем шаге.

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. Введите имя роутера: `test-http-router`.
  1. Включите **Расширенные настройки**.
  1. В блоке **Виртуальные хосты** задайте:
     * Имя хоста: `test-virtual-host`.
     * **Authority** — имя домена вашего сервиса.
     * **Профиль безопасности** — профиль, созданный ранее.

        Если профиль не выбран, защита Smart Web Security работать не будет.

  1. Задайте параметры маршрута:
     * Имя маршрута: `test-route`.
     * **Путь** — **Начинается с** и далее `/`.
     * **Действие** — **Маршрутизация**.
     * **Группа бэкендов** — оставьте созданную ранее группу.
  1. Нажмите кнопку **Создать и продолжить**.

{% endlist %}

#### Настройка L7-балансировщика {#create-load-balancer}

[Балансировщик](../../application-load-balancer/concepts/application-load-balancer.md) принимает запросы и распределяет их между ресурсами целевой группы по правилам HTTP-роутера. Для приема трафика используются [обработчики](../../application-load-balancer/concepts/application-load-balancer.md#listener). Визард создает обработчик автоматически и выбирает HTTP-роутер, созданный на предыдущем шаге.

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. Введите имя балансировщика: `test-load-balancer`.
  1. Включите **Расширенные настройки**.
  1. В блоке **Сетевые настройки** выберите созданную ранее сеть VPC.
  1. Для **Группы безопасности** выберите **Из списка** и далее группу безопасности, созданную ранее.
  1. В блоке **Размещение** выберите подсети в нужных [зонах доступности](../../overview/concepts/geo-scope.md) и включите прием трафика в этих подсетях.
  1. Настройте обработчик:
     * Введите имя обработчика: `test-listener`.
     * В блоке **Публичный IP-адрес** включите публичный IP-адрес и укажите:
        * **Порт** — TCP-порт вашего сервиса. Обычно `443` для HTTPS и `80` для HTTP.
        * **Тип** — `список` и выберите публичный IP-адрес, зарезервированный ранее.
     * В блоке **Приём и обработка трафика** укажите:
        * **Тип обработчика** — `HTTP`.
        * **Протокол** — `HTTP` или `HTTPS`.
        * Для протокола HTTPS выберите TLS-сертификат вашего сервиса, добавленный ранее в Certificate Manager.
        * **HTTP-роутер** — оставьте созданный ранее роутер.

  1. Нажмите кнопку **Создать**.

{% endlist %}

#### Добавление обработчика SNI к существующему балансировщику {#add-sni-listener}

Если в вашей инфраструктуре уже используется L7-балансировщик с обработчиком на публичном IP-адресе, добавьте к нему обработчик SNI:

{% list tabs group=instructions %}

- Консоль управления {#console}

  1. Откройте [консоль управления](https://console.yandex.cloud).
  1. [Перейдите](https://console.yandex.cloud/link/application-load-balancer) в сервис **Application Load Balancer**.
  1. Выберите L7-балансировщик.
  1. В блоке **Обработчики** напротив обработчика с публичным IP-адресом нажмите значок ![image](../../_assets/console-icons/ellipsis.svg) и выберите **Редактировать**.
  1. В блоке **Приём и обработка трафика** нажмите **Добавить обработчик SNI** и задайте параметры:
     * **Имена серверов** — доменное имя сервиса. По этим значениям расширения SNI балансировщик выбирает обработчик для установки TLS-соединения.

       {% note tip %}

       Некоторые браузеры переиспользуют TLS-соединение с одним IP-адресом, если сертификат этого соединения подходит для нужного домена. В таком случае браузер не устанавливает новое соединение, и обработчик SNI не выбирается повторно. В результате запрос может попасть не в тот HTTP-роутер. Чтобы избежать этого, используйте разные сертификаты для обработчиков SNI и основного обработчика. Если нужно маршрутизировать запросы для нескольких доменов с одним сертификатом, настройте виртуальные хосты в HTTP-роутере.

       {% endnote %}

     * **Сертификаты** — TLS-сертификат сервиса, добавленный ранее в Certificate Manager.
     * **HTTP-роутер** — созданный ранее HTTP-роутер.

  1. Сохраните изменения.

{% endlist %}

- Консоль управления {#console}
