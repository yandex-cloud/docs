# Условия

Условия определяют, к каким HTTP-запросам применяется [правило](rules.md) Smart Web Security.

## Объединение условий {#conditions-logic}

В одном правиле может быть несколько условий, а внутри одного условия — несколько проверок.

Условия разных типов (например, `IP` и `HTTP header`) объединяются оператором **И** — запрос должен соответствовать каждому из них.

Внутри одного условия логика объединения проверок зависит от его типа. Для IP, HTTP-заголовков, параметров запроса и cookie действует **И**: должны выполняться все настроенные проверки.

В одной проверке может быть несколько значений. При проверке принадлежности IP региону между значениями действует **ИЛИ**: достаточно совпадения с одним из указанных регионов.

В проверке **IP не принадлежит региону** отрицание применяется ко всему набору значений: адрес не должен относиться ни к одному из указанных регионов.

Если достаточно выполнения одного из условий или одной из проверок, создайте для них отдельные правила с одинаковым действием. При настройке учитывайте [порядок применения правил](rules.md#rules-order).

### Пример с IP-адресом и HTTP-заголовком {#request-example}

В правиле настроены два условия:

* **IP** — адрес принадлежит одному из регионов `ru` или `kz` и входит в выбранный список адресов.
* **HTTP header** — значение заголовка `User-Agent` начинается с `curl/`.

Допустим, сервис определил регион IP-адреса клиента как `ru`, а сам адрес входит в выбранный список. Клиент отправляет запрос:

```http
GET /api/orders HTTP/1.1
Host: api.example.com
User-Agent: curl/8.0
```

Запрос соответствует обоим условиям: IP-адрес принадлежит допустимому региону и входит в список, а значение заголовка начинается с `curl/`.

Если заменить заголовок на `User-Agent: Mozilla/5.0`, запрос перестанет соответствовать условиям правила, хотя обе проверки IP по-прежнему выполнены.

### Пример с исключением регионов и списка IP-адресов {#ip-exclusions-example}

В условии IP настроены две проверки: **IP не принадлежит региону** со значениями `ru`, `kz`, `tr`, `ge` и **IP не принадлежит списку** с выбранным списком адресов.

Возможны два результата проверки:

* IP-адрес вне перечисленных регионов и вне списка — обе проверки выполнены, запрос соответствует условию.
* IP-адрес относится к любому из перечисленных регионов или входит в список — условие не выполнено.

{% endcut %}

В правилах [ARL](arl.md) соответствие условиям само по себе не означает блокировку: действие применяется при превышении [лимита запросов](arl.md#requests-counting).

## Формат регулярных выражений {#regular-expressions}

Smart Web Security использует регулярные выражения библиотеки [PIRE](https://github.com/yandex/pire). Выражение применяется к выбранной части HTTP-запроса. Например, в условии **HTTP header** проверяется значение указанного заголовка.

### Особенности синтаксиса {#regular-expressions-operators}

Чтобы использовать специальный символ как обычный, экранируйте его обратным слешем `\`. Например, `\.` соответствует точке.

В PIRE `\w` соответствует латинской или русской букве, а `\W` — любому другому символу. Цифры и `_` в `\w` не входят.

### Регистр в регулярных выражениях {#regular-expressions-case}

Чтобы не учитывать регистр, добавьте `(?i)` в начало выражения. Например, `(?i)example` соответствует строкам `example`, `EXaMple` и `EXAMPLE`.

### Примеры регулярных выражений {#regular-expressions-examples}

В примерах используется проверка **Соответствует регулярному выражению**:

* **Пути API.** Для **Request path** укажите `/api/(v1|v2)/orders`. Выражение соответствует путям `/api/v1/orders` и `/api/v2/orders`, но не `/api/v3/orders`.
* **Числовой параметр запроса.** Для **Query Match** укажите ключ `order_id` и выражение `[0-9]+`. Ему соответствует значение `12345`, но не `abc`.
* **Поддомены.** Для **Host** укажите `(api|admin)\.example\.com`. Выражение соответствует значениям `api.example.com` и `admin.example.com`, но не `api-example.com`. Обратный слеш перед каждой точкой позволяет сопоставлять ее как обычный символ.
