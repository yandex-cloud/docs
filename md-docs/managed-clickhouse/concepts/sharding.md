# Шардирование в Managed Service for ClickHouse®

[_Шардирование_](../../glossary/sharding.md) в ClickHouse® — это стратегия горизонтального масштабирования кластера, при которой данные разделяются на несколько логических частей — _шардов_. Каждый шард может состоять из одного хоста или нескольких [хостов-реплик](replication.md).

Преимущества шардирования:
* Горизонтальное масштабирование — позволяет преодолеть ограничения одного сервера по CPU, RAM, объему диска и пропускной способности ввода-вывода.
* Параллельное выполнение запросов к одной логической таблице на разных шардах — распределяет нагрузку, снижает конкуренцию за ресурсы и ускоряет чтение и запись данных.

## Особенности шардирования в Managed Service for ClickHouse® {#uses}

Для распределенного хранения данных таблицы в Managed Service for ClickHouse® нужно создать:
1. Одинаковые _локальные таблицы_ на [движке семейства MergeTree](https://clickhouse.com/docs/ru/engines/table-engines/mergetree-family) на нескольких шардах кластера.
1. _Распределенную таблицу_ на [движке Distributed](https://clickhouse.com/docs/ru/engines/table-engines/special/distributed), использующую эти шарды.

Каждая локальная таблица хранит часть строк распределенного набора данных. Распределенная таблица маршрутизирует запросы к локальным таблицам, но не хранит данные.

Распределение данных таблицы по шардам определяется _ключом шардирования_. При выполнении запроса `INSERT` распределенная таблица вычисляет значение ключа шардирования и перенаправляет запрос на ту или иную локальную таблицу. Ключ шардирования задается при создании распределенной таблицы. Примеры ключей шардирования: поля таблицы, вычисляемые выражения, функции случайного распределения.

От выбора ключа шардирования зависят:
* равномерность распределения данных между шардами;
* эффективность выполнения запросов.

{% note info %}

В отличие от `INSERT`, запросы `SELECT` отправляются на все шарды кластера независимо от ключа шардирования. Это поведение может быть изменено с помощью настройки `optimize_skip_unused_shards`.

{% endnote %}

Для распределения данных таблицы можно использовать как все шарды кластера, так и их часть — [группу шардов](../operations/shard-groups.md). Распределенную таблицу также можно создать на всех шардах кластера или на группе шардов.

Такой подход позволяет вам гибко управлять шардированием в кластере Managed Service for ClickHouse®.

Разные способы шардирования показаны в разделе [Шардирование таблиц в ClickHouse®](../tutorials/sharding.md).

## Управление шардированием в Managed Service for ClickHouse® {#shard-management}

Кластер Managed Service for ClickHouse® можно сразу создать шардированным или включить шардирование позже.

При создании нешардированного кластера в него автоматически добавляется один шард, содержащий все хосты кластера. Чтобы включить шардирование на созданном кластере, добавьте в него как минимум еще один шард.

При создании шардированного кластера в него можно добавить два и более шарда. В уже существующий шардированный кластер можно добавить дополнительные шарды.


{% note info %}

Нельзя удалить хост из шарда, если достигнут [лимит на минимальное количество хостов](limits.md#mch-limits).

{% endnote %}

## Репликация в шардированном кластере Managed Service for ClickHouse® {#sharding-replication}

В шардированном кластере Managed Service for ClickHouse® [репликация](replication.md) работает на уровне шардов, а не кластера целиком:
* каждый шард хранит собственную часть данных;
* реплики одного шарда содержат одинаковые копии этой части данных;
* между разными шардами данные не реплицируются.

Если в кластере включен [сервис координации](coordination-system.md), то при создании шарда с двумя и более хостами автоматически включается репликация.

{% note info %}

Если в кластере выключен сервис координации, в нем невозможно создать шард с двумя и более хостами.

{% endnote %}
