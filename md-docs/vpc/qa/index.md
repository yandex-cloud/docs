## Сети и маршрутизация {#networks}

#### Что такое VPC? {#what-is-vpc}

VPC (Yandex Virtual Private Cloud) — это способ связи и организации облачных ресурсов с использованием виртуальных сетей.

#### Какие сетевые технологии доступны пользователям Yandex Cloud? {#available-network-techs}

VPC позволяет назначать машинам внутренние и внешние IP-адреса, создавать облачные сети и подсети.

#### Как создать облачную сеть? {#create-cloud-network}

При создании каталога через консоль управления сеть будет создана в нем автоматически. Также облачную сеть можно создать вручную с помощью консоли управления.

#### Как создать подсеть? {#create-subnet}

В каталоге по умолчанию подсети будут созданы автоматически. Дополнительные подсети можно создать с помощью [консоли управления или CLI](../operations/subnet-create.md).

#### Какие ограничения существуют при создании подсетей? {#create-subnet-limits}

В подсетях можно использовать только частные IP-адреса из IPv4-диапазонов, определенных в [RFC 1918](https://tools.ietf.org/html/rfc1918).

#### Как настроить маршрутизацию между двумя облачными сетями? {#routing-traffic-between-two-vpcs}

Связать облачные сети можно несколькими способами:

* **VPN-туннель через интернет.** В каждой сети размещается ВМ с публичным IP-адресом. Между ВМ настраивается туннель, например [OpenVPN](../tutorials/site-to-site-openvpn.md) или [IPsec](../tutorials/ipsec/ipsec-vpn.md). В [таблицах маршрутизации](../concepts/routing.md#static) в качестве следующего узла указываются внутренние IP-адреса ВМ в соответствующих сетях. Исходящий трафик между публичными IP-адресами [тарифицируется](../pricing.md#prices-traffic).
* **ВМ с сетевыми интерфейсами в разных сетях.** На ВМ настраивается маршрутизация, а в таблицах маршрутизации сетей — маршруты к нужным подсетям через внутренние адреса интерфейсов этой ВМ. За основу можно взять [NAT-инстанс](../tutorials/nat-instance/index.md), добавив ему интерфейс в другой сети и маршруты к конкретным подсетям. Также доступны виртуальные роутеры [Cisco](../tutorials/cisco.md) и [MikroTik](../tutorials/mikrotik.md); для их работы могут потребоваться лицензии.
* **VPC Stitching.** Механизм [Cloud Router](../../cloud-router/concepts/vpc-stitching.md) связывает сети в каталогах одного или разных облаков в пределах одной организации. Он доступен только при подключенной услуге Cloud Interconnect с объемом трафика не менее 300 ТБ. Подробнее в руководстве [Организация сетевой связности между несколькими виртуальными сетями с помощью VPC Stitching](../tutorials/vpc-stitching.md).

#### Как изменить сеть или подсеть для кластера управляемой базы данных? {#changing-net-or-subnet}

Сеть задается при создании кластера. В сервисах, поддерживающих восстановление кластера из резервной копии, можно выбрать другую сеть при восстановлении. Порядок действий описан в инструкциях:

* Managed Service for ClickHouse®: [Восстановить кластер из резервной копии](../../managed-clickhouse/operations/cluster-backups.md#restore).
* Yandex MPP Analytics for PostgreSQL: [Восстановить кластер из резервной копии](../../managed-greenplum/operations/cluster-backups.md#restore).
* Managed Service for MySQL®: [Восстановить кластер из резервной копии](../../managed-mysql/operations/cluster-backups.md#restore).
* Managed Service for OpenSearch: [Восстановить кластер из резервной копии](../../managed-opensearch/operations/cluster-backups.md#restore).
* Managed Service for PostgreSQL: [Восстановить кластер из резервной копии](../../managed-postgresql/operations/cluster-backups.md#restore).
* Managed Service for Sharded PostgreSQL: [Восстановить кластер из резервной копии](../../managed-spqr/operations/cluster-backups.md#restore).
* Yandex StoreDoc: [Восстановить кластер из резервной копии](../../storedoc/operations/cluster-backups.md#restore).
* Yandex Managed Service for Valkey™: [Восстановить кластер из резервной копии](../../managed-valkey/operations/cluster-backups.md#restore).

Чтобы изменить подсеть в пределах той же сети, можно пересоздать хост в нужной подсети: сначала добавить новый хост, затем удалить старый. Возможность и порядок действий зависят от сервиса и конфигурации кластера. Перед удалением учитывайте ограничения сервиса и убедитесь, что данные доступны на новом хосте. Инструкции по управлению хостами и группами хостов:

* Managed Service for ClickHouse®: [Управление хостами ClickHouse®](../../managed-clickhouse/operations/hosts.md).
* Managed Service for MySQL®: [Управление хостами кластера MySQL®](../../managed-mysql/operations/hosts.md).
* Managed Service for OpenSearch: [Управление группами хостов OpenSearch](../../managed-opensearch/operations/host-groups.md).
* Managed Service for PostgreSQL: [Управление хостами кластера PostgreSQL](../../managed-postgresql/operations/hosts.md).
* Managed Service for Sharded PostgreSQL: [Управление хостами кластера Sharded PostgreSQL](../../managed-spqr/operations/cluster-hosts.md).
* Yandex StoreDoc: [Управление хостами кластера Yandex StoreDoc](../../storedoc/operations/hosts.md).
* Yandex Managed Service for Valkey™: [Управление хостами кластера Valkey™](../../managed-valkey/operations/hosts.md).


Для Managed Service for Apache Kafka® используйте отдельную инструкцию по миграции хостов между зонами доступности:

* [Миграция хостов кластера Apache Kafka® в другую зону доступности](../../managed-kafka/operations/host-migration.md).


#### Можно ли использовать IPv6-адреса? {#using-ipv6}

Virtual Private Cloud [не поддерживает IPv6](../concepts/routing.md#static). Для сценариев, в которых клиенты подключаются по IPv6, можно разместить вне Yandex Cloud сервер, принимающий подключения по IPv4 и IPv6 и передающий запросы к облачным ресурсам по IPv4.

#### Как организовать отказоустойчивый VPN или NGFW? {#using-failsafe-vpn}

В виртуальных сетях Virtual Private Cloud не поддерживаются VRRP и другие протоколы, которым нужен общий виртуальный IP-адрес между ВМ. Подробнее об ограничениях в разделе [Устройство сети в Yandex Cloud](../concepts/network-overview.md).

Для отказоустойчивости сетевых ВМ используйте решения с переключением маршрутов:

* [Реализация отказоустойчивых сценариев для сетевых виртуальных машин](../tutorials/route-switcher.md).
* [Реализация защищенной высокодоступной сетевой инфраструктуры с выделением DMZ на основе Check Point NGFW](../tutorials/high-accessible-dmz.md).

## IP-адреса и NAT {#addresses}

#### Каким ресурсам можно назначать IP-адреса? {#assing-ip-resources}

Адреса можно назначить [виртуальным машинам](../../compute/concepts/vm.md) и хостам в кластерах баз данных.

#### Как назначаются IP-адреса облачным ресурсам? {#assign-ip}

Публичные IP-адреса облачным ресурсам можно назначить автоматически или выбрать из списка [зарезервированных статических адресов](../operations/set-static-ip.md). Внутренние адреса можно назначать автоматически или вручную при создании [виртуальной машины](../../glossary/vm.md).

#### Как сделать публичный IP-адрес статическим? {#make-ip-static}

Публичный IP-адрес можно [сделать статическим](../operations/set-static-ip.md) во вкладке **Публичные IP-адреса** сервиса VPC в [консоли управления](https://console.yandex.cloud).

#### Почему у моей ВМ или базы данных изменился IP-адрес? {#dynamic-ip-changed}

Чаще всего проблема в том, что IP-адрес был динамическим.

IP-адрес может быть статическим или динамическим. Динамический IP-адрес назначается ресурсу по умолчанию и может измениться при остановке и последующем запуске ресурса, пересоздании сетевого интерфейса или самого ресурса. Например, ресурс может остановиться из-за задолженности. При перезагрузке ВМ без остановки публичный IP-адрес [сохраняется](../concepts/address.md#public-addresses).

Динамические IP-адреса обычно используют для тестовых и временных сред, а также для сервисов, не принимающих входящие подключения.

Если динамический IP-адрес вам не подходит, сделайте его [статическим](../operations/set-static-ip.md).

#### Могу ли я защитить публичный IP-адрес от случайного удаления? {#deletion-protection}

Да, публичный IP-адрес можно [защитить от случайного удаления](../operations/deletion-protection.md).

#### Можно ли восстановить удаленный публичный IP-адрес? {#restore-ip-address}

После удаления публичный IP-адрес возвращается в общий пул и может быть выдан другому пользователю. Поэтому восстановление прежнего адреса не гарантируется.

Если требуется вернуть адрес ВМ или балансировщика, создайте запрос в [техническую поддержку](https://center.yandex.cloud/support). В нем укажите IP-адрес и идентификатор каталога.

Чтобы сохранить адрес при остановке ресурса, [зарезервируйте статический публичный IP-адрес](../operations/get-static-ip.md) или [сделайте динамический адрес статическим](../operations/set-static-ip.md). Для защиты от случайного удаления [включите защиту от удаления](../operations/deletion-protection.md).

#### Можно ли перенести публичный IP-адрес в другую зону доступности? {#transferring-ip-to-a-different-zone}

Перенос зарезервированного публичного IP-адреса между зонами доступности не поддерживается: каждой зоне выделен свой пул адресов.

Если для вашего сценария необходимо сохранить адрес в другой зоне, создайте запрос в [техническую поддержку](https://center.yandex.cloud/support). В нем укажите публичный IP-адрес и опишите сценарий.

#### Что делать, если сайт неверно определяет страну публичного IP-адреса? {#external-ip-address-country-affiliation-issue}

Сторонние сайты могут использовать устаревшие базы геолокации IP-адресов — из-за этого сайт может неверно определять страну адреса или блокировать подключения.

Проверьте адрес по [списку диапазонов Yandex Cloud](../concepts/ips.md). Регистрационные сведения об адресе доступны через `whois` или [базу RIPE](https://apps.db.ripe.net/db-web-ui/query); они могут отличаться от данных геолокации, используемых конкретным сайтом.

Если нужен другой адрес, [отвяжите текущий публичный IP-адрес](../../compute/operations/vm-control/vm-detach-public-ip.md) от ВМ и [назначьте новый](../../compute/operations/vm-control/vm-attach-public-ip.md). Это изменит адрес подключения к ВМ. Подходящий адрес можно [сделать статическим](../operations/set-static-ip.md).

#### В чем разница между NAT-шлюзом и NAT-инстансом? {#difference-nat-gateway-and-nat-instance}

[NAT-шлюз](../concepts/gateways.md#nat-gateway) предоставляет облачным ресурсам доступ в интернет без назначения им публичных IP-адресов и без создания дополнительных ВМ. Задать шлюзу фиксированный публичный IP-адрес нельзя. Использование шлюза и исходящий через него трафик [тарифицируются](../pricing.md#nat-gateways).

[NAT-инстанс](../tutorials/nat-instance/index.md) — обычная виртуальная машина, настроенная для трансляции сетевых адресов. Для нее можно использовать готовый образ из Cloud Marketplace или другой подходящий образ и настроить NAT самостоятельно. Такой вариант позволяет использовать статический публичный IP-адрес и управлять обработкой трафика. Настройку и обслуживание ВМ выполняет пользователь; ресурсы ВМ, публичный IP-адрес и исходящий трафик оплачиваются по [правилам тарификации](../tutorials/nat-instance/console.md#paid-resources).

#### Можно ли привязать фиксированный IP-адрес к NAT-шлюзу? {#link-ip-address-to-nat-gateway}

[NAT-шлюз](../concepts/gateways.md#nat-gateway) получает публичные IP-адреса из отдельного диапазона. Назначить ему зарезервированный статический адрес или собственный пул адресов нельзя.

Если внешнему сервису нужен фиксированный адрес источника, например, для списка разрешенных адресов, используйте [NAT-инстанс](../tutorials/nat-instance/index.md) со статическим публичным IP-адресом.

## Безопасность {#security}

#### Как заблокировать доступ с определенного IP-адреса? {#block-ip-address}

В [группах безопасности](../concepts/security-groups.md#security-groups-structure) действуют разрешающие правила: весь трафик, который не разрешен явно, блокируется. Отдельного запрещающего правила для одного IP-адреса нет. Можно разрешить доступ только с доверенных адресов или подсетей.

Для блокировки отдельных адресов на ВМ можно использовать межсетевой экран, например UFW или iptables.

Для HTTP-запросов к веб-приложению также подойдет Yandex Smart Web Security: [базовое правило](../../smartwebsecurity/concepts/rules.md#base-rules) может блокировать запросы по [условию на IP-адрес](../../smartwebsecurity/concepts/conditions.md).

#### Как отключить защиту от DDoS-атак на публичном IP-адресе? {#disable-ddos-protection-on-external-ip}

Адреса с [защитой от DDoS-атак](../ddos-protection/index.md) выдаются из отдельного пула. Включить или отключить защиту у уже назначенного публичного IP-адреса не получится.

Чтобы использовать ВМ без защиты от DDoS-атак:

1. [Отвяжите текущий публичный IP-адрес](../../compute/operations/vm-control/vm-detach-public-ip.md).
1. [Назначьте новый публичный IP-адрес](../../compute/operations/vm-control/vm-attach-public-ip.md), не включая опцию **Защита от DDoS-атак**.

{% note alert %}

Публичный IP-адрес ВМ изменится. Подключаться к ВМ по прежнему адресу будет невозможно.

{% endnote %}

## Диагностика и решение проблем {#troubleshooting}

#### Почему у меня медленная скорость соединения в сервисах Yandex Cloud? {#low-connection}

Скорость зависит от сетевой нагрузки, ресурсов источника и получателя, маршрута и промежуточных узлов. При высокой сетевой нагрузке рассмотрите [программно ускоренную сеть](../concepts/software-accelerated-network.md). Для выделенного канала с гарантированной полосой используйте [Cloud Interconnect](../../interconnect/index.md).

Если скорость ниже ожидаемой, создайте запрос в [техническую поддержку](https://center.yandex.cloud/support). Для диагностики приложите данные:

* Направление соединения, в котором наблюдаются проблемы: внутри облачной сети, из облачной сети в интернет, из интернета в облачную сеть.
* Тип трафика, для которого наблюдаются проблемы: входящий, исходящий.
* Параметры цели и источника: идентификаторы виртуальных машин, IP-адреса, [FQDN](../../glossary/fqdn.md).
* Результаты выполнения команды `mtr <IP-адрес_или_домен_цели>`.

#### Что делать, если блокируется почтовый трафик? {#if-traffic-blocked}

Yandex Cloud [блокирует](../concepts/limits.md#vpc-egress-traffic-filter) только трафик, который отправляется с публичных IP-адресов на порт 25. Исключение — трафик, отправляемый на почтовые серверы Яндекса.

Чтобы почтовый трафик не блокировался, перенастройте ваш почтовый сервер на использование портов 465 и 587. Для этого воспользуйтесь этими портами в качестве почтового шлюза и [делегируйте ваш домен](https://yandex.ru/support/yandex-360/business/admin/ru/domains/register/delegate) на серверы Яндекса с помощью [Почты для домена](https://habr.com/company/plesk/blog/304204/).

Если вам нужен 25 порт, присвойте виртуальной машине новый IP-адрес:

1. [Запросите](https://center.yandex.cloud/support) новый IP-адрес с открытым портом 25. При запросе сообщите поддержке:
   * идентификатор каталога, в котором нужен IP-адрес;
   * зону доступности;
   * домен для PTR-записи, если требуется.

1. Открепите от виртуальной машины текущий IP-адрес. Для этого в [CLI](../../cli/index.md) выполните команду:

   ```bash
   yc compute instance remove-one-to-one-nat \
     --id=<идентификатор_виртуальной_машины> \
     --network-interface-index=0
   ```

1. [Прикрепите](../../compute/operations/vm-control/vm-attach-public-ip.md) новый IP-адрес, полученный от поддержки.

Мы оставляем за собой право заблокировать IP-адрес и/или приостановить действие ВМ, если получим жалобы на спам с этого адреса.

Если письма не доходят до получателей, проверьте публичный IP-адрес почтовой ВМ или NAT-инстанса в списках блокировок RBL/DNSBL, например с помощью [MXToolbox](https://mxtoolbox.com/blacklists.aspx).

При наличии адреса в списке проверьте почтовый сервер: причиной могут быть жалобы на спам, некорректные PTR-записи для IP-адреса и DMARC-записи домена или компрометация сервера. После устранения причины обратитесь к оператору списка блокировок для исключения адреса.

Если адрес отсутствует в списках или проблема сохраняется, [обратитесь в техническую поддержку](https://center.yandex.cloud/support). Укажите публичный IP-адрес или его идентификатор и приложите результаты проверки в RBL/DNSBL.

#### Как читать график `Connections quota utilization`? {#connections-quota-utilization}

[График Connections quota utilization](../operations/connections-view.md) показывает использование ограничений на количество сетевых соединений в процентах.

В [метриках Compute Cloud](../../compute/metrics.md) используются два показателя:

* `network_connections.quota_utilization` — для виртуальной машины.
* `network_connections.interface_quota_utilization` — для отдельного сетевого интерфейса ВМ.

Это разные ограничения, поэтому значения метрик могут отличаться даже у ВМ с одним интерфейсом. При оценке загрузки ориентируйтесь на максимальное значение на графике.

При использовании пользовательской группы безопасности [лимит составляет 350 000 соединений на сетевой интерфейс](../concepts/monitoring-connections.md). При достижении лимита новые соединения отбрасываются.

Число соединений в мониторинге может превышать число соединений внутри ОС: записи удаляются с задержкой. Подробнее о жизненном цикле соединения и настройке `keepalive` в разделе [Мониторинг сетевых соединений](../concepts/monitoring-connections.md).

График показывает использование лимита соединений, а загрузку vCPU нужно оценивать отдельно. В обычной сети ВМ процессы обработки сетевого трафика и пользовательские процессы используют одни и те же вычислительные ядра, выделенные ВМ. Гипервизор распределяет нагрузку между этими ядрами. Подробнее в разделе [Обычная сеть ВМ](../../compute/concepts/software-accelerated-network.md#reg-vm).

#### Как получить логи входящего и исходящего трафика? {#incoming-and-outcoming-traffic-logs}

Для записи потоков трафика во внешние по отношению к Virtual Private Cloud сети используйте [Yandex Audit Trails](https://yandex.cloud/ru/services/audit-trails). Событие [ExternalFlow](../at-ref.md#data-plane-events) относится к событиям уровня сервисов (Data Plane).

[Создайте трейл](../../audit-trails/operations/create-trail.md), настройте сбор событий уровня сервисов для Virtual Private Cloud и выберите место хранения логов. Логи помогут анализировать сетевые соединения после включения сбора.

Если нужен дополнительный анализ трафика на ВМ, можно настроить IDS/IPS, например [Suricata](https://suricata.io/) или [Snort](https://snort.org/). Информация о расходах на трафик доступна в [детализации потребления](../../billing/operations/check-charges.md).

#### Что делать при ошибках TLS-соединений на ВМ с защитой от DDoS-атак? {#resolving-tls-traffic-issues}

Если на ВМ с защищенным публичным IP-адресом долго устанавливаются TLS-соединения, возникают ошибки загрузки пакетов или запросы `curl` зависают, проверьте настройки MTU и MSS.

Для адресов с защитой от DDoS-атак рекомендуется MTU `1450` байт. Порядок настройки для Linux, Windows и узлов Managed Service for Kubernetes приведен в инструкции [Настроить MTU при включении защиты от DDoS-атак](../operations/adjust-mtu-ddos-protection.md). Подробнее о параметрах в разделе [MTU и MSS](../concepts/mtu-mss.md).

Если на ВМ используются Docker-контейнеры, MTU нужно настроить также для их сетевых интерфейсов. Для стандартного сетевого моста Docker добавьте параметр `"mtu": 1450` в `/etc/docker/daemon.json`, сохранив остальные параметры, и перезапустите Docker:

```bash
sudo systemctl restart docker
```

Перезапуск может повлиять на работающие контейнеры. Для других сетей Docker проверьте MTU в их настройках.

Если проблема сохраняется, [обратитесь в техническую поддержку](https://center.yandex.cloud/support). Укажите идентификатор ВМ, защищенный публичный IP-адрес, описание ошибки и вывод менеджера пакетов или команды `curl -vI https://<домен>`.

#### Почему не удаляется облачная сеть и возникает ошибка `Network is not empty`? {#unable-to-delete-cloud-network}

Ошибка `Network is not empty` означает, что в сети остались дочерние ресурсы. Перед [удалением сети](../operations/network-delete.md) удалите ее ресурсы:

* [Подсети](../operations/subnet-delete.md).
* [Группы безопасности](../operations/security-group-delete.md), созданные пользователем.
* [Таблицы маршрутизации](../operations/delete-route-table.md).

Если удалить сеть не удается, создайте запрос в [техническую поддержку](https://center.yandex.cloud/support). В нем укажите идентификатор сети и текст ошибки.

#### Почему не удаляется группа безопасности? {#security-group-cannot-be-deleted}

Если группа безопасности назначена сетевому интерфейсу ресурса, при удалении возникает ошибка:

```text
Security group enpxxxxxxxxxxxxxxxxx has reference to VM network interface
```

Отвяжите группу безопасности от всех ресурсов, сетевым интерфейсам которых она назначена, затем [удалите группу](../operations/security-group-delete.md). Группа может использоваться не только ВМ — полный список ресурсов приведен в разделе [Применение групп безопасности](../concepts/security-groups.md#security-groups-apply).

Если не удается определить, какие ресурсы используют группу, [обратитесь в техническую поддержку](https://center.yandex.cloud/support) и укажите идентификатор группы безопасности.

Группу безопасности, созданную в сети по умолчанию, удалить нельзя.

#### Почему мне не удается настроить доступ к внешней базе данных из Virtual Private Cloud через NAT-шлюз? {#access-to-external-database}

Если в настройках внешней базы данных или файрвола разрешены подключения только с текущего IP-адреса NAT-шлюза, доступ может прерваться после изменения этого адреса.

{% note info %}

Если внешний ресурс ограничивает доступ по IP-адресам, учитывайте, что публичные IP-адреса [NAT-шлюза](../concepts/gateways.md#nat-gateway) могут меняться и их нельзя зарезервировать. Для доступа с фиксированного IP-адреса используйте [NAT-инстанс](../tutorials/nat-instance/index.md) со [статическим публичным IP-адресом](../operations/set-static-ip.md). Добавьте этот адрес в список разрешенных на внешнем ресурсе.

[Диапазоны публичных IPv4-адресов ресурсов Yandex Cloud](../concepts/ips.md) используются разными клиентами облака. Добавление всех этих диапазонов в список разрешенных откроет сетевой доступ также с IP-адресов других клиентов.

{% endnote %}
